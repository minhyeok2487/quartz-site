# 1. 스위치, 네트워크의 교통 정리원

회사 사무실을 떠올려 봅시다. 사무실에는 수십 대의 컴퓨터, 프린터, IP 전화기들이 있습니다. 이 모든 장비들은 어떻게 서로 연결되어 있을까요?

각 장비에서 나온 케이블이 모두 벽면이나 바닥 아래를 통해 한 곳으로 모입니다. 그곳에는 보통 서버실이나 통신실이 있고, 그 안에 녹색 LED가 깜빡이는 납작한 장비들이 랙에 줄지어 꽂혀 있습니다. 이것이 바로 **스위치(Switch)** 입니다.

스위치는 현대 네트워크의 핵심 장비입니다. 여러분이 지금 이 글을 읽고 있다면, 그 데이터는 최소한 하나 이상의 스위치를 거쳐서 왔을 것입니다. 회사 네트워크든, 카페 와이파이든, 집의 인터넷이든 말이죠.

## 스위치가 없던 시절 - 허브의 한계

스위치를 이해하려면 먼저 그 전신인 허브(Hub)를 알아야 합니다.

1990년대 후반, 중소기업 전산실의 흔한 풍경이었습니다. 10대의 컴퓨터가 허브에 연결되어 있습니다. 김 대리가 파일 서버에서 100MB짜리 파일을 다운로드하기 시작합니다. 그 순간, 사무실 전체의 네트워크가 느려집니다.

"야, 누가 뭐 다운받는 거야? 인터넷이 안 되잖아!"

이런 아우성이 터져나옵니다. 왜 그랬을까요?

**허브는 받은 신호를 모든 포트로 뿌립니다.** 김 대리가 서버에서 파일을 받으면, 그 데이터는 김 대리의 컴퓨터뿐만 아니라 나머지 9대의 컴퓨터에도 전송됩니다. 물론 다른 컴퓨터들은 "내 거 아니네" 하고 버리지만, 그 동안 다른 통신을 할 수 없습니다. 10대의 컴퓨터가 10Mbps 대역폭을 나눠 써야 했습니다.

더 심각한 문제도 있었습니다. 두 대의 컴퓨터가 동시에 데이터를 보내면 **충돌(Collision)** 이 발생합니다. 신호가 뒤섞여서 알아볼 수 없게 되는 거죠. 충돌이 발생하면 모든 컴퓨터가 통신을 멈추고 랜덤한 시간을 기다렸다가 다시 시도해야 했습니다.

컴퓨터가 5대일 때는 그럭저럭 괜찮았습니다. 10대가 되면 좀 느려집니다. 20대, 30대가 되면? 네트워크가 거의 마비됩니다. 충돌이 너무 자주 발생해서 아무도 제대로 통신할 수가 없었습니다.

## 스위치의 등장 - 혁명적인 변화

그리고 스위치가 등장했습니다.

스위치는 허브와 달리 **MAC 주소**를 이해합니다. 스위치는 "이 데이터가 누구한테 가야 하는지"를 알고 있습니다. 김 대리가 파일을 받을 때, 스위치는 그 데이터를 **김 대리의 컴퓨터가 연결된 포트로만** 전송합니다. 다른 9대의 컴퓨터는 아무것도 모릅니다.

마치 허브가 확성기로 모든 사람에게 외치는 것이라면, 스위치는 귓속말로 해당 사람에게만 전달하는 것입니다.

결과는 놀라웠습니다. 김 대리가 파일을 받는 동안에도 다른 직원들은 정상적으로 인터넷을 사용할 수 있게 되었습니다. 각 포트가 독립적으로 동작하니 충돌도 사실상 사라졌습니다. 10대가 연결되어도, 100대가 연결되어도 성능이 유지됩니다. 스위치 하나로 네트워크 세상이 바뀐 겁니다.

# 2. 스위치의 정체 - L2 장비

스위치는 OSI 7계층 모델에서 **Layer 2(데이터 링크 계층)** 에서 동작하는 장비입니다. 그래서 **L2 스위치**라고도 부릅니다.

## Layer 2에서 동작한다는 것의 의미

L2에서 동작한다는 것은 스위치가 **프레임(Frame)** 을 처리한다는 의미입니다.

OSI 모델에서 각 계층의 데이터 단위를 기억하시나요? L4는 세그먼트(Segment), L3는 패킷(Packet), L2는 **프레임(Frame)**, L1은 비트(Bit)입니다.

스위치는 케이블을 통해 전기 신호(비트)가 들어오면 이것을 프레임으로 해석합니다. 프레임의 헤더에는 **출발지 MAC 주소**와 **목적지 MAC 주소**가 있습니다. 스위치는 이 MAC 주소를 보고 어디로 보낼지 결정합니다.

```
프레임 구조:
┌─────────────┬─────────────┬─────────┬──────────┬─────┐
│ 목적지 MAC  │ 출발지 MAC  │  Type   │   Data   │ FCS │
│  (6 bytes)  │  (6 bytes)  │(2 bytes)│ (가변)   │     │
└─────────────┴─────────────┴─────────┴──────────┴─────┘
```

스위치가 하는 일을 한마디로 정리하면:

**"프레임의 목적지 MAC 주소를 보고, 그 MAC 주소가 연결된 포트로만 프레임을 전달한다"**

이것이 스위치의 핵심 기능입니다.

## IP 주소는 모른다?

여기서 중요한 포인트가 있습니다. **일반적인 L2 스위치는 IP 주소를 이해하지 못합니다.**

스위치에 192.168.1.100으로 데이터를 보내달라고 해도 스위치는 "192.168.1.100이 뭔데요?"라고 답할 겁니다. 스위치가 아는 건 MAC 주소뿐입니다. "AA:BB:CC:DD:EE:FF로 보내주세요"라고 하면 스위치는 "네, 그 MAC 주소는 3번 포트에 있네요. 3번으로 보낼게요"라고 합니다.

IP 주소는 L3 장비인 라우터가 처리합니다. 스위치는 프레임 안에 있는 MAC 주소만 보고 전달할 뿐, 그 안에 어떤 IP 주소가 담겨 있는지는 관심이 없습니다. 각 계층이 자기 역할만 하는 거죠.

# 3. 스위치의 핵심 기능 3가지

스위치가 하는 일을 정확히 이해하려면 세 가지 핵심 기능을 알아야 합니다.

## 기능 1: Learning (학습)

스위치는 처음 켜지면 아무것도 모릅니다. 빈 테이블만 가지고 있죠. 이 테이블을 **MAC Address Table** (또는 CAM Table)이라고 합니다.

스위치는 포트로 들어오는 프레임의 **출발지 MAC 주소**를 학습합니다.

예를 들어볼까요:

```
포트 1에 PC-A (MAC: AA:AA:AA:AA:AA:AA) 연결
포트 2에 PC-B (MAC: BB:BB:BB:BB:BB:BB) 연결
```

1. PC-A가 프레임을 보냅니다 (출발지: AA:AA:AA:AA:AA:AA)
2. 스위치는 "포트 1에서 AA:AA:AA:AA:AA:AA가 왔네? 기록해둬야지"
3. MAC Address Table에 저장: `AA:AA:AA:AA:AA:AA → Port 1`

4. PC-B가 프레임을 보냅니다 (출발지: BB:BB:BB:BB:BB:BB)
5. 스위치는 "포트 2에서 BB:BB:BB:BB:BB:BB가 왔네? 기록!"
6. MAC Address Table에 저장: `BB:BB:BB:BB:BB:BB → Port 2`

```
MAC Address Table:
┌───────────────────────┬──────────┐
│      MAC Address      │   Port   │
├───────────────────────┼──────────┤
│ AA:AA:AA:AA:AA:AA     │    1     │
│ BB:BB:BB:BB:BB:BB     │    2     │
└───────────────────────┴──────────┘
```

이렇게 스위치는 네트워크의 지도를 스스로 만들어 갑니다. 누가 어디에 있는지를 학습하는 거죠.

### MAC Address Table의 Aging

MAC Address Table의 항목에는 유효 기간이 있습니다. 보통 **300초(5분)** 입니다. 5분 동안 해당 MAC 주소로부터 프레임이 오지 않으면 테이블에서 삭제됩니다.

왜 그럴까요? 노트북을 다른 포트로 옮기거나, 장비가 교체될 수 있으니까요. 항상 최신 정보를 유지해야 합니다.

```
MAC Address Table:
┌───────────────────────┬──────────┬─────────────┐
│      MAC Address      │   Port   │  Age(sec)   │
├───────────────────────┼──────────┼─────────────┤
│ AA:AA:AA:AA:AA:AA     │    1     │    120      │
│ BB:BB:BB:BB:BB:BB     │    2     │     45      │
└───────────────────────┴──────────┴─────────────┘
```

## 기능 2: Forwarding (전달)

학습이 끝나면, 스위치는 똑똑하게 데이터를 전달할 수 있습니다.

PC-A(AA:AA...)가 PC-B(BB:BB...)에게 프레임을 보낸다고 가정해봅시다.

프레임이 포트 1로 들어옵니다. 이 프레임의 출발지 MAC은 AA:AA:AA:AA:AA:AA이고, 목적지 MAC은 BB:BB:BB:BB:BB:BB입니다. 스위치는 MAC Address Table을 확인합니다. "BB:BB:BB:BB:BB:BB는... 포트 2에 있네!" 그래서 **포트 2로만 프레임을 전송합니다.**

```
[PC-A] ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━ [PC-C]
Port 1  ┐                                       ┌  Port 3
        │  프레임  ┌──────────┐                 │
        └─────────→│  Switch  │──────X (전송 안 됨)
                   └──────────┘
        ┌─────────────────────────────────────→ Port 2
        │
       [PC-B] ← 여기로만 전달!
```

PC-C는 이 통신이 일어나고 있는지조차 모릅니다. 허브였다면 PC-C에도 데이터가 갔겠지만, 스위치는 필요한 곳에만 전달합니다.

## 기능 3: Filtering (필터링)

Filtering은 Forwarding과 반대 개념입니다. **필요 없는 곳에는 보내지 않는 것**이죠.

위의 예에서 스위치가 포트 3(PC-C)으로 프레임을 보내지 않은 것이 바로 Filtering입니다.

또 다른 중요한 Filtering 상황이 있습니다. **같은 포트에 있는 장비 간의 통신**입니다.

포트 1에 허브가 연결되어 있고, 그 허브에 PC-A와 PC-D가 연결되어 있다고 해봅시다.

```
[PC-A] ─┬─ [Hub] ─── Port 1 ─── [Switch] ─── Port 2 ─── [PC-B]
[PC-D] ─┘
```

PC-A가 PC-D에게 프레임을 보내면:
1. 프레임이 허브를 통해 스위치의 포트 1로 들어옵니다
2. 스위치가 MAC Table을 확인합니다: "PC-D도 포트 1이네?"
3. **같은 포트로는 보내지 않습니다** (Filtering)

왜냐하면 이미 허브를 통해 PC-D에 전달되었을 테니까요. 스위치가 다시 보내면 중복이 됩니다.

## 세 가지 기능 정리

| 기능 | 설명 | 언제 발생? |
|------|------|-----------|
| **Learning** | 출발지 MAC 주소를 테이블에 저장 | 프레임이 들어올 때마다 |
| **Forwarding** | 목적지 MAC 포트로만 전달 | 목적지 MAC이 테이블에 있을 때 |
| **Filtering** | 불필요한 포트로 전달 차단 | 같은 포트이거나 목적지가 아닌 포트 |

# 4. Flooding - 모르면 모두에게 물어본다

앞서 배운 Learning, Forwarding, Filtering은 스위치의 기본 동작 원리입니다. 그런데 한 가지 상황이 남았습니다. 목적지 MAC 주소가 테이블에 없으면 어떻게 될까요? 처음 켜진 스위치나, 처음 보는 MAC 주소가 목적지인 경우가 그렇습니다.

이때 스위치는 **Flooding**을 합니다. Flooding은 별개의 4번째 기능이 아니라, **목적지를 모를 때의 Forwarding 방식**입니다.

## Unknown Unicast Flooding

PC-A가 PC-B에게 처음으로 프레임을 보내는 상황입니다. 스위치의 MAC Table에는 아직 PC-B의 정보가 없습니다.

프레임이 포트 1로 들어옵니다. 출발지는 AA:AA:AA:AA:AA:AA이고, 목적지는 BB:BB:BB:BB:BB:BB입니다. 스위치는 먼저 "AA:AA는 포트 1이군. 기록!"하고 Learning을 수행합니다. 그 다음 "BB:BB를 어디로 보내지? 테이블에 없네..."라고 판단하고, **수신 포트(포트 1)를 제외한 모든 포트로 전송합니다.** 이것이 Flooding입니다.

```
[PC-A] ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━ [PC-C]
Port 1  ┐                                       ┌  Port 3
        │  프레임  ┌──────────┐     프레임 전송 ──→
        └─────────→│  Switch  │
                   └──────────┘     프레임 전송 ──→
                            └───────────────────→ Port 2
                                                   [PC-B]
```

PC-B와 PC-C 모두 프레임을 받습니다. PC-C는 "내 거 아니네" 하고 버리고, PC-B는 "내 거다!" 하고 받아들입니다.

그리고 PC-B가 응답을 보내면 스위치는 PC-B의 MAC 주소가 포트 2에 있다는 것을 학습합니다. 다음부터는 Flooding 없이 바로 포트 2로 전달할 수 있게 됩니다.

## Broadcast Flooding

브로드캐스트(목적지 MAC: **FF:FF:FF:FF:FF:FF**)는 "모든 장비에게"라는 의미입니다. 스위치는 이것을 받으면 무조건 모든 포트로 Flooding합니다.

언제 브로드캐스트가 사용될까요? 대표적으로 ARP 요청("192.168.1.100의 MAC 주소가 뭐야?"), DHCP 요청("IP 주소 좀 주세요!"), Windows 네트워크 검색을 위한 NetBIOS 브라우징 등이 있습니다.

브로드캐스트는 네트워크의 모든 장비가 처리해야 하므로, 너무 많아지면 성능 저하가 발생합니다. 이것을 **Broadcast Storm**이라고 합니다. 이 문제를 해결하기 위해 라우터나 L3 스위치로 네트워크를 분리합니다.

## Multicast Flooding

멀티캐스트(목적지 MAC: 01:00:5E:XX:XX:XX)는 "특정 그룹의 장비들에게"라는 의미입니다. 기본적으로 스위치는 멀티캐스트도 모든 포트로 Flooding합니다.

하지만 **IGMP Snooping**이라는 기능을 사용하면 멀티캐스트를 받고 싶어하는 포트로만 전달할 수 있습니다. 이것은 나중에 다루겠습니다.

## Flooding 정리

| 상황 | 동작 | 이유 |
|------|------|------|
| 목적지 MAC이 테이블에 없음 | Flooding | 어디로 보낼지 모르니까 |
| 브로드캐스트 (FF:FF:FF:FF:FF:FF) | Flooding | 원래 모두에게 보내는 것이니까 |
| 멀티캐스트 | Flooding (기본) | 누가 받을지 모르니까 |
| 목적지 MAC이 테이블에 있음 | Forwarding | 어디로 보낼지 아니까 |

# 5. 스위치 vs 허브 - 결정적 차이

스위치와 허브의 차이를 명확하게 정리해봅시다.

## 핵심 비교표

| 특성 | 허브 (Hub) | 스위치 (Switch) |
|------|-----------|----------------|
| **OSI 계층** | Layer 1 | Layer 2 |
| **MAC 주소 인식** | X | O |
| **전송 방식** | 모든 포트로 전송 | 목적지 포트로만 전송 |
| **Collision Domain** | 전체가 하나 | 포트당 하나 |
| **대역폭** | 모든 장비가 공유 | 포트별 독립 |
| **보안** | 취약 (감청 쉬움) | 상대적으로 안전 |
| **현재 사용** | 거의 사용 안 함 | 표준 장비 |

## Collision Domain의 차이

이것이 가장 중요한 차이입니다.

**허브**: 연결된 모든 장비가 하나의 Collision Domain
```
[PC-A]─┐
       │
[PC-B]─┼─[HUB]  ← 하나의 Collision Domain
       │         동시 전송 시 충돌!
[PC-C]─┘
```

**스위치**: 각 포트가 독립적인 Collision Domain
```
[PC-A]─────[Switch]─────[PC-C]
             │
           [PC-B]

← 각각 독립적인 Collision Domain
← 동시 전송 가능!
```

> 문제 | 48포트 스위치에 48대의 PC가 연결되어 있습니다. Collision Domain은 몇 개일까요?

정답: **48개**입니다. 스위치의 각 포트는 독립적인 Collision Domain을 형성합니다.

## 대역폭의 차이

100Mbps 네트워크에서 10대의 컴퓨터가 연결되어 있다고 가정합시다.

**허브**: 10대가 100Mbps를 나눠 씀 → 평균 10Mbps/대
**스위치**: 각 연결이 100Mbps 독립 → 100Mbps/대

스위치는 **전이중(Full-Duplex)** 통신도 지원합니다. 동시에 보내고 받을 수 있다는 뜻이죠. 100Mbps 포트라면 송신 100Mbps + 수신 100Mbps = 총 200Mbps의 처리량을 가집니다.

# 6. 스위치의 종류

스위치도 여러 종류가 있습니다.

## Unmanaged Switch (비관리형 스위치)

가장 단순한 스위치입니다. 전원만 꽂으면 바로 동작하고 별도 설정이 필요 없습니다. 가정이나 소규모 사무실에서 주로 사용하며, 가격도 몇 만원 수준으로 저렴합니다. 가정에서 흔히 쓰는 8포트 스위치가 대표적인 예입니다. 그냥 케이블 꽂으면 됩니다. 편하지만 세밀한 제어는 불가능합니다.

## Managed Switch (관리형 스위치)

네트워크 관리자가 설정하고 관리할 수 있는 스위치입니다. CLI 또는 웹 인터페이스를 통해 설정할 수 있으며, VLAN, Port Security, QoS, Spanning Tree 등 다양한 기능을 제공합니다. 기업 네트워크나 데이터센터에서 사용하며, 가격은 수십만원에서 수천만원까지 다양합니다. Cisco Catalyst, HP ProCurve, Juniper EX 등이 대표적인 제품입니다. CCNA에서 배우는 대부분의 내용은 이 Managed Switch를 다룹니다.

## L3 Switch (Layer 3 스위치)

스위칭과 라우팅을 모두 할 수 있는 스위치입니다. L2 스위칭 기능에 L3 라우팅 기능이 추가된 형태로, VLAN 간 라우팅이나 제한적인 라우팅 프로토콜을 지원합니다. 주로 코어나 디스트리뷰션 계층에서 사용하며, 하드웨어 기반 라우팅을 수행하기 때문에 일반 라우터보다 빠릅니다.

## PoE Switch (Power over Ethernet)

네트워크 케이블로 전력까지 공급하는 스위치입니다. 이더넷 케이블 하나로 데이터와 전원을 동시에 전송할 수 있어서 별도 전원선이 필요 없습니다. IP 전화기, 무선 AP, IP 카메라 등에 주로 사용됩니다. 천장에 설치된 무선 AP에 전원 콘센트가 없어도 됩니다. 스위치에서 네트워크 케이블로 전원을 보내니까요.

# 7. 스위치의 위치 - 네트워크 구조에서의 역할

실제 기업 네트워크에서 스위치는 어디에 위치할까요?

## 3계층 네트워크 모델

```
                    [인터넷]
                       │
                  [방화벽/라우터]
                       │
           ┌───────────┴───────────┐
           │      Core Layer       │
           │    (L3 Switch/Router) │  ← 고속 백본
           └───────────┬───────────┘
                       │
     ┌─────────────────┼─────────────────┐
     │                 │                 │
┌────┴────┐      ┌────┴────┐      ┌────┴────┐
│Distribution│    │Distribution│    │Distribution│  ← VLAN 간 라우팅
│ (L3 Switch)│    │ (L3 Switch)│    │ (L3 Switch)│
└────┬────┘      └────┬────┘      └────┬────┘
     │                 │                 │
┌────┴────┐      ┌────┴────┐      ┌────┴────┐
│ Access  │      │ Access  │      │ Access  │  ← 최종 사용자 연결
│(L2 Switch)│    │(L2 Switch)│    │(L2 Switch)│
└────┬────┘      └────┬────┘      └────┬────┘
     │                 │                 │
  [PC들]            [PC들]            [PC들]
```

## 각 계층의 스위치 역할

**Access Layer (액세스 계층)** 는 L2 스위치를 사용하여 최종 사용자의 PC, 프린터, IP 전화기 등을 네트워크에 연결합니다. 포트 보안이나 VLAN 할당을 담당하며, 가장 많은 스위치가 필요한 계층입니다.

**Distribution Layer (분배 계층)** 는 L3 스위치를 사용합니다. VLAN 간 라우팅을 수행하고, ACL이나 QoS 같은 정책을 적용합니다. Access 스위치들을 상위로 통합하는 역할을 합니다.

**Core Layer (코어 계층)** 는 고속 L3 스위치 또는 라우터를 사용합니다. 빠른 전송과 최소 지연이 목표이며, 복잡한 정책 없이 단순함을 유지하는 것이 핵심입니다.

# 8. 스위치 구매 시 고려사항

실무에서 스위치를 선택할 때 고려해야 할 사항들입니다.

## 주요 스펙

| 항목 | 설명 | 예시 |
|------|------|------|
| **포트 수** | 연결 가능한 장비 수 | 24포트, 48포트 |
| **포트 속도** | 각 포트의 전송 속도 | 1Gbps, 10Gbps |
| **업링크 포트** | 상위 스위치 연결용 고속 포트 | 10G SFP+ 4포트 |
| **스위칭 용량** | 동시 처리 가능한 총 대역폭 | 176Gbps |
| **MAC 테이블 크기** | 저장 가능한 MAC 주소 수 | 16,000개 |
| **PoE 지원** | 전원 공급 기능 | PoE+, 740W |
| **관리 기능** | CLI, Web, SNMP 등 | Managed/Unmanaged |

## 실제 선택 예시

**소규모 사무실 (20명)** 의 경우 24포트 L2 Managed Switch 한 대면 충분합니다. 1Gbps 포트에 PoE를 지원하면 IP 전화기나 무선 AP도 함께 연결할 수 있습니다.

**중견기업 (200명)** 규모라면 Access 계층에 48포트 L2 PoE Switch를 4대 정도 배치하고, Distribution 계층에 24포트 L3 Switch 2대를 두는 구성이 일반적입니다. 상위 연결은 10G 업링크를 사용합니다.

**데이터센터** 에서는 고밀도 10G/25G/100G 스위치가 필요합니다. 저지연과 고성능이 필수이며, 장애에 대비한 이중화 구성도 갖춰야 합니다.

# 9. 정리하며

스위치는 현대 네트워크의 근간입니다. 허브의 한계를 극복하고 효율적인 네트워크를 가능하게 만든 혁신적인 장비죠.

**핵심 포인트:**

**스위치는 L2 장비**입니다. MAC 주소를 이해하고 처리하며, 프레임 단위로 동작합니다.

**세 가지 핵심 기능**이 있습니다. Learning은 출발지 MAC 주소를 학습하고, Forwarding은 목적지 포트로만 전달하며, Filtering은 불필요한 포트로의 전달을 차단합니다.

**Flooding**은 Forwarding의 특수한 경우입니다. 목적지를 모르면 모든 포트로 전송하며, 브로드캐스트나 멀티캐스트도 Flooding됩니다.

**허브와의 결정적 차이**는 Collision Domain을 분리한다는 점입니다. 포트별로 독립된 대역폭을 가지며, 보안도 향상됩니다.

**스위치의 종류**로는 설정이 필요 없는 Unmanaged, 고급 기능과 관리가 가능한 Managed, 라우팅 기능이 포함된 L3 Switch, 전원 공급 기능을 가진 PoE Switch가 있습니다.

이제 스위치가 무엇이고 어떤 역할을 하는지 이해했습니다. 다음 장에서는 스위치가 실제로 데이터를 어떻게 처리하는지, 즉 **스위칭 방식**에 대해 알아보겠습니다.
