# 1. 게스트 네트워크의 필요성

회사에 방문객이 왔습니다. "Wi-Fi 좀 쓸 수 있을까요?"

이런 요청, 한 번쯤 받아보셨죠? 예전에는 "게스트용 비밀번호는 guest123입니다"라고 알려주면 끝이었습니다. 하지만 이 방식에는 문제가 많습니다.

```
┌─────────────────────────────────────────────────────────┐
│              기존 방식의 문제점                           │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  1. 누가 접속했는지 알 수 없음                           │
│     → "저번 주에 접속한 사람이 누구죠?" 답 못함          │
│                                                         │
│  2. 비밀번호가 유출되면 누구나 접속                       │
│     → 퇴사자, 방문 끝난 사람도 계속 사용                 │
│                                                         │
│  3. 접근 제어 불가                                       │
│     → 내부 서버까지 접근 가능                            │
│                                                         │
│  4. 감사/컴플라이언스 대응 불가                          │
│     → "방문객 접속 기록 보여주세요" 불가능               │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

[[01_Cisco ISE 개요와 아키텍처|ISE]]의 게스트 기능을 사용하면 이런 문제들을 모두 해결할 수 있습니다.

# 2. ISE 게스트 서비스 개요

## 게스트 서비스의 핵심 기능

ISE 게스트 서비스는 다음을 제공합니다:

1. **게스트 계정 생성/관리**
   - 임시 계정 발급
   - 유효 기간 설정
   - 자동 만료

2. **게스트 포털**
   - 셀프 등록 또는 스폰서 승인
   - AUP(이용약관) 동의
   - 사용자 정의 가능한 UI

3. **접근 제어**
   - 게스트 전용 VLAN
   - 인터넷만 접근 가능
   - 내부 리소스 차단

4. **추적 및 감사**
   - 누가 언제 접속했는지 기록
   - 스폰서 정보 기록

## 게스트 포털 유형

ISE에서 제공하는 게스트 포털 유형:

| 포털 유형 | 설명 | 사용 사례 |
|----------|------|----------|
| **Hotspot** | 약관 동의만으로 접속 | 카페, 공공장소 |
| **Self-Registered** | 게스트가 직접 등록 | 일반 방문객 |
| **Sponsored** | 스폰서(직원) 승인 필요 | 보안이 중요한 환경 |
| **Sponsored + Self-Registered** | 셀프 등록 후 스폰서 승인 | 중간 수준 보안 |

# 3. 게스트 접근 흐름

## Sponsored Guest 흐름 (스폰서 승인 방식)

가장 안전한 방식입니다. 직원(스폰서)이 게스트 계정을 만들어 줍니다.

```
┌─────────────────────────────────────────────────────────┐
│              Sponsored Guest 흐름                        │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  [사전 준비]                                            │
│  1. 직원(스폰서)이 스폰서 포털에 로그인                  │
│  2. 방문객 정보 입력 (이름, 이메일, 방문 기간)           │
│  3. 게스트 계정 생성                                    │
│  4. 방문객에게 계정 정보 전달 (이메일/SMS/인쇄)          │
│                                                         │
│  [방문객 접속]                                           │
│  5. 방문객이 게스트 Wi-Fi에 연결                        │
│  6. 게스트 포털로 자동 리다이렉트                        │
│  7. 계정 정보 입력                                      │
│  8. AUP(이용약관) 동의                                  │
│  9. 인터넷 접속 가능                                    │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

## Self-Registered Guest 흐름 (셀프 등록 방식)

방문객이 직접 등록하는 방식입니다. 스폰서 승인을 추가로 요구할 수 있습니다.

```
┌─────────────────────────────────────────────────────────┐
│           Self-Registered Guest 흐름                     │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  1. 방문객이 게스트 Wi-Fi에 연결                        │
│  2. 게스트 포털로 자동 리다이렉트                        │
│  3. "신규 등록" 클릭                                    │
│  4. 정보 입력 (이름, 이메일, 회사, 스폰서 선택)          │
│  5. AUP(이용약관) 동의                                  │
│                                                         │
│  [스폰서 승인 필요 시]                                   │
│  6. 스폰서에게 승인 요청 이메일 발송                     │
│  7. 스폰서가 승인                                       │
│  8. 방문객에게 접속 가능 알림                           │
│                                                         │
│  [스폰서 승인 불필요 시]                                 │
│  6. 즉시 인터넷 접속 가능                               │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

## Hotspot 흐름 (약관 동의만)

가장 간단한 방식입니다. 보안은 낮지만 편리합니다.

```
┌─────────────────────────────────────────────────────────┐
│                  Hotspot 흐름                           │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  1. 게스트 Wi-Fi에 연결                                 │
│  2. Hotspot 포털로 리다이렉트                           │
│  3. AUP(이용약관) 동의 버튼 클릭                        │
│  4. 인터넷 접속 가능                                    │
│                                                         │
│  ※ 계정 없이 접속 가능                                  │
│  ※ MAC 주소로만 추적 가능                               │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

> 문제 | 방문객의 신원을 가장 확실하게 파악할 수 있는 게스트 포털 유형은?

정답은 → **Sponsored Guest** 입니다. 직원이 직접 계정을 만들어 주므로 "누가 누구를 위해 계정을 만들었는지" 기록이 남습니다.

# 5. 스폰서 포털

## 스폰서 포털이란?

**스폰서 포털(Sponsor Portal)** 은 직원들이 게스트 계정을 관리하는 웹 페이지입니다.

**메뉴 위치:** Work Centers → Guest Access → Portals & Components → Sponsor Portals

## 스폰서 그룹

누가 게스트 계정을 만들 수 있는지 정의합니다.

**메뉴:** Work Centers → Guest Access → Portals & Components → Sponsor Groups

```
┌─────────────────────────────────────────────────────────┐
│              스폰서 그룹 예시                             │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  Group: ALL_ACCOUNTS                                    │
│  Members: AD:Domain Users                               │
│  권한:                                                  │
│  - 게스트 계정 생성 ☑                                   │
│  - 자신이 만든 계정만 관리 ☑                            │
│  - 다른 사람이 만든 계정 관리 ☐                         │
│  - 계정 일시 중지 ☑                                     │
│  - 계정 삭제 ☐                                          │
│                                                         │
│  ─────────────────────────────────────────────────────  │
│                                                         │
│  Group: FULL_SPONSORS (IT팀 전용)                       │
│  Members: AD:IT_Department                              │
│  권한:                                                  │
│  - 게스트 계정 생성 ☑                                   │
│  - 모든 계정 관리 ☑                                     │
│  - 계정 삭제 ☑                                          │
│  - 계정 비밀번호 재설정 ☑                               │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

## 스폰서가 게스트 계정 만들기

```
1. 스폰서가 스폰서 포털 URL 접속
   예: https://ise.company.com:8443/sponsorportal

2. AD 계정으로 로그인

3. "Create Accounts" → "Known" 선택

4. 게스트 정보 입력
   - First Name: 홍
   - Last Name: 길동
   - Email: guest@visitor.com
   - Guest Type: Daily
   - Duration: 1 day

5. "Create" 클릭

6. 계정 정보 전달 방법 선택
   - 이메일 발송
   - SMS 발송
   - 인쇄
```

# 6. BYOD (Bring Your Own Device)

## BYOD란?

**BYOD(Bring Your Own Device)** 는 직원이 개인 장비를 회사 네트워크에 연결하는 것을 의미합니다.

```
┌─────────────────────────────────────────────────────────┐
│                  BYOD의 도전과제                         │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  "김대리가 개인 노트북으로 회사 Wi-Fi에 접속하고 싶대요" │
│                                                         │
│  고려사항:                                               │
│  - 개인 장비에 회사 데이터가 저장될 수 있음              │
│  - 백신/보안 상태를 알 수 없음                          │
│  - 분실 시 정보 유출 위험                               │
│  - 그렇다고 무조건 막으면 불편...                        │
│                                                         │
│  해결책:                                                │
│  - 제한된 네트워크 접근 허용                            │
│  - 장비 등록 후에만 접근 허용                           │
│  - 회사 장비보다 낮은 권한 부여                         │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

## ISE BYOD 온보딩

ISE는 **BYOD 온보딩(Onboarding)** 기능을 제공합니다. 개인 장비를 안전하게 등록하고 관리할 수 있습니다.

### 온보딩 프로세스

```
┌─────────────────────────────────────────────────────────┐
│              BYOD 온보딩 흐름                            │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  1. 직원이 개인 장비로 회사 Wi-Fi 연결 시도              │
│                                                         │
│  2. ISE가 "등록되지 않은 장비" 감지                      │
│                                                         │
│  3. BYOD 포털로 리다이렉트                              │
│                                                         │
│  4. 직원이 회사 계정으로 로그인                          │
│                                                         │
│  5. 장비 정보 입력 (장비 이름, 설명)                     │
│                                                         │
│  6. 인증서 프로비저닝 (선택)                             │
│     - 프로파일 다운로드 및 설치                          │
│     - 인증서 자동 발급                                   │
│                                                         │
│  7. 장비가 ISE에 등록됨                                  │
│                                                         │
│  8. BYOD 정책에 따라 네트워크 접근 허용                  │
│     (제한된 VLAN, 제한된 ACL)                           │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

### Native Supplicant Provisioning

ISE는 **Native Supplicant Provisioning** 기능으로 클라이언트 설정을 자동화합니다.

**지원 플랫폼:**
- Windows
- macOS
- iOS
- Android

**프로비저닝 내용:**
- Wi-Fi 프로파일 (SSID, 인증 설정)
- 인증서 (EAP-TLS용)
- 802.1X 설정

```
┌─────────────────────────────────────────────────────────┐
│           Supplicant Provisioning 흐름                   │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  [iOS 예시]                                             │
│                                                         │
│  1. BYOD 포털에서 "Continue" 클릭                       │
│                                                         │
│  2. 설정 프로파일 다운로드 안내                          │
│     "설정에서 프로파일을 설치하세요"                     │
│                                                         │
│  3. 설정 앱 → 프로파일 다운로드됨 → 설치                 │
│                                                         │
│  4. 프로파일에 포함된 인증서와 Wi-Fi 설정 적용           │
│                                                         │
│  5. 자동으로 Corporate Wi-Fi에 연결됨                   │
│     (EAP-TLS 인증서 기반)                               │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

# 7. 게스트/BYOD 정책 구성

## 인가 정책 예시

```
┌─────────────────────────────────────────────────────────┐
│          게스트/BYOD 인가 정책 예시                       │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  Rule Name           │ Condition            │ Result    │
│  ────────────────────┼──────────────────────┼──────────│
│  Registered_BYOD     │ Endpoint:            │ BYOD     │
│                      │ BYODRegistered=True  │ _Access   │
│                      │ AND                  │          │
│                      │ IdentityGroup:       │          │
│                      │ Employee             │          │
│  ────────────────────┼──────────────────────┼──────────│
│  BYOD_Onboarding     │ IdentityGroup:       │ BYOD     │
│                      │ Employee             │ _Redirect │
│                      │ AND                  │          │
│                      │ Endpoint:            │          │
│                      │ BYODRegistered=False │          │
│  ────────────────────┼──────────────────────┼──────────│
│  Guest_Access        │ IdentityGroup:       │ Guest    │
│                      │ GuestEndpoints       │ _Access   │
│  ────────────────────┼──────────────────────┼──────────│
│  Guest_Redirect      │ Wireless_MAB         │ Guest    │
│                      │                      │ _Redirect │
│  ────────────────────┼──────────────────────┼──────────│
│  Default             │ (기본)               │ Deny     │
│                      │                      │ Access    │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

## Authorization Profile 예시

### Guest_Redirect (게스트 포털 리다이렉트)

```
Profile: Guest_Redirect

Web Redirection (CWA):
- ACL: ACL_WEBAUTH_REDIRECT
- Redirect URL: https://ise.company.com:8443/portal/gateway?...
- Portal: Guest_Portal

VLAN: (변경 없음 - 리다이렉트 후 CoA로 변경)
```

### Guest_Access (게스트 접근 허용)

```
Profile: Guest_Access

VLAN: 100 (Guest_VLAN)
dACL: PERMIT_INTERNET_ONLY
  - permit udp any any eq 53 (DNS)
  - permit tcp any any eq 80 (HTTP)
  - permit tcp any any eq 443 (HTTPS)
  - deny ip any 10.0.0.0 0.255.255.255 (내부 차단)
  - deny ip any 172.16.0.0 0.15.255.255
  - deny ip any 192.168.0.0 0.0.255.255
  - permit ip any any

Reauthentication: 3600초
```

### BYOD_Redirect (BYOD 온보딩 리다이렉트)

```
Profile: BYOD_Redirect

Web Redirection:
- ACL: ACL_BYOD_REDIRECT
- Portal: BYOD_Portal
```

### BYOD_Access (BYOD 접근 허용)

```
Profile: BYOD_Access

VLAN: 50 (BYOD_VLAN)
dACL: PERMIT_BYOD_LIMITED
  - permit tcp any host 10.1.1.10 eq 443 (특정 서버만)
  - permit tcp any host 10.1.1.20 eq 443
  - permit udp any any eq 53
  - deny ip any 10.1.2.0 0.0.0.255 (민감 서버망 차단)
  - permit ip any any

SGT: BYOD_Devices (30)
Reauthentication: 7200초
```

# 8. Change of Authorization (CoA)

## CoA란?

**CoA(Change of Authorization)** 는 이미 연결된 세션의 권한을 변경하는 기능입니다.

게스트가 포털에서 인증을 완료하면, ISE는 스위치/WLC에 CoA를 보내서 "이 사용자 권한 바꿔!"라고 알려줍니다.

```
┌─────────────────────────────────────────────────────────┐
│                  CoA 동작 흐름                          │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  [초기 상태]                                            │
│  게스트 장비 → Guest_Redirect 프로파일 적용             │
│              → 게스트 포털로 리다이렉트                  │
│                                                         │
│  [포털에서 인증 완료]                                   │
│  게스트가 계정으로 로그인 성공                           │
│                                                         │
│  [CoA 발생]                                             │
│  ISE ─── CoA (Reauthenticate) ───► WLC/Switch          │
│                                                         │
│  [재인증]                                               │
│  WLC/Switch가 장비 재인증                               │
│                                                         │
│  [새 정책 적용]                                         │
│  Guest_Access 프로파일 적용                             │
│  → VLAN 100, 인터넷만 접근 가능                         │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

## CoA 설정

네트워크 장비에서 CoA를 받을 수 있도록 설정해야 합니다.

**스위치 설정:**
```bash
! CoA 활성화
Switch(config)# aaa server radius dynamic-author
Switch(config-locsvr-da-radius)# client 10.1.1.100 server-key MyCoASecret
```

**WLC 설정:**
- Security → AAA → RADIUS → Authentication에서 CoA 지원 활성화

# 9. 게스트/BYOD 베스트 프랙티스

## 1. 게스트 네트워크 분리

게스트 트래픽은 **완전히 분리된 VLAN** 과 **별도 인터넷 회선** 을 사용하는 것이 좋습니다.

```
┌─────────────────────────────────────────────────────────┐
│              네트워크 분리 예시                          │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  [업무 네트워크]                                        │
│  VLAN 10-50 → 방화벽 → 업무용 인터넷 회선              │
│                                                         │
│  [게스트 네트워크]                                      │
│  VLAN 100 → 별도 방화벽/NAT → 게스트용 인터넷 회선     │
│                                                         │
│  ※ 게스트가 내부 네트워크에 접근할 수 없도록 완전 분리  │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

## 2. 게스트 계정 유효 기간 설정

게스트 계정은 **필요한 기간만** 유효하도록 설정하세요.

- 일반 방문객: 1일
- 단기 프로젝트: 1주
- 장기 외주: 최대 90일 (주기적 갱신)

## 3. BYOD는 회사 장비보다 낮은 권한

BYOD 장비는 회사 소유 장비보다 **제한된 접근 권한** 을 가져야 합니다.

```
회사 PC: 모든 내부 서버 접근 가능
BYOD: 이메일, 특정 웹 서비스만 접근 가능
```

## 4. 등록 장비 수 제한

직원당 등록 가능한 BYOD 장비 수를 제한하세요.

- 예: 직원당 최대 3대까지
- My Devices Portal에서 관리

## 5. 정기적인 감사

- 게스트 접속 로그 정기 검토
- 만료된 계정 정리
- 오래된 BYOD 장비 삭제

# 10. 정리하며

이번 장에서 배운 게스트/BYOD의 핵심을 정리합니다.

**게스트 서비스:**
- **Hotspot**: 약관 동의만, 가장 간단
- **Self-Registered**: 게스트가 직접 등록
- **Sponsored**: 직원이 계정 생성, 가장 안전

**BYOD:**
- 개인 장비의 안전한 네트워크 접속
- 온보딩 과정을 통한 장비 등록
- 회사 장비보다 제한된 권한 부여

**주요 기능:**
- 게스트/스폰서/BYOD/My Devices 포털
- Native Supplicant Provisioning
- Change of Authorization (CoA)

> 문제 | 직원의 개인 스마트폰을 회사 네트워크에 안전하게 연결하기 위해 사용하는 ISE 기능은?

정답은 → **BYOD 온보딩** 입니다. 장비를 등록하고, 필요시 인증서를 프로비저닝하여 안전하게 연결합니다.
