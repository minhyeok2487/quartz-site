# 1. 프로파일링이란?

네트워크에 연결된 장비가 뭔지 어떻게 알 수 있을까요?

MAC 주소만 보면 "00:1A:2B:3C:4D:5E"... 이게 PC인지, 프린터인지, IP폰인지 알 수가 없습니다. 사용자가 직접 "이건 프린터예요"라고 등록해주면 좋겠지만, 수천 대의 장비를 일일이 등록하는 건 현실적으로 불가능하죠.

**프로파일링(Profiling)** 은 [[01_Cisco ISE 개요와 아키텍처|ISE]]가 네트워크에 연결된 장비를 **자동으로 식별하고 분류** 하는 기능입니다.

```
┌─────────────────────────────────────────────────────────┐
│              프로파일링의 역할                           │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  [프로파일링 없이]                                       │
│  MAC: 00:1A:2B:3C:4D:5E → ??? (모름)                   │
│                                                         │
│  [프로파일링 적용]                                       │
│  MAC: 00:1A:2B:3C:4D:5E                                │
│  → OUI: Cisco                                          │
│  → DHCP hostname: SEP001A2B3C4D5E                      │
│  → CDP: Cisco IP Phone 8845                            │
│  → 결론: "Cisco-IP-Phone-8800-Series"                  │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

# 2. 프로파일링이 필요한 이유

## 장비 유형별 정책 적용

프로파일링 결과를 인가 정책에 활용할 수 있습니다.

```
┌─────────────────────────────────────────────────────────┐
│           장비 유형별 정책 적용 예시                      │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  Cisco IP Phone    → Voice VLAN 할당                   │
│  HP Printer        → Printer VLAN, 제한된 ACL          │
│  Windows PC        → 802.1X 인증 요구                   │
│  IoT Sensor        → IoT VLAN, 특정 서버만 통신         │
│  Apple iPhone      → BYOD 정책 적용                    │
│  Unknown Device    → 격리 VLAN                         │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

## 가시성 확보

네트워크에 **어떤 장비들이 있는지** 파악할 수 있습니다.

- 전체 엔드포인트 수
- 장비 유형별 분포
- 제조사별 분포
- 운영체제별 분포

## MAB 장비 보안 강화

802.1X를 지원하지 않는 장비(프린터, IP폰 등)는 MAB로 인증합니다. 하지만 MAB는 MAC 주소만으로 인증하기 때문에 스푸핑에 취약하죠.

프로파일링을 함께 사용하면:
```
조건: MAC = 등록된 프린터 MAC
      AND EndpointPolicy = "HP-Printer"

→ MAC은 맞지만 프로파일이 "Windows PC"로 나오면?
→ 스푸핑 의심! 접근 거부
```

> 문제 | 프로파일링 없이 MAB만 사용할 때의 보안 위험은?

정답은 → **MAC 스푸핑** 입니다. 누군가 허용된 프린터의 MAC 주소를 도용하면 인증을 통과할 수 있습니다. 프로파일링으로 실제 장비 유형을 확인하면 이를 탐지할 수 있습니다.

# 3. 프로파일링 프로브 (Probes)

ISE는 다양한 **프로브(Probe)** 를 통해 장비 정보를 수집합니다. 프로브는 정보를 수집하는 방법/소스를 의미합니다.

## 주요 프로브 유형

| 프로브 | 수집 정보 | 설정 위치 |
|--------|----------|----------|
| **RADIUS** | 인증 요청에 포함된 속성 | 기본 활성화 |
| **DHCP** | DHCP 요청/응답 정보 | DHCP 스누핑 또는 SPAN |
| **HTTP** | User-Agent, URL | HTTP 트래픽 리다이렉트 |
| **DNS** | DNS 쿼리/응답 | DNS 서버 연동 |
| **SNMP** | 장비 상세 정보 | SNMP 쿼리 |
| **NetFlow** | 트래픽 패턴 | NetFlow 수신 |
| **NMAP** | 포트 스캔 결과 | 능동 스캔 |
| **CDP/LLDP** | 네트워크 장비 정보 | 스위치에서 전달 |

## 프로브별 상세 설명

### RADIUS Probe

802.1X/MAB 인증 과정에서 수집되는 정보입니다. 별도 설정 없이 기본으로 동작합니다.

**수집 정보:**
- Calling-Station-ID (MAC 주소)
- Framed-IP-Address
- NAS-Port-Type
- Service-Type

### DHCP Probe

장비가 DHCP 요청을 할 때 포함되는 정보를 수집합니다.

**수집 정보:**
- DHCP Hostname (Option 12)
- DHCP Class Identifier (Option 60)
- DHCP Parameter Request List (Option 55)
- DHCP Fingerprint

**설정 방법:**
1. DHCP 서버에서 ISE로 DHCP 패킷 미러링 (ip helper 또는 SPAN)
2. 또는 스위치에서 DHCP 스누핑 활성화 후 ISE로 전달

```bash
! 스위치에서 DHCP 스누핑 설정 예시
Switch(config)# ip dhcp snooping
Switch(config)# ip dhcp snooping vlan 10,20,30
Switch(config)# interface Gi0/1
Switch(config-if)# ip dhcp snooping trust
```

### HTTP Probe

웹 브라우저의 User-Agent 정보를 수집합니다.

**수집 정보:**
```
User-Agent: Mozilla/5.0 (Windows NT 10.0; Win64; x64)
            AppleWebKit/537.36 (KHTML, like Gecko)
            Chrome/120.0.0.0 Safari/537.36
```

이 정보에서 운영체제(Windows 10), 브라우저(Chrome) 등을 파악할 수 있습니다.

**동작 방식:**
장비를 임시로 제한된 네트워크에 배치 → 웹 접속 시도 시 ISE로 리다이렉트 → User-Agent 수집

### SNMP Probe

스위치나 엔드포인트에 SNMP 쿼리를 보내서 정보를 수집합니다.

**수집 정보:**
- System Description
- CDP/LLDP 정보
- 인터페이스 정보
- MAC 테이블

```
! SNMP 쿼리 예시 결과
sysDescr.0 = "Cisco IP Phone 8845, V12.0.1"
```

### NMAP Probe

**능동적(Active)** 으로 장비를 스캔합니다. 열린 포트, 서비스, OS 정보를 파악합니다.

**주의:** NMAP 스캔은 네트워크 트래픽을 발생시키고, 일부 장비에 영향을 줄 수 있습니다. 신중하게 사용하세요.

```
NMAP 스캔 결과 예시:
- Open ports: 22 (SSH), 80 (HTTP), 443 (HTTPS)
- OS: Linux 4.x
- Service: Apache 2.4
```

### CDP/LLDP Probe

Cisco 장비간에 교환되는 CDP(Cisco Discovery Protocol) 또는 표준 LLDP 정보를 수집합니다.

**수집 정보:**
- Device Type
- Platform
- Capabilities
- VoIP VLAN

```
CDP 정보 예시:
Device ID: SEPXXXXXXXXXXXX
Platform: Cisco IP Phone 8845
Capabilities: Host, Phone
```

# 5. 프로파일링 정책

## 프로파일링 정책이란?

수집된 정보를 바탕으로 **"이 조건에 맞으면 이 장비 유형으로 분류"** 하는 규칙입니다.

**메뉴:** Work Centers → Profiler → Profiling Policies

## 정책 구조

```
┌─────────────────────────────────────────────────────────┐
│              프로파일링 정책 구조                        │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  Policy Name: Cisco-IP-Phone-8800-Series                │
│                                                         │
│  Minimum Certainty Factor: 20                           │
│                                                         │
│  Rules:                                                 │
│  ┌────────────────────────────────────────────────┐    │
│  │ Rule 1: CDP:Device-Platform contains "8845"    │    │
│  │         → Certainty Factor: 30                 │    │
│  └────────────────────────────────────────────────┘    │
│  ┌────────────────────────────────────────────────┐    │
│  │ Rule 2: DHCP:hostname starts with "SEP"        │    │
│  │         → Certainty Factor: 15                 │    │
│  └────────────────────────────────────────────────┘    │
│  ┌────────────────────────────────────────────────┐    │
│  │ Rule 3: MAC OUI = Cisco                        │    │
│  │         → Certainty Factor: 10                 │    │
│  └────────────────────────────────────────────────┘    │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

## Certainty Factor (확실성 지수)

각 규칙이 매칭될 때마다 **Certainty Factor(확실성 지수)** 가 누적됩니다. 누적된 값이 **Minimum Certainty Factor** 이상이 되면 해당 프로파일로 분류됩니다.

```
예시: Cisco IP Phone 8845 식별

수집된 정보:
- MAC OUI: Cisco (00:1A:2B) → +10
- DHCP hostname: SEP001A2B3C4D5E → +15
- CDP Platform: "Cisco IP Phone 8845" → +30

총 Certainty Factor: 55
Minimum 요구값: 20

결과: Cisco-IP-Phone-8800-Series로 분류 ✓
```

**왜 이런 방식을 사용할까요?**

하나의 조건만으로 판단하면 오탐이 발생할 수 있습니다. 여러 조건을 조합해서 **확신도가 높을 때만** 분류하면 정확도가 올라갑니다.

## 기본 제공 프로파일

ISE에는 수천 개의 **기본 프로파일** 이 포함되어 있습니다.

**주요 카테고리:**
- Cisco-Device (Cisco 장비)
- Apple-Device (Apple 제품)
- Microsoft-Device (Windows, Xbox 등)
- Printer (HP, Canon, Epson 등)
- IP-Phone (Cisco, Polycom 등)
- IoT (센서, 카메라 등)

기본 프로파일은 Cisco에서 정기적으로 **Feed Update** 를 통해 업데이트됩니다.

# 6. 프로파일 계층 구조

프로파일은 **계층 구조(Hierarchy)** 로 구성됩니다.

```
┌─────────────────────────────────────────────────────────┐
│              프로파일 계층 구조 예시                      │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  Unknown                                                │
│  └── Cisco-Device                                       │
│      └── Cisco-IP-Phone                                │
│          └── Cisco-IP-Phone-8800-Series                │
│              └── Cisco-IP-Phone-8845                   │
│                                                         │
│  Unknown                                                │
│  └── Apple-Device                                       │
│      └── Apple-iPhone                                   │
│          └── Apple-iPhone-14                           │
│              └── Apple-iPhone-14-Pro                   │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

**계층 구조의 장점:**

1. **점진적 분류**: 처음엔 "Cisco-Device"로 시작, 정보가 쌓이면 "Cisco-IP-Phone-8845"까지 구체화

2. **정책 유연성**: 상위 레벨로 정책 적용 가능
   ```
   조건: EndpointPolicy = "Cisco-IP-Phone" (모든 Cisco IP폰 포함)
   ```

3. **관리 용이성**: 새 모델이 나와도 상위 정책이 적용됨

# 7. 프로파일링 정책 활용

## 인가 정책에서 활용

프로파일링 결과를 인가 정책의 조건으로 사용합니다.

```
┌─────────────────────────────────────────────────────────┐
│          인가 정책에서 프로파일 활용                      │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  Rule: IP_Phone_Access                                  │
│  Condition:                                             │
│    Endpoint:EndpointPolicy = "Cisco-IP-Phone"          │
│  Result:                                                │
│    - Voice VLAN 할당                                    │
│    - Voice ACL 적용                                     │
│                                                         │
│  ─────────────────────────────────────────────────────  │
│                                                         │
│  Rule: Printer_Access                                   │
│  Condition:                                             │
│    Endpoint:EndpointPolicy = "Printer"                 │
│  Result:                                                │
│    - Printer VLAN 할당                                  │
│    - 제한된 ACL (프린트 서버만 통신)                     │
│                                                         │
│  ─────────────────────────────────────────────────────  │
│                                                         │
│  Rule: IoT_Access                                       │
│  Condition:                                             │
│    Endpoint:EndpointPolicy = "IoT-Device"              │
│  Result:                                                │
│    - IoT VLAN 할당                                      │
│    - IoT 게이트웨이만 통신 허용                          │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

## 스푸핑 탐지

프로파일과 기대값이 다르면 스푸핑으로 의심합니다.

```
시나리오: 프린터 MAC으로 등록된 장비

예상: EndpointPolicy = "HP-Printer"
실제: EndpointPolicy = "Windows-Workstation"

→ MAC 스푸핑 의심!
→ 격리 VLAN으로 이동 또는 접근 거부
```

**인가 정책 예시:**
```
Rule: Spoof_Detection
Condition:
  Endpoint:StaticAssignment = True (수동 등록된 MAC)
  AND
  Endpoint:EndpointPolicy != Endpoint:StaticGroupAssignment
Result:
  DenyAccess 또는 Quarantine_Profile
```

## 자동 VLAN 할당

프로파일에 따라 자동으로 적절한 VLAN에 배치합니다.

```
프로파일               → VLAN
──────────────────────────────────
Cisco-IP-Phone        → VLAN 100 (Voice)
Printer               → VLAN 200 (Printer)
Corporate-Windows-PC  → VLAN 10 (Employee)
BYOD-Device           → VLAN 50 (BYOD)
Unknown               → VLAN 999 (Quarantine)
```

# 8. Endpoint Identity Groups

## Endpoint Identity Group이란?

**Endpoint Identity Group** 은 엔드포인트를 그룹으로 묶어서 관리하는 기능입니다. 프로파일링과 함께 사용하면 더욱 강력해집니다.

**메뉴:** Work Centers → Profiler → Endpoint Groups

## 정적 그룹 vs 동적 그룹

### 정적 그룹 (Static Group)

관리자가 수동으로 엔드포인트를 그룹에 추가합니다.

```
그룹: VIP_Devices
멤버:
  - 00:11:22:33:44:55 (CEO 노트북)
  - 00:11:22:33:44:56 (CFO 노트북)
```

### 동적 그룹 (Dynamic Group)

조건에 따라 자동으로 그룹에 포함됩니다.

```
그룹: All_Printers
조건: EndpointPolicy LIKE "%Printer%"
결과: 프로파일이 Printer 계열인 모든 장비 자동 포함
```

## 프로파일 기반 자동 그룹 할당

프로파일링 정책에서 **자동 그룹 할당** 을 설정할 수 있습니다.

```
┌─────────────────────────────────────────────────────────┐
│              프로파일 자동 그룹 할당                      │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  Policy: HP-Printer                                     │
│                                                         │
│  Create Matching Endpoint Identity Group: ☑            │
│  Parent Group: Printer                                  │
│                                                         │
│  결과: HP 프린터로 프로파일된 장비는                      │
│        자동으로 "HP-Printer" 그룹에 추가됨               │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

# 9. 커스텀 프로파일 만들기

기본 프로파일에 없는 장비를 위해 **커스텀 프로파일** 을 만들 수 있습니다.

## 예시: 특정 IoT 센서 프로파일

회사에서 사용하는 특정 IoT 센서를 식별하는 프로파일을 만들어 봅시다.

**1단계: 장비 정보 수집**

먼저 해당 장비가 연결되었을 때 어떤 정보가 수집되는지 확인합니다.

**메뉴:** Work Centers → Profiler → Endpoint Inventory → [장비 선택]

```
수집된 정보:
- MAC OUI: AA:BB:CC (제조사: XYZ Corp)
- DHCP hostname: IoT-Sensor-001
- DHCP Class ID: XYZ-IoT-v2
- HTTP User-Agent: XYZ-Sensor/2.0
```

**2단계: 커스텀 프로파일 생성**

**메뉴:** Work Centers → Profiler → Profiling Policies → Add

```
Name: XYZ-IoT-Sensor
Description: XYZ Corp IoT 센서
Minimum Certainty Factor: 20

Parent Policy: IoT-Device

Rules:
┌────────────────────────────────────────────────────────┐
│ Rule 1:                                                │
│ Condition: MAC:OUI contains "AA:BB:CC"                │
│ Certainty Factor: 10                                   │
└────────────────────────────────────────────────────────┘
┌────────────────────────────────────────────────────────┐
│ Rule 2:                                                │
│ Condition: DHCP:hostname contains "IoT-Sensor"        │
│ Certainty Factor: 15                                   │
└────────────────────────────────────────────────────────┘
┌────────────────────────────────────────────────────────┐
│ Rule 3:                                                │
│ Condition: DHCP:class-identifier equals "XYZ-IoT-v2"  │
│ Certainty Factor: 20                                   │
└────────────────────────────────────────────────────────┘
```

**3단계: 테스트**

장비를 다시 연결하거나, 기존 엔드포인트를 수동으로 다시 프로파일링합니다.

```bash
# ISE CLI에서 재프로파일링
ise/admin# application configure ise
[선택] 3 (Profiler Functions)
[선택] 1 (Re-profile endpoints)
```

# 11. 트러블슈팅

## 프로파일링이 안 되는 경우

### 1. 프로브가 비활성화됨

```
확인: Administration → System → Deployment → [노드] → Profiling
해결: 필요한 프로브 활성화
```

### 2. DHCP 정보가 수집되지 않음

```
원인: DHCP 패킷이 ISE에 도달하지 않음
해결:
- ip helper-address에 ISE 추가
- 또는 SPAN으로 DHCP 트래픽 미러링
- 또는 DHCP 서버에서 ISE로 전달
```

### 3. Certainty Factor가 부족함

```
원인: 수집된 정보가 적어서 최소 확실성에 도달하지 못함
해결:
- 추가 프로브 활성화 (SNMP, HTTP 등)
- 프로파일 규칙의 Certainty Factor 조정
- 커스텀 프로파일 생성
```

### 4. 잘못된 프로파일로 분류됨

```
원인: 프로파일 규칙이 너무 일반적이거나 충돌
해결:
- 해당 엔드포인트의 수집된 속성 확인
- 더 구체적인 규칙 추가
- 잘못된 프로파일의 규칙 수정
```

## 디버그 방법

```
1. 엔드포인트 상세 정보 확인
   Work Centers → Profiler → Endpoint Inventory → [장비 클릭]

2. 수집된 속성(Attributes) 확인
   - 어떤 프로브에서 어떤 정보가 수집되었는지

3. 프로파일링 과정 확인
   - 왜 특정 프로파일로 분류되었는지
   - 어떤 규칙이 매칭되었는지
```

# 12. 정리하며

이번 장에서 배운 프로파일링의 핵심을 정리합니다.

**프로파일링이란:**
- 네트워크 장비를 **자동으로 식별하고 분류** 하는 기능
- 수집된 정보를 바탕으로 장비 유형 판별

**프로브 (정보 수집 방법):**
- RADIUS, DHCP, HTTP, DNS, SNMP, NMAP, CDP/LLDP
- 여러 프로브를 조합하면 정확도 향상

**Certainty Factor:**
- 규칙 매칭 시 누적되는 확실성 점수
- 최소값 이상이면 해당 프로파일로 분류

**활용:**
- 장비 유형별 자동 정책 적용
- MAC 스푸핑 탐지
- 네트워크 가시성 확보

> 문제 | ISE에서 DHCP hostname이 "SEP"로 시작하는 장비를 Cisco IP Phone으로 분류하려면 어떤 기능을 사용해야 할까요?

정답은 → **프로파일링 정책(Profiling Policy)** 입니다. DHCP 프로브로 수집된 hostname 정보를 조건으로 사용하여 분류합니다.

# 시리즈를 마무리하며

지금까지 Cisco ISE와 네트워크 접근 제어에 대해 알아보았습니다.

**배운 내용 정리:**

1. **ISE 개요** - ISE가 무엇이고 왜 필요한지
2. **AAA** - 인증, 인가, 계정 관리의 기본 개념
3. **802.1X** - 포트 기반 네트워크 접근 제어
4. **RADIUS/TACACS+** - AAA 프로토콜
5. **NAC 정책** - ISE에서 정책 구성하기
6. **게스트/BYOD** - 방문객과 개인 장비 관리
7. **프로파일링** - 장비 자동 식별과 분류

이 내용들을 이해하셨다면, 네트워크 접근 제어의 기본기는 갖추신 겁니다. 실제 환경에서 ISE를 구축하고 운영하면서 더 깊은 경험을 쌓아가시기 바랍니다.
