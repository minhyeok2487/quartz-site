# 1. Cisco ISE란 무엇인가? - 네트워크의 경비원을 만나다

네트워크 보안을 이야기할 때 방화벽만 생각하시는 분들이 많습니다. 물론 방화벽도 중요하죠. 하지만 잠깐 생각해 보세요. 방화벽은 외부에서 들어오는 위협을 막는 데 집중합니다. 그런데 **내부에서 발생하는 위협** 은 어떻게 막을까요?

제가 예전에 근무했던 회사에서 있었던 일입니다. 어느 날 네트워크가 갑자기 느려졌어요. 원인을 찾아보니 누군가 개인 노트북을 회사 네트워크에 연결해서 토렌트를 돌리고 있더군요. 방화벽은 멀쩡했습니다. 외부 공격이 아니었으니까요. 문제는 내부에서 아무나 네트워크에 접속할 수 있다는 것이었죠.

회사에 출입할 때 사원증을 찍고 들어가잖아요? 네트워크에도 똑같은 게 필요합니다. "누가 접속하는지", "어떤 장비로 접속하는지", "접속해서 무엇을 하는지" 확인하는 시스템 말이에요. 이것이 바로 **Cisco ISE(Identity Services Engine)** 가 하는 일입니다.

## ISE를 한마디로 정의하면

**Cisco ISE** 는 네트워크 접근 제어(NAC)와 정책 관리를 위한 **차세대 [[02_AAA 기본 개념|AAA]](Authentication, Authorization, Accounting) 플랫폼** 입니다.

어렵게 느껴지시나요? 쉽게 말해볼게요. ISE는 네트워크에 접속하려는 모든 사용자와 장비를 **식별하고, 권한을 부여하고, 활동을 기록** 하는 중앙 관리 시스템입니다. 회사 건물의 출입 관리 시스템을 생각하시면 됩니다.

```
┌─────────────────────────────────────────────────────────┐
│                 회사 출입 vs 네트워크 접속                 │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  [회사 건물]                    [네트워크]               │
│                                                         │
│  사원증 찍기      ─────────►    ID/Password 입력        │
│  출입문 열림      ─────────►    네트워크 접속 허용       │
│  3층만 출입 가능   ─────────►    특정 서버만 접근 가능    │
│  출입 기록 저장    ─────────►    접속 로그 저장          │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

예전에는 네트워크에 케이블만 꽂으면 바로 접속이 됐습니다. 보안? 그런 거 없었죠. "연결되면 곧 신뢰"였던 시절이었습니다. 하지만 지금은 완전히 다릅니다.

요즘 회사를 둘러보세요. 직원들이 개인 노트북, 스마트폰, 태블릿을 회사 Wi-Fi에 연결합니다. 이른바 **BYOD(Bring Your Own Device)** 시대죠. 거기에 IP 카메라, 스마트 프린터, 온도 센서 같은 IoT 장비도 폭발적으로 늘어났고요. 이런 환경에서 "아무나 접속 OK"는 정말 있을 수 없는 일입니다.

## 실제로 ISE가 필요한 상황들

"그래서 ISE가 정확히 언제 필요한 건데요?" 좋은 질문입니다. 제가 현장에서 겪었던 상황들을 말씀드릴게요.

**상황 1: 감사가 왔을 때**

"누가 언제 어디서 네트워크에 접속했는지 보여주세요."

감사관이 이렇게 요청합니다. ISE가 없으면? 식은땀이 흐르죠. 스위치 로그를 일일이 뒤져야 하는데, 그것도 다 남아있지 않습니다. ISE가 있으면? 클릭 몇 번으로 깔끔한 보고서가 나옵니다. 실제로 금융권이나 의료 분야에서 ISE를 도입하는 가장 큰 이유 중 하나가 바로 이 **컴플라이언스 대응** 입니다.

**상황 2: 방문객이 Wi-Fi를 요청할 때**

"인터넷 좀 쓸 수 있을까요?"

거래처 담당자가 회의실에서 물어봅니다. 그런데 회사 Wi-Fi 비밀번호를 알려주면... 그 사람이 내부 서버에도 접근할 수 있게 됩니다. 위험하죠? ISE가 있으면 **게스트 포털** 을 통해 임시 계정을 발급하고, 인터넷만 사용할 수 있도록 제한할 수 있습니다. 방문객은 편하게 인터넷을 쓰고, 회사는 보안을 유지하고. 모두가 행복해지는 거죠.

**상황 3: 직원이 개인 스마트폰을 연결하려 할 때**

"제 폰으로도 회사 메일 좀 볼 수 있나요?"

영업팀 김 대리가 물어봅니다. 업무상 필요하니 OK 해주고 싶은데, 개인 폰에 회사 데이터가 들어가면 보안 문제가 생길 수 있습니다. ISE의 **BYOD 기능** 을 쓰면 개인 장비를 등록하고, 회사 장비와 다른 수준의 접근 권한을 줄 수 있습니다. "메일은 되는데 파일 서버는 안 돼요" 이런 식으로요.

**상황 4: 이상한 장비가 네트워크에 붙었을 때**

"이 MAC 주소는 뭐지...?"

모니터링을 하다 보면 등록되지 않은 장비가 네트워크에 접속한 걸 발견할 때가 있습니다. 누가 몰래 개인 공유기를 연결했거나, 최악의 경우 악의적인 장비일 수도 있죠. ISE는 이런 장비를 **자동으로 탐지하고 격리** 할 수 있습니다. 네트워크의 CCTV 같은 역할을 하는 거예요.

> 문제 | 다음 중 ISE가 해결하는 문제가 아닌 것은?
> A) 허가되지 않은 장비의 네트워크 접속
> B) 사용자별 네트워크 접근 권한 관리
> C) 라우팅 프로토콜 최적화
> D) 게스트 사용자 접근 관리

정답은 → C입니다. 라우팅은 라우터가 하는 일이지, ISE의 영역이 아니에요. ISE는 "누가 접속하느냐"를 관리하는 거지, "패킷이 어디로 가느냐"를 관리하는 게 아닙니다.

# 2. ISE 아키텍처 - 이 녀석은 어떻게 생겼을까?

ISE의 구조를 이해하면 전체 그림이 보입니다. 처음엔 좀 복잡해 보일 수 있는데, 하나씩 뜯어보면 그리 어렵지 않아요.

## 페르소나(Persona) - ISE가 쓰는 여러 개의 모자

ISE 서버는 여러 가지 **페르소나(Persona)** 를 가질 수 있습니다. 페르소나라... 좀 멋있는 단어죠? 쉽게 말하면 "역할"입니다. 한 사람이 회사에서는 팀장, 집에서는 아빠, 동창회에서는 총무 역할을 하는 것처럼, ISE도 상황에 따라 다른 모자를 씁니다.

| 페르소나 | 별명 | 하는 일 |
|---------|------|---------|
| **PAN** (Policy Administration Node) | 두뇌 | 정책 설정, 시스템 구성, 전체 관리 |
| **PSN** (Policy Service Node) | 일꾼 | 실제로 인증하고 권한 부여하는 실무자 |
| **MnT** (Monitoring and Troubleshooting) | 기록관 | 로그 수집하고 보고서 만드는 역할 |
| **pxGrid** | 외교관 | 다른 보안 시스템과 정보 교환 |

회사에 비유하면 이해가 쉬울 거예요.

- **PAN** 은 사장님입니다. 정책을 결정하고 전체를 관리하죠.
- **PSN** 은 현장 직원들입니다. 실제로 손님(사용자)을 맞이하고 업무를 처리해요.
- **MnT** 는 감사팀입니다. 모든 일을 기록하고 보고서를 만들죠.
- **pxGrid** 는 대외협력팀입니다. 다른 회사(시스템)와 정보를 주고받아요.

소규모 환경에서는 하나의 ISE 서버가 모든 역할을 다 합니다. 사장님이 직접 손님 맞이하고, 기록도 하고, 외부 미팅도 다니는 1인 기업 같은 거죠. 이걸 **Standalone** 구성이라고 합니다.

하지만 회사가 커지면 어떻게 되나요? 역할을 나눠야겠죠. 대규모 환경에서는 서버를 여러 대 두고 역할별로 분리합니다.

```
┌─────────────────────────────────────────────────────────┐
│              대규모 ISE 배포 - 이렇게 생겼어요            │
├─────────────────────────────────────────────────────────┤
│                                                         │
│           ┌─────────┐         ┌─────────┐              │
│           │   PAN   │◄───────►│   PAN   │              │
│           │ Primary │  동기화  │Secondary│              │
│           └────┬────┘         └─────────┘              │
│                │ (정책 배포)                            │
│       ┌────────┼────────┬────────────┐                 │
│       ▼        ▼        ▼            ▼                 │
│  ┌─────────┐┌─────────┐┌─────────┐┌─────────┐         │
│  │   PSN   ││   PSN   ││   PSN   ││   MnT   │         │
│  │  서울   ││  부산   ││  대전   ││ 로그수집 │          │
│  └─────────┘└─────────┘└─────────┘└─────────┘         │
│                                                         │
│  (각 지역 사용자들은 가까운 PSN에서 인증받아요)           │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

서울에 있는 직원이 인증받으려고 부산까지 갈 필요 없잖아요? 각 지역에 PSN을 배치하면 가까운 곳에서 빠르게 인증받을 수 있습니다. PAN은 본사에서 전체를 관리하고요.

## 함께 일하는 친구들 - ISE 혼자서는 못해요

ISE가 아무리 똑똑해도 혼자서는 아무것도 못합니다. 여러 구성 요소가 함께 일해야 하죠. 마치 축구에서 골키퍼 혼자 경기를 할 수 없는 것처럼요.

**1. 네트워크 장비 (NAD - Network Access Device)**

스위치, 무선 컨트롤러(WLC), VPN 장비 같은 것들이에요. 이 장비들이 "문지기" 역할을 합니다. 사용자가 네트워크에 접속하려고 하면, NAD가 ISE에게 물어봐요. "이 사람 들여보내도 돼요?"

**2. ISE 서버**

두뇌 역할이죠. NAD한테 "이 사람 누군데?" 하고 정보를 받으면, 정책을 확인해서 "OK, 들여보내" 또는 "NO, 차단해"라고 답해줍니다.

**3. 외부 ID 소스 (Identity Source)**

Active Directory, LDAP 같은 거예요. ISE가 "김철수라는 사람 있어?" 하고 물어보면 "응, 있어. 개발팀 소속이야"라고 알려주는 역할입니다. ISE가 모든 직원 정보를 직접 저장할 수도 있지만, 대부분의 회사는 이미 AD에 직원 정보가 있으니까 그걸 활용하는 거죠.

**4. 엔드포인트 (Endpoint)**

네트워크에 접속하려는 PC, 스마트폰, 프린터, IP 카메라 같은 장비들이에요. 이 친구들이 주인공입니다. ISE는 이들을 위해 존재하는 거니까요.

이 네 가지가 어떻게 대화하는지 그림으로 볼까요?

```
당신의 노트북              스위치                 ISE                AD서버
     │                      │                    │                    │
     │ ─── 연결 시도 ──────► │                    │                    │
     │                      │                    │                    │
     │ ◄─── ID/PW 입력해 ── │                    │                    │
     │                      │                    │                    │
     │ ─── ID/PW 전송 ─────► │                    │                    │
     │                      │                    │                    │
     │                      │ ── 이 사람 OK? ──► │                    │
     │                      │                    │                    │
     │                      │                    │ ── 김철수 있어? ──► │
     │                      │                    │                    │
     │                      │                    │ ◄── 응, 개발팀 ─── │
     │                      │                    │                    │
     │                      │ ◄── OK, VLAN 10 ── │                    │
     │                      │                    │                    │
     │ ◄─── 접속 완료! ───── │                    │                    │
     │                      │                    │                    │
```

이 과정이 눈 깜짝할 사이에 일어납니다. 사용자 입장에서는 그냥 ID, 비밀번호 넣으면 접속되는 것처럼 느껴지죠.

## 라이선스 - 돈 이야기도 해야죠

ISE 라이선스... 솔직히 좀 복잡합니다. 하지만 기본 구조만 알면 됩니다.

**ISE 3.x 기준 라이선스:**

| 라이선스 | 뭐가 되나요? | 언제 필요해요? |
|---------|-------------|---------------|
| **Essentials** | 기본 인증, 802.1X, 게스트 접근 | "일단 인증만 하고 싶어요" |
| **Advantage** | + 프로파일링, BYOD, pxGrid | "장비 자동 인식도 하고 싶어요" |
| **Premier** | + 고급 위협 대응 연동 | "완전체가 필요해요" |

라이선스는 **동시 접속 엔드포인트 수** 기준입니다. 회사에 PC가 1,000대 있는데 동시에 500대만 켜져 있다면? 500개 라이선스면 됩니다. 물론 여유 있게 준비하는 게 좋겠지만요.

# 3. ISE 배포 모델 - 우리 회사엔 뭐가 맞을까?

환경 규모에 따라 ISE 배포 방식이 달라집니다. 1인 카페와 프랜차이즈 커피숍의 운영 방식이 다른 것처럼요.

## Standalone - 작지만 강한

가장 단순한 구성입니다. ISE 서버 한 대가 모든 일을 다 합니다.

**이런 곳에 어울려요:**
- 엔드포인트 500개 미만의 소규모 네트워크
- "일단 테스트해보자"는 PoC 환경
- "서버 한 대 죽어도 괜찮아"라고 할 수 있는 곳 (솔직히 거의 없죠)

**장점:** 구성이 간단하고, 서버 한 대만 사면 됩니다.
**단점:** 이 서버가 죽으면 끝입니다. 아무도 인증을 못 받아요.

저는 개인적으로 Standalone은 테스트용으로만 권장합니다. 실제 운영 환경에서 단일 장애점(SPOF)은 정말 위험하거든요. 새벽 2시에 ISE가 죽으면... 생각만 해도 아찔하죠?

## 분산 배포 - 크고 안정적인

역할별로 서버를 나누는 구성입니다. 대부분의 기업 환경에서 이 방식을 사용해요.

**이런 곳에 어울려요:**
- 엔드포인트가 많은 중대규모 네트워크
- 서울, 부산, 대전 등 지리적으로 분산된 환경
- "24시간 365일 죽으면 안 돼요"라는 곳

**일반적인 구성:**
- PAN 2대 (Primary + Secondary) - 하나 죽어도 다른 하나가 버팀
- PSN 여러 대 (지역별 배치) - 가까운 곳에서 빠르게 인증
- MnT 1~2대 - 로그는 중앙에서 관리

비용은 더 들지만, 마음의 평화를 삽니다. IT 담당자라면 이 마음의 평화가 얼마나 소중한지 아실 거예요.

## 하이브리드 - 클라우드와 함께

온프레미스 ISE와 클라우드 서비스를 함께 쓰는 구성입니다. Cisco의 클라우드 서비스와 연동해서 관리 부담을 줄일 수 있어요. 최근 트렌드이긴 한데, 아직 완전한 클라우드 ISE는 아닙니다. 하이브리드 형태로 가는 과도기라고 보시면 됩니다.

# 4. ISE vs 경쟁 솔루션 - 왜 ISE를 선택할까?

ISE만 NAC 솔루션인 건 아닙니다. 다른 선택지도 있어요. 간단히 비교해 볼까요?

| 항목 | Cisco ISE | Aruba ClearPass | ForeScout |
|------|-----------|-----------------|-----------|
| **강점** | Cisco 장비랑 찰떡 | 이것저것 섞어 쓰는 환경에 좋음 | 에이전트 설치 안 해도 됨 |
| **약점** | Cisco 아니면 좀 아쉬움 | 라이선스가 복잡함 | 인증 기능이 약함 |
| **추천 환경** | Cisco 위주 인프라 | 멀티벤더 환경 | "일단 뭐가 있는지 보고 싶어요" |

솔직히 말씀드리면, 이미 Cisco 스위치와 무선 장비를 쓰고 있다면 ISE가 최선의 선택입니다. **TrustSec** , **SD-Access** 같은 Cisco의 고급 기능들과 완벽하게 연동되거든요. 다른 벤더 NAC로는 이 기능들을 100% 활용하기 어렵습니다.

반대로 HP, Juniper, Aruba 장비가 섞여 있다면? ClearPass도 고려해볼 만합니다. 세상에 완벽한 솔루션은 없어요. 자기 환경에 맞는 걸 고르는 게 중요합니다.

# 5. 정리하며 - 여기까지 잘 따라오셨나요?

이번 장에서 배운 내용을 정리해 볼게요. 생각보다 많이 배우셨죠?

- **Cisco ISE** 는 네트워크의 출입 관리 시스템입니다. 누가 들어오는지 확인하고, 뭘 할 수 있는지 정하고, 뭘 했는지 기록해요.

- ISE는 네 가지 역할(페르소나)을 합니다:
  - **PAN** - 정책 관리하는 두뇌
  - **PSN** - 실제 인증하는 일꾼
  - **MnT** - 로그 기록하는 기록관
  - **pxGrid** - 다른 시스템이랑 대화하는 외교관

- 소규모면 **Standalone** , 대규모면 **분산 배포** 를 사용합니다.

- ISE 혼자 일하는 게 아니에요. **NAD(스위치 등)** , **AD** , **엔드포인트** 와 함께 팀플레이합니다.

> 문제 | ISE에서 실제 RADIUS 인증을 처리하는 페르소나는?

정답은 → **PSN(Policy Service Node)** 입니다. PAN은 정책만 관리하고, 실제 인증 업무는 PSN이 담당해요. 회사로 치면 PAN이 사장님, PSN이 현장 직원인 셈이죠.

어떠세요? ISE가 뭔지 대략 감이 오시나요? 아직 구체적인 설정 방법은 다루지 않았지만, 일단 "이 녀석이 뭐 하는 놈인지"는 아셨을 거예요. 그게 가장 중요합니다. 세부 사항은 앞으로 차근차근 배워나가면 됩니다.
