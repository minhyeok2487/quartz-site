# 1. 802.1X란 무엇인가?

예전에는 네트워크 케이블만 꽂으면 바로 네트워크에 접속됐습니다. 스위치 포트에 PC를 연결하면 끝. 보안? 물리적으로 건물 안에 있으니까 괜찮겠지... 라고 생각했던 시절이 있었죠.

하지만 이제는 다릅니다. 누군가 몰래 네트워크 케이블을 꽂아서 내부망에 침투할 수 있습니다. 무선 네트워크는 더 위험하고요. 그래서 등장한 것이 **802.1X** 입니다.

**IEEE 802.1X** 는 **포트 기반 네트워크 접근 제어(Port-Based Network Access Control)** 표준입니다. 쉽게 말해서, 네트워크 포트(유선이든 무선이든)에 연결할 때 **인증을 거쳐야만** 네트워크를 사용할 수 있게 하는 기술입니다.

```
┌─────────────────────────────────────────────────────────┐
│              802.1X 없을 때 vs 있을 때                   │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  [802.1X 없음]                                          │
│  케이블 연결 → 바로 네트워크 접속 → 내부 자원 접근 가능    │
│                                                         │
│  [802.1X 있음]                                          │
│  케이블 연결 → 인증 요청 → 인증 성공 → 네트워크 접속      │
│                        → 인증 실패 → 접근 차단           │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

# 2. 802.1X 구성 요소

802.1X 인증에는 세 가지 핵심 구성 요소가 있습니다.

## 1. Supplicant (요청자)

네트워크에 접속하려는 **클라이언트** 입니다. PC, 노트북, 스마트폰 등이 해당됩니다.

Supplicant는 인증에 필요한 자격 증명(Credential)을 제공합니다:
- 사용자명/비밀번호
- 디지털 인증서
- 기타 인증 정보

**Windows, macOS, Linux** 등 대부분의 운영체제에는 802.1X Supplicant가 내장되어 있습니다. Cisco에서는 **AnyConnect** 의 NAM(Network Access Manager) 모듈을 Supplicant로 사용하기도 합니다.

## 2. Authenticator (인증자)

Supplicant와 Authentication Server 사이에서 **중개 역할** 을 하는 네트워크 장비입니다.

- **유선 네트워크**: 스위치
- **무선 네트워크**: 무선 컨트롤러(WLC) 또는 AP

Authenticator는 직접 인증을 수행하지 않습니다. Supplicant의 인증 요청을 Authentication Server로 전달하고, 결과에 따라 포트를 열거나 닫습니다.

## 3. Authentication Server (인증 서버)

실제로 인증을 수행하는 서버입니다. 우리의 주인공 **Cisco ISE** 가 바로 이 역할을 합니다.

Authentication Server는:
- 사용자 자격 증명을 검증
- 외부 ID 소스(AD, LDAP 등)와 연동
- 인증 결과와 인가 정책을 Authenticator에 전달

```
┌─────────────────────────────────────────────────────────┐
│                 802.1X 구성 요소                         │
├─────────────────────────────────────────────────────────┤
│                                                         │
│   ┌──────────┐    EAPoL     ┌──────────┐    RADIUS    ┌──────────┐
│   │Supplicant│ ◄──────────► │Authenti- │ ◄──────────► │  Auth    │
│   │  (PC)    │              │  cator   │              │  Server  │
│   │          │              │ (Switch) │              │  (ISE)   │
│   └──────────┘              └──────────┘              └──────────┘
│                                                         │
│   "나 접속할게"              "잠깐, ISE한테           "이 사람
│                              물어볼게"                 확인됐어"
│                                                         │
└─────────────────────────────────────────────────────────┘
```

> 문제 | 802.1X에서 스위치의 역할은 무엇인가요?

정답은 → **Authenticator(인증자)** 입니다. 스위치는 직접 인증하지 않고, Supplicant와 Authentication Server 사이에서 중개 역할을 합니다.

# 3. 802.1X 프로토콜

802.1X 인증에서 사용되는 프로토콜들을 살펴보겠습니다.

## EAPoL (EAP over LAN)

**Supplicant와 Authenticator 사이** 에서 사용되는 프로토콜입니다. 이더넷 프레임으로 캡슐화되어 전송됩니다.

- 이더넷 타입: 0x888E
- 직접 연결된 L2 구간에서만 동작

**EAPoL 메시지 유형:**

| 메시지 | 설명 |
|--------|------|
| **EAPoL-Start** | Supplicant가 인증 시작 요청 |
| **EAPoL-Request/Identity** | Authenticator가 신원 요청 |
| **EAPoL-Response/Identity** | Supplicant가 신원 응답 |
| **EAPoL-Success** | 인증 성공 |
| **EAPoL-Failure** | 인증 실패 |
| **EAPoL-Logoff** | 세션 종료 |

## RADIUS

**Authenticator와 Authentication Server 사이** 에서 사용되는 프로토콜입니다.

- UDP 포트: 1812 (인증), 1813 (어카운팅)
- EAP 메시지를 RADIUS 패킷 안에 캡슐화해서 전송

([[04_RADIUS와 TACACS+|RADIUS]]에 대해서는 다음 장에서 자세히 다룹니다)

# 4. EAP (Extensible Authentication Protocol)

## EAP란?

**EAP(Extensible Authentication Protocol)** 은 인증 방식을 정의하는 **프레임워크** 입니다. "확장 가능한"이라는 이름처럼, 다양한 인증 방식을 지원합니다.

EAP 자체는 인증 방식을 규정하지 않습니다. 대신 여러 가지 **EAP 메서드(EAP Method)** 를 통해 실제 인증이 이루어집니다.

## 주요 EAP 메서드

### EAP-TLS (Transport Layer Security)

**가장 안전한** EAP 메서드입니다. 클라이언트와 서버 **모두 인증서** 를 사용합니다.

**장점:**
- 상호 인증 (서버도 클라이언트를 인증, 클라이언트도 서버를 인증)
- 비밀번호 없음 = 비밀번호 유출 위험 없음
- 가장 높은 보안 수준

**단점:**
- 모든 클라이언트에 인증서 배포 필요
- 인증서 관리 복잡 (발급, 갱신, 폐기)
- PKI 인프라 필수

```
┌─────────────────────────────────────────────────────────┐
│                    EAP-TLS 인증 흐름                     │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  Supplicant                              Auth Server    │
│      │                                        │         │
│      │ ──── Client Hello ──────────────────► │         │
│      │                                        │         │
│      │ ◄─── Server Hello + Server Cert ───── │         │
│      │                                        │         │
│      │ ──── Client Cert + Key Exchange ────► │         │
│      │                                        │         │
│      │ ◄─── Finished ─────────────────────── │         │
│      │                                        │         │
│      │           [TLS 터널 수립 완료]           │         │
│      │           [상호 인증 완료]              │         │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

### EAP-PEAP (Protected EAP)

**서버 인증서만** 사용하고, 클라이언트는 사용자명/비밀번호로 인증합니다. Microsoft와 Cisco가 공동 개발했습니다.

**동작 방식:**
1. 서버 인증서로 TLS 터널 생성
2. 터널 안에서 내부 인증 (보통 MSCHAPv2)

**장점:**
- 클라이언트 인증서 불필요 (관리 부담 감소)
- 기존 AD 계정 사용 가능
- 널리 지원됨 (Windows 기본 지원)

**단점:**
- EAP-TLS보다 보안 수준 낮음 (비밀번호 사용)
- 서버 인증서는 여전히 필요

```
┌─────────────────────────────────────────────────────────┐
│                   EAP-PEAP 인증 흐름                     │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  [Phase 1: TLS 터널 생성]                               │
│  서버 인증서로 암호화된 터널 수립                         │
│                                                         │
│  [Phase 2: 내부 인증 (터널 안에서)]                      │
│  사용자명/비밀번호로 인증 (MSCHAPv2 등)                  │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

### EAP-TTLS (Tunneled TLS)

PEAP과 유사하지만, 내부 인증 방식이 더 유연합니다.

**지원하는 내부 인증:**
- PAP, CHAP, MS-CHAP, MS-CHAPv2
- EAP-MD5, EAP-MSCHAPv2

### EAP-FAST (Flexible Authentication via Secure Tunneling)

**Cisco가 개발** 한 EAP 메서드입니다. 인증서 없이 빠른 인증이 가능합니다.

**특징:**
- PAC(Protected Access Credential)이라는 공유 비밀 사용
- 인증서 인프라 없이 배포 가능
- 빠른 재인증 지원

## EAP 메서드 비교

| 메서드 | 클라이언트 인증서 | 서버 인증서 | 보안 수준 | 배포 난이도 |
|--------|------------------|-------------|----------|------------|
| **EAP-TLS** | 필요 | 필요 | 최상 | 어려움 |
| **EAP-PEAP** | 불필요 | 필요 | 상 | 보통 |
| **EAP-TTLS** | 불필요 | 필요 | 상 | 보통 |
| **EAP-FAST** | 불필요 | 선택 | 중상 | 쉬움 |

> 문제 | 클라이언트와 서버 모두 인증서를 사용하는 EAP 메서드는?

정답은 → **EAP-TLS** 입니다.

# 5. 802.1X 인증 흐름

전체 인증 흐름을 단계별로 살펴보겠습니다.

```
┌─────────────────────────────────────────────────────────────────────┐
│                      802.1X 인증 전체 흐름                           │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│  Supplicant          Authenticator           Auth Server (ISE)     │
│  (PC)                (Switch)                                       │
│      │                    │                        │                │
│      │                    │                        │                │
│  ① 케이블 연결 (Link Up)   │                        │                │
│      │                    │                        │                │
│      │ ◄── EAP-Request ── │                        │                │
│      │     /Identity      │                        │                │
│      │                    │                        │                │
│  ② 사용자 ID 전송          │                        │                │
│      │ ─── EAP-Response ─►│                        │                │
│      │     /Identity      │                        │                │
│      │                    │                        │                │
│      │                    │ ── RADIUS Access ────► │                │
│      │                    │    Request             │                │
│      │                    │                        │                │
│      │                    │ ◄─ RADIUS Access ───── │                │
│      │                    │    Challenge           │                │
│      │                    │                        │                │
│  ③ EAP 인증 교환 (여러 왕복)                         │                │
│      │ ◄──────────────────┼────────────────────────│                │
│      │ ──────────────────►│────────────────────────►                │
│      │                    │                        │                │
│      │                    │ ◄─ RADIUS Access ───── │                │
│      │                    │    Accept              │ ④ 인증 성공     │
│      │                    │    + 인가 정보         │                │
│      │                    │                        │                │
│      │ ◄── EAP-Success ── │                        │                │
│      │                    │                        │                │
│  ⑤ 포트 열림, 네트워크 접속 │                        │                │
│      │                    │                        │                │
└─────────────────────────────────────────────────────────────────────┘
```

### 단계별 설명

**① 링크 업 (Link Up)**
- PC가 스위치 포트에 연결됨
- 스위치가 해당 포트를 "unauthorized" 상태로 설정
- 인증 전까지 일반 트래픽 차단

**② Identity 요청/응답**
- 스위치가 EAP-Request/Identity 전송
- PC가 사용자 ID로 응답

**③ EAP 인증 교환**
- 선택된 EAP 메서드에 따라 인증 진행
- 스위치는 EAP 메시지를 RADIUS로 변환해서 ISE에 전달
- 여러 번의 Challenge-Response 교환

**④ 인증 결과**
- 성공: RADIUS Access-Accept (+ 인가 정보)
- 실패: RADIUS Access-Reject

**⑤ 포트 상태 변경**
- 성공 시: 포트를 "authorized" 상태로 변경, VLAN/ACL 적용
- 실패 시: 포트 차단 또는 Guest VLAN으로 이동

# 6. 802.1X 포트 상태

802.1X를 사용하면 스위치 포트는 두 가지 상태를 가집니다.

## Unauthorized (비인가)

- 인증이 완료되지 않은 상태
- **EAPoL 트래픽만** 허용
- 일반 데이터 트래픽 차단

## Authorized (인가)

- 인증이 성공한 상태
- 모든 트래픽 허용 (정책에 따라)
- 적용된 VLAN, ACL에 따라 접근 제어

# 7. 스위치 802.1X 설정

Cisco 스위치에서 802.1X를 설정하는 방법을 알아보겠습니다.

## 기본 설정

```bash
! AAA 활성화
Switch(config)# aaa new-model

! RADIUS 서버 정의
Switch(config)# radius server ISE-SERVER
Switch(config-radius-server)# address ipv4 10.1.1.100 auth-port 1812 acct-port 1813
Switch(config-radius-server)# key MySecretKey123
Switch(config-radius-server)# exit

! AAA 인증 방식 정의
Switch(config)# aaa authentication dot1x default group radius

! AAA 인가 방식 정의
Switch(config)# aaa authorization network default group radius

! AAA 어카운팅 설정
Switch(config)# aaa accounting dot1x default start-stop group radius

! 802.1X 전역 활성화
Switch(config)# dot1x system-auth-control
```

## 인터페이스 설정

```bash
! 인터페이스 진입
Switch(config)# interface GigabitEthernet0/1

! 포트 모드를 Access로 설정
Switch(config-if)# switchport mode access

! 802.1X 활성화
Switch(config-if)# authentication port-control auto

! 인증 방식 지정 (802.1X 우선)
Switch(config-if)# authentication order dot1x mab
Switch(config-if)# authentication priority dot1x mab

! 802.1X 활성화
Switch(config-if)# dot1x pae authenticator
```

## 인증 실패 시 대체 동작

인증에 실패했을 때의 대체 동작을 설정할 수 있습니다.

```bash
! Guest VLAN 설정 (인증 실패 시)
Switch(config-if)# authentication event fail action authorize vlan 999

! Auth-Fail VLAN 설정
Switch(config-if)# authentication event server dead action authorize vlan 1

! No-Response 시 (Supplicant 없는 장비)
Switch(config-if)# authentication event no-response action authorize vlan 999
```

## 확인 명령어

```bash
! 802.1X 상태 확인
Switch# show dot1x all

! 인터페이스별 인증 상태 확인
Switch# show authentication sessions interface Gi0/1

! 인증 세션 상세 정보
Switch# show authentication sessions interface Gi0/1 details
```

# 8. MAB (MAC Authentication Bypass)

## MAB란?

**MAB(MAC Authentication Bypass)** 은 802.1X를 지원하지 않는 장비를 위한 대체 인증 방식입니다.

프린터, IP폰, IP 카메라, IoT 센서 등 많은 장비들이 802.1X Supplicant를 가지고 있지 않습니다. 이런 장비들은 어떻게 인증할까요?

MAB는 장비의 **MAC 주소** 를 인증 정보로 사용합니다.

```
┌─────────────────────────────────────────────────────────┐
│                    MAB 동작 흐름                        │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  1. 장비가 스위치 포트에 연결                            │
│  2. 스위치가 EAP-Request/Identity 전송                  │
│  3. 장비가 응답 없음 (Supplicant 없으니까)               │
│  4. 타임아웃 후 MAB 시작                                │
│  5. 스위치가 장비의 MAC 주소 학습                        │
│  6. MAC 주소를 Username/Password로 ISE에 전송           │
│  7. ISE가 MAC 주소 데이터베이스 확인                     │
│  8. 등록된 MAC이면 인증 성공, 아니면 실패                │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

## MAB 설정

```bash
! 인터페이스에서 MAB 활성화
Switch(config-if)# mab

! 802.1X와 MAB 순서 지정
Switch(config-if)# authentication order dot1x mab
Switch(config-if)# authentication priority dot1x mab
```

## MAB 주의사항

**보안 경고:** MAC 주소는 쉽게 위조(스푸핑)할 수 있습니다!

누군가 허용된 프린터의 MAC 주소를 알아내서 자신의 노트북 MAC을 변경하면, MAB 인증을 통과할 수 있습니다.

따라서 MAB는:
- 802.1X를 사용할 수 없을 때만 사용
- 프로파일링과 함께 사용 권장
- 중요 자원에 대한 접근은 추가 제어 필요

# 9. 802.1X 고급 기능

## Multi-Auth (다중 인증)

하나의 포트에 여러 장비가 연결되는 경우(예: IP폰 뒤에 PC 연결) 각 장비를 개별 인증합니다.

```bash
Switch(config-if)# authentication host-mode multi-auth
```

## Multi-Domain Authentication (MDA)

Voice VLAN과 Data VLAN을 분리해서, IP폰과 PC를 각각 다른 도메인에서 인증합니다.

```bash
Switch(config-if)# authentication host-mode multi-domain
```

## Critical VLAN

ISE 서버에 연결할 수 없을 때 장비를 특정 VLAN에 배치합니다.

```bash
Switch(config-if)# authentication event server dead action authorize vlan 100
Switch(config-if)# authentication event server alive action reinitialize
```

## Flexible Authentication (FlexAuth)

인증 방식의 순서와 우선순위를 유연하게 설정합니다.

```bash
! 802.1X 먼저 시도, 실패하면 MAB
Switch(config-if)# authentication order dot1x mab

! 802.1X가 성공하면 MAB 결과 무시
Switch(config-if)# authentication priority dot1x mab
```

# 10. 정리하며

이번 장에서 배운 802.1X의 핵심을 정리합니다.

**구성 요소:**
- **Supplicant**: 네트워크에 접속하려는 클라이언트 (PC, 스마트폰)
- **Authenticator**: 중개 역할 (스위치, WLC)
- **Authentication Server**: 인증 수행 (ISE)

**프로토콜:**
- **EAPoL**: Supplicant ↔ Authenticator (L2)
- **RADIUS**: Authenticator ↔ Auth Server (L3)

**주요 EAP 메서드:**
- **EAP-TLS**: 클라이언트+서버 인증서, 최고 보안
- **EAP-PEAP**: 서버 인증서만, 내부 MSCHAPv2
- **EAP-FAST**: 인증서 없이 빠른 인증

**MAB:**
- 802.1X 미지원 장비용
- MAC 주소로 인증
- 보안 수준 낮음, 스푸핑 위험

> 문제 | 프린터처럼 802.1X Supplicant가 없는 장비를 인증하는 방식은?

정답은 → **MAB(MAC Authentication Bypass)** 입니다.
