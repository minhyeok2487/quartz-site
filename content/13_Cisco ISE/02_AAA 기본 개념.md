# 1. AAA란 무엇인가?

네트워크 보안에서 가장 기본이 되는 개념이 바로 **AAA** 입니다. 처음 들으면 "트리플 A? 배터리 이름인가?" 싶으실 수 있는데요, 전혀 다릅니다.

**AAA** 는 다음 세 가지의 약자입니다:

- **A**uthentication (인증) - "너 누구야?"
- **A**uthorization (인가) - "너 뭐 할 수 있어?"
- **A**ccounting (계정 관리) - "너 뭐 했어?"

이 세 가지가 네트워크 접근 제어의 핵심입니다. 회사 건물에 비유하면 이해가 쉽습니다.

```
┌─────────────────────────────────────────────────────────┐
│                    회사 건물 출입 비유                     │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  1. Authentication (인증)                               │
│     → 사원증을 찍어서 "김철수 사원"임을 확인              │
│                                                         │
│  2. Authorization (인가)                                │
│     → 김철수는 3층 개발팀 출입 가능, 5층 서버실 출입 불가   │
│                                                         │
│  3. Accounting (계정 관리)                              │
│     → 김철수가 09:00에 출근, 18:30에 퇴근했다고 기록       │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

네트워크에서도 똑같습니다. 사용자가 네트워크에 접속하려고 하면:

1. **인증**: 이 사람이 정말 "홍길동"인지 확인 (ID/Password, 인증서 등)
2. **인가**: 홍길동에게 어떤 네트워크 자원에 접근할 권한을 줄지 결정
3. **계정 관리**: 홍길동이 언제 접속해서 무엇을 했는지 기록

# 2. Authentication (인증)

## 인증의 개념

**인증(Authentication)** 은 "사용자가 주장하는 신원이 실제로 맞는지 확인하는 과정"입니다.

여러분이 은행 앱에 로그인할 때를 생각해 보세요. ID와 비밀번호를 입력하죠? 은행은 이 정보가 맞는지 확인해서 "아, 이 사람이 정말 김철수 고객이구나"라고 판단합니다. 이게 바로 인증입니다.

## 인증 요소 (Authentication Factors)

인증에는 크게 세 가지 요소가 있습니다.

| 요소 | 설명 | 예시 |
|------|------|------|
| **지식 기반** (Something you know) | 본인만 아는 정보 | 비밀번호, PIN, 보안 질문 |
| **소유 기반** (Something you have) | 본인만 가진 것 | OTP 토큰, 스마트카드, 휴대폰 |
| **생체 기반** (Something you are) | 본인의 신체적 특징 | 지문, 홍채, 얼굴 인식 |

> 문제 | "비밀번호 + OTP"를 함께 사용하는 인증 방식을 무엇이라고 할까요?

정답은 → **MFA(Multi-Factor Authentication, 다중 인증)** 또는 **2FA(Two-Factor Authentication, 이중 인증)** 입니다.

요즘은 비밀번호만으로는 보안이 충분하지 않습니다. 비밀번호가 유출되면 끝이니까요. 그래서 두 가지 이상의 인증 요소를 조합하는 **다중 인증(MFA)** 이 표준이 되어가고 있습니다.

## 인증 방식의 종류

네트워크에서 사용하는 주요 인증 방식을 살펴보겠습니다.

### 1. 사용자명/비밀번호 (Username/Password)

가장 기본적인 방식입니다. 하지만 단독으로 사용하면 보안에 취약합니다.

```
사용자: admin
비밀번호: ********

[인증 성공] 또는 [인증 실패]
```

### 2. 인증서 기반 (Certificate-based)

**디지털 인증서(Digital Certificate)** 를 사용합니다. 인증서 안에는 공개키, 발급자 정보, 유효기간 등이 포함되어 있습니다.

**장점:**
- 비밀번호보다 안전 (유출 위험 낮음)
- 자동화된 인증 가능

**단점:**
- 인증서 관리(발급, 갱신, 폐기)가 복잡
- PKI(Public Key Infrastructure) 인프라 필요

### 3. EAP (Extensible Authentication Protocol)

802.1X 인증에서 사용하는 프레임워크입니다. 다양한 인증 방식을 지원합니다.

| EAP 유형 | 특징 |
|---------|------|
| **EAP-TLS** | 인증서 기반, 가장 안전, 클라이언트 인증서 필요 |
| **EAP-PEAP** | 서버 인증서만 필요, 내부에서 MSCHAPv2 등 사용 |
| **EAP-TTLS** | PEAP과 유사, 더 유연한 내부 인증 방식 지원 |
| **EAP-FAST** | Cisco 개발, 인증서 없이 빠른 인증 |

(EAP에 대해서는 802.1X 장에서 더 자세히 다루겠습니다)

### 4. MAC 인증 (MAB - MAC Authentication Bypass)

MAC 주소를 사용한 인증입니다. 802.1X를 지원하지 않는 장비(프린터, IP폰, IoT 장비 등)에 사용합니다.

**주의:** MAC 주소는 쉽게 위조(스푸핑)할 수 있으므로, 보안 수준이 낮습니다. 다른 인증 방식을 사용할 수 없을 때만 사용해야 합니다.

# 3. Authorization (인가)

## 인가의 개념

**인가(Authorization)** 는 "인증된 사용자에게 어떤 권한을 부여할지 결정하는 과정"입니다.

인증과 인가를 혼동하는 분들이 많은데, 확실히 구분해야 합니다.

- **인증**: "너 누구야?" → 신원 확인
- **인가**: "너 뭐 할 수 있어?" → 권한 부여

비유하자면, 호텔에 체크인할 때 신분증을 보여주는 것이 **인증** 이고, 방 카드키를 받아서 특정 층과 시설에 접근할 수 있게 되는 것이 **인가** 입니다.

## 인가 결과의 유형

ISE에서 인가 결과로 적용할 수 있는 것들을 살펴보겠습니다.

### 1. VLAN 할당

사용자나 장비 유형에 따라 다른 VLAN에 배치합니다.

```
┌─────────────────────────────────────────────────────────┐
│                    VLAN 할당 예시                        │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  직원 PC (도메인 가입) → VLAN 10 (업무망)               │
│  게스트 장비         → VLAN 100 (게스트망)              │
│  BYOD 장비          → VLAN 50 (제한된 접근)             │
│  프린터/IoT         → VLAN 200 (IoT망)                 │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

### 2. ACL (Access Control List) 적용

특정 트래픽만 허용하거나 차단하는 ACL을 적용합니다.

**dACL (Downloadable ACL)** 이라고 해서, ISE에서 스위치로 ACL을 동적으로 내려보낼 수 있습니다.

```
! ISE에서 내려보내는 dACL 예시
permit tcp any host 10.1.1.100 eq 443    ! 웹 서버 접근 허용
permit udp any any eq 53                  ! DNS 허용
deny ip any any                           ! 나머지 차단
```

### 3. SGT (Security Group Tag) 할당

Cisco **TrustSec** 환경에서 사용합니다. 트래픽에 태그를 붙여서 정책을 적용합니다.

```
직원 그룹 → SGT: Employees (10)
서버 그룹 → SGT: Servers (20)

정책: Employees(10) → Servers(20) : 허용
```

### 4. URL 리다이렉션

사용자를 특정 웹 페이지로 리다이렉트합니다. 주로 다음 상황에서 사용합니다:
- 게스트 포털 (Guest Portal)
- BYOD 온보딩 (Device Registration)
- 약관 동의 (Acceptable Use Policy)

# 4. Accounting (계정 관리)

## 계정 관리의 개념

**Accounting(계정 관리)** 은 "사용자가 무엇을 했는지 기록하는 과정"입니다.

보안 감사(Audit)를 받아 본 분이라면 아실 겁니다. 감사관이 제일 먼저 요청하는 것 중 하나가 "접속 기록"입니다.

- 누가 언제 네트워크에 접속했나요?
- 얼마나 오래 접속해 있었나요?
- 어떤 자원에 접근했나요?

이런 질문에 답하려면 Accounting이 필수입니다.

## Accounting 기록 내용

일반적으로 다음 정보들이 기록됩니다:

| 항목 | 설명 |
|------|------|
| **사용자 ID** | 누가 접속했는지 |
| **접속 시작 시간** | 언제 접속했는지 |
| **접속 종료 시간** | 언제 접속을 끊었는지 |
| **세션 지속 시간** | 얼마나 오래 접속했는지 |
| **NAS IP** | 어떤 장비를 통해 접속했는지 |
| **할당된 IP** | 어떤 IP를 받았는지 |
| **송수신 바이트** | 얼마나 많은 데이터를 주고받았는지 |
| **종료 사유** | 왜 접속이 끊어졌는지 |

## RADIUS Accounting 메시지

RADIUS 프로토콜에서는 다음과 같은 Accounting 메시지를 사용합니다:

```
┌─────────────────────────────────────────────────────────┐
│              RADIUS Accounting 흐름                     │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  [사용자 접속 시작]                                      │
│       │                                                 │
│       ▼                                                 │
│  NAD ──── Accounting-Start ────► ISE                   │
│       │   (세션 시작 알림)                               │
│       │                                                 │
│       │   ... 접속 중 ...                               │
│       │                                                 │
│       ▼                                                 │
│  NAD ──── Interim-Update ──────► ISE                   │
│       │   (주기적 업데이트, 선택)                         │
│       │                                                 │
│       │   ... 접속 중 ...                               │
│       │                                                 │
│       ▼                                                 │
│  [사용자 접속 종료]                                      │
│       │                                                 │
│       ▼                                                 │
│  NAD ──── Accounting-Stop ─────► ISE                   │
│           (세션 종료 알림)                               │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

# 5. AAA 적용 시나리오

실제 환경에서 AAA가 어떻게 동작하는지 시나리오로 살펴보겠습니다.

## 시나리오: 직원의 유선 네트워크 접속

```
1. 홍길동이 PC를 스위치 포트에 연결
2. 스위치가 802.1X 인증 요청
3. PC에서 ID/Password 입력
4. 스위치가 ISE로 RADIUS 인증 요청 전송

[Authentication - 인증]
5. ISE가 Active Directory에 사용자 정보 조회
6. AD에서 "홍길동 - 개발팀 - 유효한 계정" 확인
7. ISE → 스위치: "인증 성공"

[Authorization - 인가]
8. ISE가 정책 확인: "개발팀 직원 → VLAN 10, dACL 적용"
9. ISE → 스위치: "VLAN 10 할당, dACL 적용해"
10. 스위치가 해당 포트에 VLAN 10 설정, dACL 적용

[Accounting - 계정 관리]
11. 스위치 → ISE: "Accounting-Start" (홍길동 접속 시작 기록)
12. ... 업무 중 ...
13. 홍길동이 PC 종료
14. 스위치 → ISE: "Accounting-Stop" (홍길동 접속 종료 기록)
```

## 시나리오: 인증 실패 시

```
1. 악의적인 사용자가 잘못된 계정으로 접속 시도
2. 스위치가 ISE로 인증 요청

[Authentication 실패]
3. ISE가 AD 조회 → 계정 없음 또는 비밀번호 틀림
4. ISE → 스위치: "인증 실패"
5. 스위치가 해당 포트 차단 또는 Guest VLAN으로 이동

[Accounting]
6. ISE에 "인증 실패" 로그 기록 (포렌식 분석용)
```

# 6. AAA 프로토콜 미리보기

AAA를 구현하는 프로토콜로는 **[[04_RADIUS와 TACACS+|RADIUS]]** 와 **TACACS+** 가 있습니다. 간단히 비교만 해두고, 자세한 내용은 별도 장에서 다루겠습니다.

| 항목 | RADIUS | TACACS+ |
|------|--------|---------|
| **개발** | IETF 표준 | Cisco 독자 개발 |
| **전송 프로토콜** | UDP (1812/1813) | TCP (49) |
| **암호화** | 비밀번호만 암호화 | 전체 패킷 암호화 |
| **AAA 분리** | 인증+인가 결합 | 인증, 인가, 계정 분리 |
| **주요 용도** | 네트워크 접근 제어 | 장비 관리자 접근 제어 |

**일반적인 사용 가이드:**
- 사용자/장비의 네트워크 접근 → **RADIUS**
- 네트워크 관리자의 장비 접근 → **TACACS+**

# 7. 정리하며

이번 장에서 배운 AAA의 핵심을 정리합니다.

| 구성 요소 | 질문 | 역할 |
|----------|------|------|
| **Authentication** | 너 누구야? | 신원 확인 |
| **Authorization** | 너 뭐 할 수 있어? | 권한 부여 |
| **Accounting** | 너 뭐 했어? | 활동 기록 |

**인증 요소 3가지:**
- 지식 기반 (비밀번호)
- 소유 기반 (OTP, 스마트카드)
- 생체 기반 (지문, 얼굴)

**인가 결과:**
- VLAN 할당
- ACL/dACL 적용
- SGT 할당
- URL 리다이렉션

> 문제 | 다음 중 Authorization의 예가 아닌 것은?
> A) 사용자에게 VLAN 10을 할당
> B) 사용자의 비밀번호를 확인
> C) 특정 서버 접근만 허용하는 ACL 적용
> D) 게스트 포털로 리다이렉트

정답은 → B입니다. 비밀번호 확인은 **Authentication(인증)** 입니다.

**다음 장에서는 802.1X 인증에 대해 배우겠습니다.**

AAA의 개념을 이해했으니, 이제 실제로 네트워크에서 어떻게 인증이 이루어지는지 알아볼 차례입니다. 802.1X는 유선/무선 네트워크 인증의 표준 프로토콜입니다.

**다음 장 주요 내용:**
- 802.1X의 구성 요소 (Supplicant, Authenticator, Authentication Server)
- EAP 프로토콜 상세
- 802.1X 인증 흐름
- 스위치에서의 802.1X 설정
