# 이전 장 요약

이전 장에서는 **네트워크의 정의와 필요성**에 대해 배웠습니다:
- **네트워크의 정의**: 두 대 이상의 장치가 연결되어 정보와 자원을 공유하는 시스템
- **네트워크의 필요성**: 자원 공유, 데이터 교환, 협업, 비용 절감
- **네트워크의 역사**: ARPANET에서 시작하여 현대 인터넷까지의 발전 과정
- **실제 사례**: 2018년 KT 아현지사 화재 사건을 통해 본 네트워크의 중요성

이제 네트워크를 **어떤 형태로 연결할 것인가**, 즉 **네트워크 토폴로지**에 대해 알아봅시다.

---

# 1. 네트워크 토폴로지란? - 연결의 모양이 중요하다

여러분이 새로운 사무실에 컴퓨터 10대를 설치해야 한다고 상상해 보세요. 각 컴퓨터를 네트워크로 연결해야 하는데, 어떻게 연결할 건가요? 모든 컴퓨터를 하나의 중앙 장비에 연결할까요? 아니면 컴퓨터들을 일렬로 연결할까요? 각 컴퓨터를 모든 다른 컴퓨터에 연결할까요?

이렇게 **어떤 방식으로 연결하느냐**를 결정하는 것이 바로 네트워크 토폴로지입니다. 토폴로지(Topology)는 그리스어로 '장소'를 뜻하는 'topos'와 '학문'을 뜻하는 'logos'가 합쳐진 말로, 원래는 수학에서 도형의 위치 관계를 연구하는 학문을 의미합니다. 네트워크에서는 **장치들이 어떤 형태로 연결되어 있는지**를 의미하죠.

같은 10대의 컴퓨터라도 어떻게 연결하느냐에 따라 성능, 비용, 안정성이 완전히 달라집니다. 마치 같은 재료로 집을 짓더라도 설계에 따라 완전히 다른 집이 나오는 것과 같습니다.

## 토폴로지를 왜 알아야 할까?

"그냥 다 연결되면 되는 거 아니야?"라고 생각할 수도 있습니다. 하지만 네트워크 토폴로지는 여러 면에서 중요합니다.

**비용이 달라집니다**

어떤 토폴로지는 케이블이 많이 필요하고, 어떤 토폴로지는 적게 필요합니다. 10대의 컴퓨터를 연결하는데 케이블 10개가 필요한 방식이 있고, 45개가 필요한 방식이 있다면? 비용 차이가 엄청나겠죠.

**안정성이 달라집니다**

어떤 토폴로지는 하나의 케이블이 끊어지면 전체 네트워크가 마비됩니다. 반면 어떤 토폴로지는 여러 개의 케이블이 끊어져도 계속 작동합니다. 은행이나 병원처럼 절대 멈춰서는 안 되는 곳에서는 이것이 생사의 문제입니다.

**성능이 달라집니다**

어떤 토폴로지는 데이터가 여러 장비를 거쳐야 하고, 어떤 토폴로지는 직접 연결됩니다. 당연히 속도가 다를 수밖에 없겠죠.

**확장성이 달라집니다**

처음에는 10대였던 컴퓨터가 회사가 커지면서 50대, 100대로 늘어날 수 있습니다. 어떤 토폴로지는 쉽게 확장할 수 있고, 어떤 토폴로지는 처음부터 다시 설계해야 합니다.

## 물리적 토폴로지 vs 논리적 토폴로지

토폴로지에는 두 가지 관점이 있습니다.

**물리적 토폴로지 (Physical Topology)**

실제로 케이블이 어떻게 연결되어 있는지를 나타냅니다. 여러분이 사무실 천장을 열어보면 케이블들이 어떻게 연결되어 있는지 볼 수 있겠죠? 그것이 물리적 토폴로지입니다.

**논리적 토폴로지 (Logical Topology)**

데이터가 실제로 어떤 경로로 흐르는지를 나타냅니다. 물리적으로는 모든 컴퓨터가 중앙 스위치에 연결되어 있어도, 데이터가 마치 링 형태로 순환하는 것처럼 동작할 수 있습니다.

예를 들어볼까요? 여러분 회사 사무실의 모든 컴퓨터가 물리적으로는 스위치에 연결되어 있습니다(Star 토폴로지). 하지만 실제로 데이터는 특정 순서대로 컴퓨터들을 거쳐 갑니다(Ring 토폴로지). 이것이 물리적 토폴로지와 논리적 토폴로지가 다른 경우입니다.

이번 장에서는 주로 물리적 토폴로지를 다루지만, 논리적 토폴로지도 함께 이해하는 것이 중요합니다.

# 2. 주요 네트워크 토폴로지 종류

네트워크 토폴로지는 크게 다섯 가지 기본 형태가 있습니다. 각각의 장단점을 하나씩 살펴보겠습니다.

## Bus 토폴로지 - 하나의 선에 모두 연결

**구조**

Bus 토폴로지는 가장 단순한 형태입니다. 하나의 긴 케이블(버스)에 모든 컴퓨터를 연결하는 방식이죠. 마치 시내버스 노선처럼 하나의 선 위에 여러 정류장(컴퓨터)이 있는 것과 같습니다.

```
터미네이터                                            터미네이터
    [T]─────┬─────┬─────┬─────┬─────[T]
            │     │     │     │     │
           PC1   PC2   PC3   PC4   PC5

        ← Backbone (백본 케이블) →
```

중앙의 긴 케이블을 **백본(Backbone)** 또는 **트렁크(Trunk)** 라고 부릅니다. 각 컴퓨터는 이 백본에 T자 형태의 커넥터로 연결됩니다. 그리고 백본의 양 끝에는 **터미네이터(Terminator)** 라는 것을 달아야 합니다. 터미네이터는 신호가 케이블 끝에서 반사되어 돌아오는 것을 막아주는 장치입니다.

**동작 원리**

한 컴퓨터가 데이터를 보내면, 그 신호는 백본을 타고 양방향으로 퍼져나갑니다. 백본에 연결된 모든 컴퓨터가 이 신호를 받습니다. 각 컴퓨터는 신호를 받아서 "이게 나한테 온 거야?"를 확인하고, 자기한테 온 게 아니면 무시합니다.

이 방식의 문제는 한 번에 한 컴퓨터만 데이터를 보낼 수 있다는 점입니다. 두 컴퓨터가 동시에 데이터를 보내면 **충돌(Collision)** 이 발생합니다. 그래서 CSMA/CD(Carrier Sense Multiple Access with Collision Detection)라는 프로토콜을 사용해서 충돌을 감지하고 피합니다.

**장점**

- **설치가 간단합니다**: 하나의 긴 케이블만 깔면 됩니다.
- **비용이 저렴합니다**: 케이블이 적게 필요하고, 중앙 장비(스위치나 허브)가 필요 없습니다.
- **소규모 네트워크에 적합합니다**: 컴퓨터가 몇 대 안 되면 충분히 쓸 만합니다.

**단점**

- **한 곳이 고장 나면 전체가 마비됩니다**: 백본 케이블이 끊어지면 모든 통신이 중단됩니다. 터미네이터가 빠져도 마찬가지입니다.
- **성능이 떨어집니다**: 컴퓨터가 많아질수록 충돌이 자주 발생해서 속도가 느려집니다.
- **문제 해결이 어렵습니다**: 어디선가 문제가 생겼는데 정확히 어디인지 찾기 힘듭니다.
- **확장이 어렵습니다**: 컴퓨터를 추가하려면 백본을 건드려야 하는데, 그러면 네트워크 전체가 잠시 멈춥니다.

**사용 사례**

Bus 토폴로지는 1980년대와 1990년대 초반에 많이 사용되었습니다. 10Base2 (Thin Ethernet)이나 10Base5 (Thick Ethernet) 같은 초기 이더넷이 버스 토폴로지를 사용했죠. 하지만 지금은 거의 사용하지 않습니다. 안정성이 너무 낮고, 더 나은 대안들이 있기 때문입니다.

다만 자동차 내부 네트워크인 CAN(Controller Area Network) 버스처럼 특수한 환경에서는 아직도 버스 토폴로지를 사용합니다.

## Star 토폴로지 - 중앙에서 모든 것을 관리

**구조**

Star 토폴로지는 현재 가장 널리 사용되는 형태입니다. 이름 그대로 별(Star) 모양을 하고 있죠. 중앙에 **중앙 장비**(Hub, Switch, 또는 Router)가 있고, 모든 컴퓨터가 이 중앙 장비에 개별 케이블로 연결됩니다.

```
        PC1
         │
         │
    PC2──┼──PC3
         │
      [Switch]
         │
    PC4──┼──PC5
         │
         │
        PC6
```

여러분이 지금 사용하고 있는 집이나 사무실 네트워크가 바로 이 Star 토폴로지일 가능성이 높습니다. 각 컴퓨터나 노트북이 공유기(Router)나 스위치에 연결되어 있을 거예요.

**동작 원리**

컴퓨터 A가 컴퓨터 B에게 데이터를 보내려고 합니다. 이때 데이터는 먼저 중앙 장비로 갑니다. 중앙 장비는 이 데이터를 받아서 "이 데이터는 B한테 가는 거구나"라고 확인하고, B에게만 전달합니다.

이것이 Bus 토폴로지와의 큰 차이점입니다. Bus에서는 모든 컴퓨터가 신호를 받았지만, Star에서는 중앙 장비가 필요한 컴퓨터에게만 데이터를 전달합니다. 훨씬 효율적이죠.

**장점**

- **관리가 쉽습니다**: 모든 연결이 중앙 장비로 모이기 때문에 문제가 생기면 찾기 쉽습니다. 컴퓨터 5번에 문제가 있다? 5번 케이블만 확인하면 됩니다.
- **확장이 용이합니다**: 새 컴퓨터를 추가하고 싶으면? 중앙 장비에 케이블 하나만 연결하면 됩니다. 기존 네트워크를 건드릴 필요가 없습니다.
- **한 컴퓨터의 문제가 전체에 영향을 주지 않습니다**: 컴퓨터 하나가 고장 나거나 케이블이 끊어져도 다른 컴퓨터들은 계속 작동합니다.
- **성능이 좋습니다**: 중앙 장비가 Switch라면, 여러 쌍의 컴퓨터가 동시에 통신할 수 있습니다.

**단점**

- **중앙 장비에 의존적입니다**: 중앙의 스위치나 허브가 고장 나면 전체 네트워크가 마비됩니다. 이것이 가장 큰 약점입니다.
- **케이블 비용이 높습니다**: 각 컴퓨터마다 중앙까지 개별 케이블이 필요합니다. 10대면 케이블 10개, 100대면 100개가 필요하죠.
- **중앙 장비의 성능이 중요합니다**: 모든 트래픽이 중앙 장비를 거치기 때문에, 중앙 장비가 병목이 될 수 있습니다.

**사용 사례**

Star 토폴로지는 현대 네트워크의 표준입니다. 거의 모든 LAN(Local Area Network)이 이 형태를 사용합니다.

- **가정용 네트워크**: 여러분 집의 인터넷 공유기가 중앙 장비 역할을 합니다.
- **사무실 네트워크**: 각 층에 스위치를 두고, 모든 컴퓨터를 스위치에 연결합니다.
- **학교, 도서관**: 중앙 서버실에 메인 스위치를 두고, 각 교실이나 자리의 컴퓨터들을 연결합니다.

## Ring 토폴로지 - 끝없이 순환하는 고리

**구조**

Ring 토폴로지는 이름처럼 고리(Ring) 모양입니다. 각 컴퓨터가 양옆의 컴퓨터와 연결되어 원형을 이룹니다. 첫 번째 컴퓨터와 마지막 컴퓨터가 연결되어 있어서 끝이 없는 고리가 만들어지죠.

```
        PC1
       ↗   ↘
    PC5      PC2
     ↑        ↓
    PC4  ←  PC3

   데이터 흐름: →
```

Bus 토폴로지와 비슷해 보이지만, 중요한 차이가 있습니다. Bus는 양 끝이 있지만, Ring은 끝이 없습니다. 데이터가 계속 순환할 수 있다는 뜻이죠.

**동작 원리**

컴퓨터 A가 컴퓨터 D에게 데이터를 보낸다고 가정해 봅시다. 데이터는 한 방향으로만 움직입니다(시계 방향이라고 하죠). A → B → C → D 순서로 데이터가 전달됩니다.

각 컴퓨터는 데이터를 받으면 "이게 나한테 온 거야?"를 확인합니다. 자기 것이 아니면 다음 컴퓨터로 전달합니다. 마치 릴레이 경주처럼 바통을 넘기는 것과 같습니다.

데이터가 목적지에 도착하면 어떻게 될까요? 계속 순환하면 네트워크가 꽉 차버리겠죠. 그래서 목적지 컴퓨터가 데이터를 받으면, 데이터를 고리에서 제거하거나 다시 출발지로 되돌려 보냅니다. "잘 받았어!"라는 확인 신호로요.

**토큰 링 (Token Ring)**

실제 Ring 토폴로지에서는 **토큰(Token)** 이라는 특별한 신호를 사용합니다. 토큰은 고리를 계속 돌아다니는 일종의 허가증입니다. 데이터를 보내려는 컴퓨터는 먼저 토큰을 잡아야 합니다.

토큰을 잡은 컴퓨터가 데이터를 보내고, 다 보내면 토큰을 다시 놓습니다. 그러면 다음 컴퓨터가 토큰을 잡을 수 있죠. 이 방식 덕분에 Bus처럼 충돌이 발생하지 않습니다.

**장점**

- **공평합니다**: 토큰을 사용하면 모든 컴퓨터가 순서대로 데이터를 보낼 기회를 얻습니다.
- **충돌이 없습니다**: 한 번에 한 컴퓨터만 토큰을 가지므로 충돌이 발생하지 않습니다.
- **성능이 예측 가능합니다**: 네트워크가 바쁠 때도 각 컴퓨터가 언제 데이터를 보낼 수 있는지 대략 알 수 있습니다.

**단점**

- **한 곳이 고장 나면 전체가 마비됩니다**: 고리의 한 부분이 끊어지면 전체 네트워크가 작동하지 않습니다.
- **문제 해결이 어렵습니다**: 어디선가 문제가 생겼을 때 정확한 위치를 찾기 힘듭니다.
- **확장과 재구성이 어렵습니다**: 컴퓨터를 추가하거나 제거하려면 고리를 끊어야 하는데, 그러면 네트워크 전체가 멈춥니다.
- **지연 시간이 증가합니다**: 데이터가 여러 컴퓨터를 거쳐야 하므로, 컴퓨터가 많을수록 느려집니다.

**사용 사례**

Ring 토폴로지는 1980년대와 1990년대에 IBM의 Token Ring 네트워크로 인기를 끌었습니다. 당시에는 Ethernet(Bus)과 경쟁하는 기술이었죠.

하지만 지금은 거의 사용하지 않습니다. Star 토폴로지가 더 편리하고 관리하기 쉽기 때문입니다.

다만 광통신 네트워크에서는 **SONET/SDH Ring**이라는 형태로 아직 사용됩니다. 통신사의 백본 네트워크가 이런 방식을 쓰는 경우가 많습니다. 이 경우에는 이중 링(Dual Ring)을 사용해서 한쪽이 끊어져도 다른 쪽으로 우회할 수 있게 만듭니다.

## Mesh 토폴로지 - 모든 것이 모든 것과 연결

**구조**

Mesh는 '그물망'이라는 뜻입니다. 그 이름처럼 Mesh 토폴로지에서는 여러 컴퓨터가 그물처럼 서로 연결되어 있습니다.

Mesh 토폴로지에는 두 가지 유형이 있습니다:

**Full Mesh (완전 연결형)**

모든 컴퓨터가 다른 모든 컴퓨터와 직접 연결됩니다. 컴퓨터가 5대 있다면, 각 컴퓨터는 4개의 연결을 가집니다. 전체적으로 필요한 연결 수는 n×(n-1)/2개입니다. 5대면 10개, 10대면 45개, 100대면 4,950개의 연결이 필요합니다!

```
Full Mesh (모두 연결)

    PC1────PC2
    │ ╲  ╱ │
    │  ╲╱  │
    │  ╱╲  │
    │ ╱  ╲ │
    PC3────PC4
```

**Partial Mesh (부분 연결형)**

모든 컴퓨터가 연결되는 것은 아니고, 중요한 경로만 여러 개 연결됩니다. Full Mesh의 비용 문제를 해결하면서도 중복성을 확보하는 방식입니다.

```
Partial Mesh (일부만 연결)

    PC1────PC2
     │      │
     │      │
    PC3────PC4
```

**동작 원리**

컴퓨터 A가 컴퓨터 D에게 데이터를 보낸다고 해봅시다. Full Mesh라면 A와 D가 직접 연결되어 있으므로 바로 전달됩니다. 만약 그 연결에 문제가 생기면? A는 B나 C를 거쳐서 D에게 데이터를 보낼 수 있습니다.

이것이 Mesh의 핵심입니다. **여러 경로가 있어서 하나가 막혀도 다른 길로 갈 수 있다**는 점이죠. 마치 도시의 도로망처럼요. 한 길이 막혀도 다른 길로 우회할 수 있습니다.

**장점**

- **매우 안정적입니다**: 여러 연결이 끊어져도 네트워크는 계속 작동합니다. 이것이 가장 큰 장점입니다.
- **성능이 우수합니다**: Full Mesh에서는 모든 컴퓨터가 직접 연결되어 있어 최단 경로로 통신합니다.
- **장애 대응이 뛰어납니다**: 한 경로에 문제가 생기면 자동으로 다른 경로를 사용합니다.
- **병목 현상이 적습니다**: 여러 경로로 트래픽이 분산되기 때문입니다.

**단점**

- **비용이 매우 높습니다**: 케이블과 네트워크 인터페이스가 엄청나게 많이 필요합니다.
- **설치와 관리가 복잡합니다**: 케이블이 너무 많아서 설치하기도 어렵고, 문제가 생겼을 때 관리하기도 어렵습니다.
- **확장이 어렵습니다**: 컴퓨터를 하나 추가하면 모든 다른 컴퓨터와 연결해야 합니다(Full Mesh의 경우).

**사용 사례**

Full Mesh는 비용 때문에 소수의 핵심 장비를 연결할 때만 사용합니다:

- **인터넷 백본**: 대형 통신사의 핵심 라우터들은 Full Mesh로 연결되어 있습니다. 절대 멈춰서는 안 되니까요.
- **데이터센터 코어**: 대규모 데이터센터의 핵심 스위치들도 Full Mesh로 연결합니다.
- **무선 Mesh 네트워크**: 요즘 유행하는 메시 Wi-Fi는 여러 AP(액세스 포인트)가 서로 연결되어 넓은 영역을 커버합니다.

Partial Mesh는 더 널리 사용됩니다:

- **기업 WAN**: 본사와 지사들을 연결할 때, 중요한 지사는 여러 경로로 연결하고 작은 지사는 하나만 연결합니다.
- **클라우드 네트워크**: 여러 데이터센터를 연결할 때 Partial Mesh를 자주 사용합니다.

## Hybrid 토폴로지 - 현실에서 만나는 조합

**구조**

실제 네트워크에서는 하나의 토폴로지만 사용하는 경우가 거의 없습니다. 대부분은 여러 토폴로지를 조합한 **Hybrid 토폴로지**를 사용합니다.

예를 들어볼까요?

한 건물의 각 층에는 Star 토폴로지로 컴퓨터들이 스위치에 연결되어 있습니다. 그리고 각 층의 스위치들은 건물의 메인 스위치에 연결됩니다(이것도 Star). 그런데 본사와 지사 사이는 Mesh로 연결되어 있습니다. 이것이 바로 Hybrid입니다.

**Star-Bus**

여러 Star 네트워크를 하나의 Bus 백본으로 연결하는 방식입니다. 각 부서가 자체 Star 네트워크를 가지고 있고, 부서들은 백본으로 연결됩니다.

**Hierarchical (Tree) 토폴로지**

Star 토폴로지를 계층적으로 쌓아올린 형태입니다. 마치 나무(Tree)처럼 보이죠. 가장 위에 루트 스위치가 있고, 그 아래에 여러 스위치가 연결되고, 또 그 아래에 컴퓨터들이 연결됩니다.

```
Hierarchical (Tree) 토폴로지

        [Core Switch]        ← Core Layer
            │
     ┌──────┼──────┐
     │      │      │
  [SW1]  [SW2]  [SW3]        ← Distribution Layer
     │      │      │
  ┌──┼──┐ ┌┼┐  ┌──┼──┐
  │  │  │ ││ │ │  │  │
 PC PC PC PC PC PC PC PC     ← Access Layer
```

이것이 현대 기업 네트워크의 전형적인 모습입니다:
- **Core Layer**: 최상위, 빠른 스위칭
- **Distribution Layer**: 중간, 라우팅과 정책 적용
- **Access Layer**: 최하위, 실제 컴퓨터 연결

**장점**

- **유연합니다**: 각 부분에 가장 적합한 토폴로지를 선택할 수 있습니다.
- **확장이 쉽습니다**: 새로운 부분을 추가하기 쉽습니다.
- **문제를 격리할 수 있습니다**: 한 부분의 문제가 전체로 번지지 않게 만들 수 있습니다.
- **성능과 비용의 균형**: 중요한 부분은 비싸지만 안정적인 방식으로, 덜 중요한 부분은 저렴한 방식으로 구성할 수 있습니다.

**단점**

- **설계가 복잡합니다**: 전체 구조를 잘 이해하고 설계해야 합니다.
- **관리가 어렵습니다**: 여러 토폴로지를 동시에 관리해야 합니다.
- **문제 해결이 복잡할 수 있습니다**: 어디서 문제가 생겼는지 찾기 위해 여러 계층을 확인해야 합니다.

**사용 사례**

사실상 모든 중대형 네트워크가 Hybrid입니다:

- **대학 캠퍼스**: 각 건물은 Star, 건물들 사이는 Mesh 또는 Ring
- **기업 네트워크**: 3계층 계층적 구조(Core-Distribution-Access)
- **데이터센터**: Spine-Leaf 아키텍처(Partial Mesh)

# 3. 토폴로지 선택 가이드

자, 이제 각 토폴로지를 다 살펴봤습니다. 그럼 어떤 상황에서 어떤 토폴로지를 선택해야 할까요?

**작은 사무실 (5-20대)**

→ **Star 토폴로지**를 추천합니다. 스위치 하나만 있으면 되고, 관리가 쉽습니다. 비용도 적당하고요.

**중간 규모 회사 (50-500대)**

→ **Hierarchical Star (Tree)** 를 추천합니다. 층별로 스위치를 두고, 메인 스위치로 연결합니다. 확장도 쉽고 관리도 편합니다.

**미션 크리티컬 환경 (병원, 금융, 통신사)**

→ **Partial Mesh**를 추천합니다. 핵심 장비들은 여러 경로로 연결해서 절대 멈추지 않게 만듭니다. 비용이 들더라도 안정성이 최우선입니다.

**원격지 연결 (본사-지사)**

→ **Star-Mesh Hybrid**를 추천합니다. 본사는 Mesh로 안정성을 확보하고, 각 지사는 본사로 Star 연결합니다. 중요한 지사는 두 개 이상의 경로로 연결하고요.

**가정용**

→ **Star 토폴로지**면 충분합니다. 공유기 하나에 모든 기기를 연결하면 됩니다.

# 4. 마무리하며

네트워크 토폴로지는 단순히 "어떻게 연결하느냐"의 문제가 아닙니다. 비용, 성능, 안정성, 확장성 사이의 균형을 찾는 문제입니다.

- **Bus**는 간단하지만 안정성이 낮아서 지금은 거의 안 씁니다.
- **Star**는 현대 네트워크의 기본이고, 가장 보편적입니다.
- **Ring**은 특수한 경우(통신사 백본)를 제외하고는 잘 안 씁니다.
- **Mesh**는 최고의 안정성을 제공하지만 비용이 높아서 핵심 부분에만 씁니다.
- **Hybrid**는 실제 세계에서 가장 많이 보는 형태입니다.

중요한 것은 **상황에 맞는 선택**입니다. 작은 사무실에 Full Mesh를 쓰는 것도 낭비고, 대형 데이터센터에 단순 Star만 쓰는 것도 위험합니다.

네트워크를 설계할 때는 현재의 요구사항뿐만 아니라 미래의 확장도 고려해야 합니다. 처음에는 작게 시작하더라도, 나중에 쉽게 확장할 수 있는 구조를 만드는 것이 중요합니다.

**다음 장 주요 내용**:
- **PAN (Personal Area Network)**: 개인 영역 네트워크, 블루투스 이어폰부터 시작
- **LAN (Local Area Network)**: 지역 네트워크, 사무실과 집의 네트워크
- **WLAN (Wireless LAN)**: 무선 LAN, Wi-Fi의 모든 것

- **WAN (Wide Area Network)**: 광역 네트워크, 인터넷의 핵심
