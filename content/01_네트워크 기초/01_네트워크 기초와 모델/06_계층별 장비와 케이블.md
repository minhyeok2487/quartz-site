# 이전 장 요약

이전 장에서는 **캡슐화와 디캡슐화**에 대해 배웠습니다:

**캡슐화 (Encapsulation)**:
- 데이터를 보낼 때 각 OSI 계층을 거치면서 헤더 정보를 추가하는 과정
- **L7~L5**: 데이터(Data) 생성
- **L4**: TCP/UDP 헤더 추가 → 세그먼트(Segment)
- **L3**: IP 헤더 추가 → 패킷(Packet)
- **L2**: MAC 헤더/트레일러 추가 → 프레임(Frame)
- **L1**: 전기 신호로 변환 → 비트(Bit)

**디캡슐화 (Decapsulation)**:
- 데이터를 받을 때 각 계층에서 헤더를 제거하며 원래 데이터를 복원하는 과정

이제 각 OSI 계층에서 **실제로 어떤 장비가 동작하는지**, 즉 **계층별 네트워크 장비와 케이블**에 대해 알아봅시다.

---

# 1. OSI 계층별 네트워크 장비란?

네트워크를 구축하려면 다양한 장비가 필요합니다. 하지만 모든 장비가 같은 방식으로 동작하는 것은 아닙니다. 각 장비는 OSI 7계층 모델의 특정 계층에서 동작하며, 그 계층에 맞는 정보를 이해하고 처리합니다.

예를 들어, 어떤 장비는 MAC 주소만 이해하고, 어떤 장비는 IP 주소를 이해합니다. 이러한 차이를 이해하면 네트워크 구조를 설계하고 문제를 해결하는 데 큰 도움이 됩니다.

이번 장에서는 각 OSI 계층에서 동작하는 네트워크 장비들과 그 특징, 그리고 네트워크 케이블의 종류에 대해 알아보겠습니다. 또한 Collision Domain과 Broadcast Domain이라는 중요한 개념도 함께 살펴보겠습니다.

# 2. 물리 계층(L1) 장비

물리 계층(Layer 1)은 OSI 모델의 가장 하위 계층으로, 전기 신호, 광 신호, 무선 신호를 다룹니다. 이 계층에서 동작하는 장비들은 데이터의 내용을 전혀 이해하지 못하며, 단순히 신호를 증폭하거나 연결하는 역할만 합니다.

## Repeater (리피터)

**Repeater**는 가장 단순한 네트워크 장비입니다. 주요 기능은 **전기 신호를 증폭**하는 것입니다.

### 왜 리피터가 필요한가?

네트워크 케이블을 통해 전기 신호가 전송될 때, 거리가 멀어질수록 신호가 약해집니다(감쇠). 예를 들어, 이더넷 케이블(Cat5e)로 신호를 전송하면 약 100미터를 넘어가면 신호가 너무 약해져서 제대로 통신할 수 없게 됩니다.

리피터는 약해진 신호를 받아서 다시 증폭하여 보내줍니다. 마치 마라톤 중간 중간에 있는 급수대처럼, 신호에 힘을 불어넣어 더 먼 거리까지 전송할 수 있게 합니다.

### 리피터의 한계

- **MAC 주소를 모릅니다**: 물리 계층에서만 동작하므로 L2의 MAC 주소 정보를 전혀 이해하지 못합니다
- **방향 구분 없음**: 들어온 신호를 단순히 증폭해서 다른 쪽으로 보낼 뿐입니다
- **현재는 거의 사용하지 않음**: 허브나 스위치가 리피터 기능을 포함하고 있어 독립적인 리피터는 거의 사용되지 않습니다

## Hub (허브)

**Hub**는 리피터를 발전시킨 장비로, **멀티 포트 리피터**라고도 불립니다. 여러 대의 장비를 LAN에 연결할 수 있도록 해줍니다.

### 허브의 동작 방식

허브는 한 포트로 들어온 신호를 **수신 포트를 제외한 모든 포트로 복사하여 전송**합니다. 이것을 **Flooding(플로딩)** 이라고 합니다.

예를 들어, 4포트 허브에 A, B, C, D 네 대의 컴퓨터가 연결되어 있다고 가정해봅시다:
1. 컴퓨터 A가 B에게 데이터를 보내려고 허브에 신호를 전송합니다
2. 허브는 이 신호를 B, C, D 모두에게 전송합니다 (MAC 주소를 모르므로)
3. B는 자신에게 온 데이터를 받아들이고, C와 D는 자신의 것이 아니므로 버립니다

### 허브의 문제점

**1. MAC 주소를 이해하지 못함**

허브는 물리 계층에서만 동작하므로 MAC 주소를 전혀 이해하지 못합니다. 따라서 특정 장비에게만 데이터를 보낼 수 없고, 항상 모든 장비에게 전송합니다.

**2. 보안 문제**

모든 데이터가 연결된 모든 장비에 전송되므로, 네트워크 스니핑(감청)이 쉽습니다. 악의적인 사용자가 네트워크 감청 프로그램을 실행하면 같은 허브에 연결된 모든 장비의 통신 내용을 볼 수 있습니다.

**3. 대역폭 공유**

허브는 **1차선 도로**와 같습니다. 한 번에 한 장비만 데이터를 보낼 수 있으며, 동시에 여러 장비가 데이터를 보내려고 하면 충돌(Collision)이 발생합니다.

### Collision Domain (충돌 영역)

**Collision Domain**은 네트워크에서 데이터 충돌이 발생할 수 있는 영역을 의미합니다.

허브에 연결된 모든 장비는 **하나의 Collision Domain** 안에 있습니다. 이것은 다음을 의미합니다:
- 동시에 두 대 이상의 장비가 데이터를 보내면 충돌이 발생합니다
- 충돌이 발생하면 모든 장비가 전송을 멈추고 랜덤 시간 대기 후 재시도합니다
- 연결된 장비가 많을수록 충돌 확률이 높아지고 네트워크 성능이 저하됩니다

> 문제 | 10포트 허브에 10대의 컴퓨터가 연결되어 있습니다. Collision Domain은 몇 개일까요?

정답은 → 1개입니다. 허브에 연결된 모든 장비는 하나의 Collision Domain을 공유합니다. 이것이 허브의 가장 큰 단점입니다.

### 허브는 현재 사용되지 않음

위와 같은 문제점 때문에 현대 네트워크에서는 허브를 거의 사용하지 않습니다. 스위치가 허브를 완전히 대체했으며, 가격도 비슷하거나 더 저렴해졌습니다.

# 3. 데이터 링크 계층(L2) 장비

데이터 링크 계층(Layer 2) 장비는 물리 계층의 한계를 극복합니다. 이 계층에서 동작하는 장비들은 **MAC 주소**를 이해하고, 이를 이용해 지능적으로 데이터를 전송할 수 있습니다.

## Bridge (브리지)

**Bridge**는 두 개 이상의 네트워크 세그먼트를 연결하는 장비입니다. 허브와 달리 **MAC 주소를 학습하고 저장**할 수 있습니다.

### 브리지의 동작 방식

1. **MAC 주소 학습**: 각 포트로 들어오는 프레임의 출발지 MAC 주소를 학습하여 테이블에 저장합니다
2. **선택적 전송**: 목적지 MAC 주소를 확인하여, 해당 장비가 연결된 포트로만 프레임을 전송합니다
3. **Collision Domain 분리**: 브리지의 각 포트는 서로 다른 Collision Domain이 됩니다

### 브리지의 활용

브리지는 주로 **가까이 있는 네트워크 세그먼트를 연결**하는 데 사용되었습니다. 예를 들어:
- 한 층의 네트워크와 다른 층의 네트워크를 연결
- 부서별로 나뉜 네트워크를 연결

하지만 현재는 스위치가 브리지의 역할을 대체했습니다. 스위치는 사실상 **멀티 포트 브리지**라고 볼 수 있습니다.

## Switch (스위치)

**Switch**는 현대 네트워크의 핵심 장비입니다. 브리지를 발전시켜 많은 포트를 가지고, 훨씬 빠른 속도로 동작합니다.

### 스위치의 동작 방식

스위치는 **MAC Address Table**을 유지합니다:

1. **학습 단계**: 각 포트로 들어오는 프레임의 출발지 MAC 주소를 학습
2. **전송 결정**:
   - 목적지 MAC 주소가 테이블에 있으면 → 해당 포트로만 전송 (Unicast)
   - 목적지 MAC 주소가 테이블에 없으면 → 수신 포트를 제외한 모든 포트로 전송 (Unknown Unicast Flooding)
   - 브로드캐스트/멀티캐스트 → 수신 포트를 제외한 모든 포트로 전송

### 스위치의 핵심 장점: Collision Domain 분리

스위치의 **각 포트는 독립적인 Collision Domain**입니다. 이것은 허브와의 가장 큰 차이점입니다.

**허브의 경우 (1차선 도로):**
```
[PC-A] ━┓
         ┣━ [HUB] ━ 하나의 Collision Domain
[PC-B] ━┛
```
- PC-A와 PC-B가 동시에 전송하면 충돌 발생

**스위치의 경우 (각각 독립된 차선):**
```
[PC-A] ━━━ [Switch] ━━━ [PC-C]
             │
[PC-B] ━━━━━┘
```
- PC-A와 PC-B가 동시에 전송해도 충돌 없음
- 각 연결이 독립적인 Collision Domain

> 문제 | 24포트 스위치에 24대의 컴퓨터가 연결되어 있습니다. Collision Domain은 몇 개일까요?

정답은 → 24개입니다. 스위치의 각 포트는 독립적인 Collision Domain을 형성합니다. 이것이 스위치가 허브보다 훨씬 효율적인 이유입니다.

### 스위치의 장점 정리

1. **MAC 주소 기반 전송**: 특정 장비에게만 데이터 전송, 불필요한 트래픽 감소
2. **Collision Domain 분리**: 각 포트가 독립적, 충돌 없음
3. **전이중(Full-Duplex) 통신**: 동시에 송수신 가능
4. **보안**: 다른 포트의 통신을 감청하기 어려움
5. **성능**: 여러 연결이 동시에 최대 속도로 통신 가능

### 스위치의 Flooding

스위치도 다음 경우에는 모든 포트로 전송합니다:
- **Broadcast** (목적지 MAC: FF:FF:FF:FF:FF:FF)
- **Multicast** (목적지 MAC이 멀티캐스트 주소)
- **Unknown Unicast** (목적지 MAC이 MAC Address Table에 없음)

이것은 스위치의 한계이며, 이러한 트래픽을 제어하려면 L3 장비가 필요합니다.

# 4. 네트워크 계층(L3) 장비

네트워크 계층(Layer 3) 장비는 **IP 주소**를 이해하고 처리할 수 있습니다. 이 장비들은 서로 다른 네트워크 간에 데이터를 전송하는 **라우팅**을 수행합니다.

## Router (라우터)

**Router**는 네트워크 간의 교통 정리를 담당하는 핵심 장비입니다.

### 라우터의 주요 기능

**1. 라우팅 (Routing)**

라우터는 **패킷을 최적의 경로를 찾아 다른 네트워크로 전달**합니다.

예를 들어, 여러분이 집에서 인터넷을 사용할 때:
1. 여러분의 컴퓨터 → 가정용 라우터
2. 가정용 라우터 → ISP의 라우터
3. ISP의 라우터 → 인터넷 백본 라우터들
4. ... (여러 라우터를 거침)
5. 최종 목적지 서버에 도달

각 라우터는 패킷의 목적지 IP 주소를 보고, 자신의 **라우팅 테이블**을 참조하여 다음 홉(Next Hop)을 결정합니다.

**2. Broadcast Domain 분리**

이것이 라우터의 가장 중요한 기능 중 하나입니다. 라우터는 **브로드캐스트 프레임을 차단**합니다.

스위치의 한계를 다시 생각해봅시다:
- 스위치는 브로드캐스트, 멀티캐스트, Unknown Unicast를 모든 포트로 flooding합니다
- 스위치가 많이 연결된 대형 네트워크에서는 브로드캐스트 트래픽이 네트워크 전체로 퍼집니다
- 이것을 **Broadcast Storm**이라고 하며, 심각한 성능 저하를 일으킵니다

라우터는 이 문제를 해결합니다:
```
[Network A: 192.168.1.0/24]
    |
[Router] ━ Broadcast 차단!
    |
[Network B: 192.168.2.0/24]
```

Network A에서 발생한 브로드캐스트는 라우터를 넘어 Network B로 전달되지 않습니다. 각 네트워크는 독립적인 **Broadcast Domain**이 됩니다.

### Broadcast Domain이란?

**Broadcast Domain**은 브로드캐스트 프레임이 도달할 수 있는 네트워크 영역을 의미합니다.

- **L2 장비(스위치, 브리지)**: 브로드캐스트를 통과시킵니다
- **L3 장비(라우터)**: 브로드캐스트를 차단합니다

> 문제 | 2대의 라우터와 5대의 스위치로 구성된 네트워크에서, 라우터로 분리된 네트워크가 3개라면 Broadcast Domain은 몇 개일까요?

정답은 → 3개입니다. Broadcast Domain은 라우터(L3 장비)에 의해 분리됩니다. 스위치의 개수는 Broadcast Domain에 영향을 주지 않습니다.

**3. 서로 다른 네트워크 연결**

라우터는 서로 다른 네트워크(서브넷)를 연결합니다:
- 192.168.1.0/24 네트워크와 192.168.2.0/24 네트워크 연결
- 사설 네트워크와 공인 네트워크 연결
- 본사와 지사 네트워크 연결

### 라우터의 특징

1. **IP 주소 인식**: L3에서 동작하므로 IP 주소를 이해하고 처리합니다
2. **MAC 주소도 인식**: L2 프레임을 받아야 하므로 MAC 주소도 사용합니다
3. **라우팅 테이블 유지**: 목적지 네트워크에 도달하는 방법을 저장합니다
4. **브로드캐스트 차단**: 브로드캐스트, 멀티캐스트, Unknown Unicast를 차단합니다

## L3 Switch (Layer 3 스위치)

**L3 Switch**는 스위치와 라우터의 기능을 결합한 장비입니다.

### L3 스위치란?

- **기본적으로는 스위치**: L2 스위칭 기능이 주 기능
- **라우팅 기능 추가**: VLAN 간 라우팅, 제한적인 라우팅 기능
- **빠른 속도**: 하드웨어 기반 라우팅으로 일반 라우터보다 빠름
- **가격 효율적**: 라우터보다 저렴하면서도 기본적인 라우팅 가능

### L3 스위치 vs 라우터

| 특징 | L3 Switch | Router |
|------|-----------|--------|
| 주 기능 | 스위칭 (L2) + 제한적 라우팅 | 라우팅 (L3) |
| 속도 | 매우 빠름 (하드웨어 기반) | 상대적으로 느림 |
| 라우팅 프로토콜 | 제한적 (OSPF, RIP 등 기본만) | 다양한 프로토콜 지원 |
| WAN 연결 | 제한적 | 다양한 WAN 인터페이스 |
| 사용 위치 | 내부 네트워크 (LAN) | 네트워크 경계, WAN |
| 가격 | 상대적으로 저렴 | 상대적으로 비싸 |

### 실무에서의 사용

- **L3 스위치**: 주로 내부 네트워크에서 VLAN 간 라우팅에 사용
- **라우터**: 인터넷 연결, 지사 간 연결, 복잡한 라우팅이 필요한 곳에 사용

# 5. 케이블 종류

네트워크 장비를 연결하려면 케이블이 필요합니다. 주로 사용되는 케이블 종류를 알아보겠습니다.

## 이더넷 케이블 (UTP Cable)

**UTP(Unshielded Twisted Pair)** 케이블은 가장 일반적으로 사용되는 네트워크 케이블입니다.

### 케이블 카테고리

| 카테고리 | 최대 속도 | 최대 거리 | 용도 |
|---------|-----------|-----------|------|
| Cat5 | 100 Mbps | 100m | 구형 네트워크 |
| Cat5e | 1 Gbps | 100m | 일반적인 네트워크 |
| Cat6 | 1 Gbps (10 Gbps - 55m) | 100m | 고속 네트워크 |
| Cat6a | 10 Gbps | 100m | 데이터센터 |
| Cat7 | 10 Gbps | 100m | 고성능 네트워크 |

### 케이블 타입

**1. Straight-Through Cable (다이렉트 케이블)**
- 양쪽 끝이 같은 배선 순서
- **서로 다른 종류의 장비** 연결에 사용
- 예: PC ↔ Switch, Switch ↔ Router

**2. Crossover Cable (크로스오버 케이블)**
- 양쪽 끝의 배선 순서가 교차
- **같은 종류의 장비** 연결에 사용
- 예: PC ↔ PC, Switch ↔ Switch, Router ↔ Router

**참고**: 현대의 대부분 장비는 Auto-MDIX 기능을 지원하여 케이블 타입을 자동으로 감지하므로, 어떤 케이블을 사용해도 동작합니다.

## 광케이블 (Fiber Optic Cable)

**광케이블**은 빛을 이용하여 데이터를 전송하는 케이블입니다.

### 광케이블의 장점

1. **긴 전송 거리**: 수 킬로미터에서 수십 킬로미터까지 가능
2. **높은 대역폭**: 10 Gbps, 40 Gbps, 100 Gbps 이상
3. **전자기 간섭 없음**: EMI/RFI에 영향을 받지 않음
4. **보안**: 신호 도청이 매우 어려움

### 광케이블 종류

**1. 싱글모드 (Single-Mode)**
- 긴 거리 전송 (수십 km)
- 데이터센터 간 연결, 통신사 백본

**2. 멀티모드 (Multi-Mode)**
- 상대적으로 짧은 거리 (최대 수백 m)
- 건물 내 백본, 데이터센터 내부

### 사용처

- 데이터센터 백본
- 스위치 간 고속 연결 (Uplink)
- 건물 간 연결
- 통신사 백본 네트워크

## 시리얼 케이블

라우터의 WAN 연결에 사용되는 케이블입니다.

- **용도**: 라우터 간 WAN 연결
- **속도**: 수십 Kbps ~ 수 Mbps
- **현재**: 점점 광케이블이나 이더넷 케이블로 대체되는 추세

# 6. 계층별 장비와 도메인 정리

지금까지 배운 내용을 표로 정리해보겠습니다.

## 계층별 장비 비교

| OSI 계층 | 장비 | 이해하는 주소 | Collision Domain | Broadcast Domain | 주요 기능 |
|---------|------|--------------|------------------|------------------|-----------|
| **L1 (물리)** | Repeater, Hub | 없음 | 분리 안 됨 | 분리 안 됨 | 신호 증폭, 연결 |
| **L2 (데이터링크)** | Bridge, Switch | MAC 주소 | **분리됨** | 분리 안 됨 | MAC 기반 전송 |
| **L3 (네트워크)** | Router, L3 Switch | IP 주소, MAC 주소 | 분리됨 | **분리됨** | 라우팅, 네트워크 연결 |

## 핵심 개념 정리

**Collision Domain (충돌 영역)**
- 데이터 충돌이 발생할 수 있는 영역
- **L1 장비(Hub)**: 분리하지 못함 → 모든 장비가 하나의 Collision Domain
- **L2 장비(Switch)**: 각 포트가 독립적인 Collision Domain
- **현대 네트워크**: 스위치 사용으로 충돌 문제는 거의 해결됨

**Broadcast Domain (브로드캐스트 영역)**
- 브로드캐스트가 도달할 수 있는 영역
- **L2 장비(Switch)**: 브로드캐스트를 모든 포트로 전송 → 분리하지 못함
- **L3 장비(Router)**: 브로드캐스트를 차단 → Broadcast Domain 분리
- **중요성**: 대형 네트워크에서 Broadcast Domain을 적절히 분리해야 성능 저하 방지

# 7. 실무에서의 네트워크 구조

실제 네트워크는 이러한 장비들을 계층적으로 구성합니다.

## 전형적인 기업 네트워크 구조

```
[인터넷]
    |
[라우터] ← L3, 외부 네트워크 연결, Broadcast Domain 경계
    |
[코어 스위치 (L3)] ← VLAN 간 라우팅
    |
[디스트리뷰션 스위치 (L2/L3)] ← 부서별, 층별 분배
    |
[액세스 스위치 (L2)] ← 최종 사용자 연결
    |
[PC, 프린터 등]
```

### 각 계층의 역할

**1. 액세스 계층 (Access Layer)**
- L2 스위치 사용
- 최종 사용자 장비 연결
- 각 포트는 독립적인 Collision Domain
- VLAN으로 논리적 분리

**2. 디스트리뷰션 계층 (Distribution Layer)**
- L3 스위치 사용
- VLAN 간 라우팅
- 정책 적용 (ACL, QoS)
- Broadcast Domain 분리

**3. 코어 계층 (Core Layer)**
- 고속 L3 스위치 또는 라우터
- 고속 전송, 최소 지연
- 주로 광케이블 사용

**4. 경계 (Edge)**
- 라우터 사용
- 인터넷 연결
- 방화벽, 보안 장비
- WAN 연결

# 8. 마치며

OSI 계층별 네트워크 장비를 이해하는 것은 네트워크 설계와 문제 해결의 기초입니다.

핵심을 정리하면:

**L1 장비 (Hub, Repeater):**
- 단순히 신호만 증폭
- Collision Domain을 분리하지 못함
- 현대 네트워크에서는 거의 사용 안 함

**L2 장비 (Switch, Bridge):**
- MAC 주소 기반 전송
- **Collision Domain 분리** ← 허브 대비 핵심 개선
- Broadcast Domain은 분리하지 못함
- 현대 네트워크의 핵심 장비

**L3 장비 (Router, L3 Switch):**
- IP 주소 기반 라우팅
- **Broadcast Domain 분리** ← 스위치 대비 핵심 개선
- 서로 다른 네트워크 연결
- 네트워크 경계에서 필수

**케이블:**
- UTP 케이블: 일반적인 연결 (100m 제한)
- 광케이블: 장거리, 고속 연결

**설계 원칙:**
- Collision Domain: 스위치로 각 포트를 독립적으로
- Broadcast Domain: 라우터/L3 스위치로 적절히 분리
- 계층적 설계: 액세스 → 디스트리뷰션 → 코어 → 경계

이러한 개념을 이해하면, 네트워크를 효율적으로 설계하고, 성능 문제를 진단하며, 적절한 장비를 선택할 수 있습니다. 특히 Collision Domain과 Broadcast Domain의 차이를 명확히 이해하는 것은 네트워크 엔지니어로서 반드시 필요한 지식입니다.
