# 이전 장 요약

이전 두 장에서는 **네트워크 유형**과 **네트워크 구성 요소**에 대해 배웠습니다:

**네트워크 유형**:
- **PAN, LAN, WLAN, MAN, WAN**: 크기와 범위에 따른 네트워크 분류
- **CAN, SAN, VPN**: 특수 목적 네트워크

**네트워크 구성 요소**:
- **NIC, Hub, Switch, Router, AP, Firewall, Modem**: 각 장비의 역할과 특징
- **실전 시나리오**: 스타트업 사무실, 재택근무 VPN, 카페 Wi-Fi, 가정 네트워크 구축

이제 네트워크가 **실제로 어떻게 작동하는지**, 그 핵심인 **OSI 7계층 모델**에 대해 깊이 있게 알아봅시다.

---

# 1. OSI 7계층, 네트워크를 이해하는 첫걸음

네트워크를 공부하다 보면 가장 먼저, 그리고 가장 자주 듣게 되는 말이 바로 'OSI 7계층'입니다. 사실 처음 네트워크를 공부하시는 분들은 이 OSI 7계층이라는 것이 무엇인지, 왜 이렇게 7개나 되는 계층으로 나눠놨는지 쉽게 이해가 안 될 겁니다. 저도 처음에는 그랬습니다. "그냥 데이터를 보내면 되는 건데, 왜 이렇게 복잡하게 만들어 놨을까?" 하는 생각이 들었으니까요.

하지만 네트워크를 공부하면 할수록 OSI 7계층이라는 것이 얼마나 중요한지, 그리고 왜 이렇게 만들어졌는지를 이해하게 됩니다. OSI 7계층은 네트워킹의 모든 것을 이해하는 기초이자 핵심입니다. 이것을 제대로 이해하지 못하면 네트워크 문제를 해결할 때 어디서부터 시작해야 할지 막막해지게 됩니다.

이번 장에서는 OSI 7계층이 무엇인지, 왜 필요한지, 그리고 각 계층이 어떤 역할을 하는지에 대해서 차근차근 알아보도록 하겠습니다. 조금 길어질 수도 있지만, 이것을 확실히 이해하고 나면 앞으로 배울 모든 네트워크 내용이 훨씬 쉬워질 것입니다.

## 왜 계층으로 나눴을까? - 표준의 필요성

자, 그럼 먼저 왜 OSI 7계층이라는 것이 등장하게 되었는지부터 알아볼까요?

컴퓨터 네트워크가 처음 만들어지기 시작한 것은 1960년대 후반부터입니다. 그때는 지금처럼 통일된 표준 같은 것이 없었습니다. 각 컴퓨터 회사들은 자기들만의 방식으로 네트워크를 만들었죠. IBM(1970년대 메인프레임 컴퓨터 회사)은 IBM만의 방식으로 네트워크를 구축했고, DEC(미니컴퓨터 회사)는 또 DEC만의 방식으로 네트워크를 만들었습니다.

이렇게 되면 어떤 문제가 생길까요? 네, 맞습니다. IBM 컴퓨터와 DEC 컴퓨터가 서로 통신을 할 수 없게 되는 겁니다. 마치 한국 사람은 한국어만 할 수 있고, 미국 사람은 영어만 할 수 있어서 서로 대화가 안 되는 것과 똑같은 상황입니다.

상상해 보세요. 어떤 회사에서 IBM 컴퓨터를 쓰고 있는데, 새로운 부서가 생기면서 DEC 컴퓨터를 사게 되었습니다. 그런데 이 두 컴퓨터가 서로 데이터를 주고받을 수 없다면? 그야말로 낭패가 아닐 수 없겠죠.

이런 문제가 점점 심각해지면서 컴퓨터 업계에서는 "이러면 안 되겠다. 모두가 함께 사용할 수 있는 공통된 방식이 필요하다"는 인식을 하게 됩니다. 그래서 등장한 것이 바로 **표준(Standard)** 입니다.

1970년대 말, 국제표준화기구(ISO, International Organization for Standardization)라는 곳에서 서로 다른 시스템 간에도 통신할 수 있도록 하는 표준 모델을 만들기 시작했습니다. 그리고 1984년, 드디어 **OSI(Open Systems Interconnection) 참조 모델**이라는 것이 세상에 나오게 됩니다. 여기서 Open Systems Interconnection이라는 말은 "개방된 시스템들 간의 상호 연결"이라는 뜻입니다. 즉, 어떤 시스템이든 이 표준을 따르면 서로 통신할 수 있다는 의미죠.

## 복잡한 문제를 단순하게 만드는 계층화의 마법

그런데 ISO에서는 왜 이 표준을 7개의 계층으로 나눴을까요? 그냥 하나로 통일하면 안 됐을까요?

사실 네트워크 통신이라는 것은 생각보다 훨씬 복잡합니다. 데이터를 한 컴퓨터에서 다른 컴퓨터로 보낸다는 것이 단순해 보이지만, 그 안에는 정말 많은 일들이 벌어집니다.

생각해 보세요. 데이터를 보내려면 먼저 전기 신호나 빛, 또는 전파로 바꿔야 합니다. 그런 다음 케이블이나 무선으로 전송하고, 받는 쪽에서는 이것을 다시 데이터로 복원해야 합니다. 그런데 여기서 끝이 아닙니다. 데이터가 어디로 가야 하는지 주소를 붙여야 하고, 중간에 여러 라우터를 거쳐서 목적지를 찾아가야 합니다. 또 데이터가 중간에 손실되거나 에러가 나면 이것을 검출하고 재전송해야 합니다. 데이터를 암호화할 수도 있어야 하고, 압축할 수도 있어야 합니다. 그리고 마지막으로 우리가 사용하는 응용 프로그램(웹 브라우저, 이메일 프로그램 등)이 이 데이터를 사용할 수 있어야 합니다.

이 모든 것을 한꺼번에 다루려고 하면 어떻게 될까요? 너무 복잡해서 아무도 이해할 수 없을 겁니다. 그래서 나온 것이 바로 **계층화(Layering)** 라는 개념입니다.

복잡한 문제는 작게 나눠서 해결하는 것이 훨씬 쉽습니다. 마치 택배를 보낼 때를 생각해 보세요. 물건을 포장하는 사람, 송장을 붙이는 사람, 집하하는 사람, 분류하는 사람, 배송하는 사람이 각각 따로 있습니다. 각자 자기 역할만 제대로 하면 되는 거죠. 포장하는 사람은 "이 물건이 부산까지 어떤 경로로 갈까?"를 걱정할 필요가 없습니다. 그냥 물건이 깨지지 않게 잘 포장하기만 하면 됩니다. 마찬가지로 배송하는 사람은 "이 상자 안에 뭐가 들었지?"를 알 필요가 없습니다. 그냥 주소를 보고 해당 주소로 배달하기만 하면 되는 겁니다.

OSI 7계층도 똑같습니다. 네트워크 통신에 필요한 모든 기능을 7개의 계층으로 나누고, 각 계층은 자신의 역할만 충실히 수행하면 되는 겁니다. 이렇게 하면 각 계층을 이해하기도 쉽고, 문제가 생겼을 때 어느 계층에서 문제가 생긴 건지 파악하기도 쉬워집니다.

## 계층화가 주는 실질적인 이점들

계층화가 주는 이점을 좀 더 구체적으로 알아볼까요?

**첫째, 문제 해결이 훨씬 쉬워집니다.**

여러분이 인터넷이 안 된다고 가정해 봅시다. "인터넷이 안 돼요"라는 문제를 어디서부터 해결해야 할까요? 계층 구조를 모른다면 정말 막막할 겁니다.

하지만 OSI 7계층을 알고 있다면 체계적으로 접근할 수 있습니다. 먼저 물리 계층(1계층)을 확인합니다. 랜선이 제대로 꽂혀 있나요? 랜 카드에 불이 들어와 있나요? 여기는 문제없다면 다음 계층으로 넘어갑니다. 데이터링크 계층(2계층)은 어떤가요? 스위치는 정상 동작하나요? 문제없다면 또 다음 계층으로 넘어갑니다. 네트워크 계층(3계층)을 확인합니다. IP 주소는 제대로 받아왔나요? 게이트웨이까지 ping은 되나요?

이렇게 계층별로 하나씩 확인해 나가면 어느 계층에서 문제가 발생했는지 찾을 수 있고, 그 계층에 집중해서 문제를 해결할 수 있습니다. 실제로 네트워크 엔지니어들이 문제를 해결할 때 이런 방식으로 접근합니다.

**둘째, 표준화와 호환성이 보장됩니다.**

각 계층이 표준화되어 있으면 서로 다른 제조사의 장비도 함께 사용할 수 있습니다. 예를 들어 여러분 회사에서 시스코(Cisco) 라우터를 쓰고 있는데, 새로 확장하는 지사에는 주니퍼(Juniper) 라우터를 설치했다고 해봅시다. 두 회사의 라우터는 제조사도 다르고, 내부 구조도 다르고, 운영체제도 다릅니다. 하지만 둘 다 OSI 표준을 따르기 때문에 서로 통신할 수 있습니다.

이것이 가능한 이유는 각 계층의 인터페이스가 표준화되어 있기 때문입니다. 3계층에서는 IP 프로토콜을 사용하고, 4계층에서는 TCP나 UDP를 사용한다는 것이 정해져 있으니까, 어떤 제조사의 장비를 쓰든 이 표준만 따르면 통신이 가능한 겁니다.

**셋째, 기술 발전이 유연하게 이루어집니다.**

한 계층의 기술이 바뀌어도 다른 계층에는 영향을 주지 않습니다. 이것은 정말 중요한 장점입니다.

예를 들어 볼까요? 옛날에는 네트워크 케이블로 동축 케이블(Coaxial Cable)을 많이 썼습니다. 그런데 요즘은 대부분 UTP 케이블이나 광케이블을 사용합니다. 물리 계층(1계층)의 기술이 완전히 바뀐 겁니다. 그런데 이것 때문에 IP 프로토콜을 바꿔야 했나요? TCP를 수정해야 했나요? 웹 브라우저를 새로 만들어야 했나요? 아닙니다. 전혀 바꿀 필요가 없었습니다.

왜냐하면 각 계층이 독립적으로 동작하기 때문입니다. 물리 계층이 하는 일은 "비트를 전기 신호나 빛으로 바꿔서 전송한다"는 것이고, 상위 계층 입장에서는 "어떻게든 비트가 전달되기만 하면 된다"는 겁니다. 동축 케이블로 보내든, UTP 케이블로 보내든, 광케이블로 보내든 상관없는 거죠.

마찬가지로 미래에 6G, 7G 같은 새로운 무선 기술이 나와도 상위 계층의 프로토콜들은 바꿀 필요가 없습니다. 이것이 바로 계층화의 힘입니다.

**넷째, 개발과 유지보수가 쉬워집니다.**

각 계층이 명확히 분리되어 있으면 각 계층을 담당하는 개발자들이 자기 계층만 집중해서 개발할 수 있습니다. 라우터를 만드는 엔지니어는 3계층(네트워크 계층)의 라우팅 알고리즘에 집중하면 되고, 웹 개발자는 7계층(응용 계층)의 HTTP 프로토콜에 집중하면 됩니다.

또한 문제가 생겼을 때도 해당 계층만 수정하면 되니까 유지보수가 훨씬 쉬워집니다.

# 2. OSI 7계층의 전체 구조

자, 그럼 이제 OSI 7계층이 어떻게 구성되어 있는지 전체적인 그림을 한번 그려볼까요?

OSI 모델은 네트워크 통신을 **7개의 계층**으로 나눕니다. 각 계층은 특정한 기능을 담당하며, 하위 계층은 상위 계층에게 서비스를 제공합니다. 이게 무슨 말인가 하면, 예를 들어 4계층(전송 계층)은 3계층(네트워크 계층)의 서비스를 이용하고, 5계층(세션 계층)은 4계층의 서비스를 이용한다는 뜻입니다.

계층은 아래에서 위로 번호가 매겨집니다. 1계층이 가장 낮은 계층으로 하드웨어와 직접 관련된 물리적인 부분을 담당하고, 7계층이 가장 높은 계층으로 우리가 직접 사용하는 응용 프로그램 부분을 담당합니다.

**OSI 7계층 구조 (하단에서 상단으로)**:
- **7계층 (Application Layer)**: 응용 계층 - HTTP, FTP, SMTP 등
- **6계층 (Presentation Layer)**: 표현 계층 - 암호화, 압축, 인코딩
- **5계층 (Session Layer)**: 세션 계층 - 세션 관리
- **4계층 (Transport Layer)**: 전송 계층 - TCP, UDP
- **3계층 (Network Layer)**: 네트워크 계층 - IP, 라우팅
- **2계층 (Data Link Layer)**: 데이터 링크 계층 - MAC, 스위칭
- **1계층 (Physical Layer)**: 물리 계층 - 케이블, 전기 신호

이 7개의 계층은 크게 두 그룹으로 나눌 수 있습니다.

**하위 계층(Lower Layers): 1계층부터 4계층까지**

이 계층들은 주로 **데이터를 어떻게 전송할 것인가**에 집중합니다. 물리적으로 비트를 보내고(1계층), 옆 장비에게 프레임을 전달하고(2계층), 멀리 떨어진 목적지까지 패킷을 라우팅하고(3계층), 데이터가 제대로 도착했는지 확인합니다(4계층). 주로 하드웨어나 네트워크 장비와 관련이 깊습니다.

**상위 계층(Upper Layers): 5계층부터 7계층까지**

이 계층들은 주로 **데이터를 어떻게 표현하고 사용할 것인가**에 집중합니다. 응용 프로그램 간의 연결을 관리하고(5계층), 데이터의 형식을 변환하거나 암호화하고(6계층), 실제로 우리가 사용하는 서비스를 제공합니다(7계층). 주로 소프트웨어와 관련이 깊습니다.

실무에서는 하위 4개 계층을 더 중요하게 다룹니다. 네트워크 엔지니어들이 주로 다루는 것이 라우터(3계층), 스위치(2계층), 케이블(1계층), 그리고 TCP/UDP(4계층)이기 때문입니다. 상위 3개 계층은 주로 응용 프로그램 개발자들이 관심을 갖는 영역이고, 실제로는 운영체제나 응용 프로그램에 통합되어 있는 경우가 많습니다.

## 계층 간의 통신 원칙

OSI 7계층에는 중요한 원칙이 있습니다.

**첫째, 각 계층은 독립적으로 동작합니다.**

각 계층은 자신이 해야 할 일만 합니다. 2계층은 3계층이 무슨 일을 하는지 자세히 알 필요가 없고, 3계층도 2계층의 내부 동작을 알 필요가 없습니다. 서로가 정해진 인터페이스로만 통신하면 됩니다.

**둘째, 각 계층은 바로 아래 계층의 서비스만 이용합니다.**

예를 들어 4계층(전송 계층)은 3계층(네트워크 계층)의 서비스를 이용합니다. 4계층이 직접 1계층(물리 계층)과 통신하는 일은 없습니다. 모든 것은 인접한 계층끼리만 통신합니다.

**셋째, 각 계층은 바로 위 계층에게 서비스를 제공합니다.**

2계층은 3계층에게 "MAC 주소를 이용한 프레임 전달" 서비스를 제공하고, 3계층은 4계층에게 "IP 주소를 이용한 패킷 전달" 서비스를 제공합니다.

이런 원칙 덕분에 각 계층을 독립적으로 개발하고 수정할 수 있는 겁니다.

# 3. 각 계층을 하나씩 자세히 알아보기

자, 이제 본격적으로 각 계층이 무엇을 하는지 하나씩 알아보도록 하겠습니다. 아래 계층부터 차근차근 올라가면서 설명하겠습니다.

## 제1계층: 물리 계층 (Physical Layer)

물리 계층은 OSI 모델의 가장 밑바닥에 있는 계층입니다. 이름에서 알 수 있듯이 물리적인 하드웨어와 직접 관련이 있습니다.

**물리 계층이 하는 일**

물리 계층의 역할은 아주 단순합니다. **0과 1로 이루어진 비트(bit) 데이터를 전기 신호나 빛, 또는 전파로 바꿔서 물리적인 매체(케이블, 공기)를 통해 전송하는 것**입니다.

컴퓨터 안에서 데이터는 0과 1의 비트로 표현됩니다. 하지만 이 0과 1을 다른 컴퓨터로 보내려면 물리적인 신호로 바꿔야 합니다. 유선 케이블을 사용한다면 전기 신호로 바꿔야 하고(전압이 높으면 1, 낮으면 0), 광케이블을 사용한다면 빛으로 바꿔야 하고(빛이 있으면 1, 없으면 0), 무선을 사용한다면 전파로 바꿔야 합니다.

이 모든 것을 담당하는 것이 바로 물리 계층입니다. 물리 계층은 데이터가 무슨 의미인지, 어디로 가는 건지 전혀 관심이 없습니다. 그냥 비트를 신호로 바꾸고, 신호를 비트로 바꾸는 일만 합니다.

**물리 계층과 관련된 것들**

물리 계층과 관련된 것들을 나열해 보면 다음과 같습니다.

- **케이블**: UTP 케이블(랜선), 동축 케이블, 광케이블 등
- **커넥터**: RJ-45 커넥터, 광커넥터 등
- **네트워크 장비**: 허브(Hub), 리피터(Repeater)
- **전송 속도**: 10Mbps, 100Mbps, 1Gbps, 10Gbps 등
- **전송 방식**: 단방향(Simplex), 반이중(Half-Duplex), 전이중(Full-Duplex)
- **신호 방식**: 전기 신호, 광 신호, 무선 전파

**허브(Hub)는 물리 계층 장비입니다**

허브는 여러 대의 컴퓨터를 연결하는 장비입니다. 허브는 한 포트로 들어온 전기 신호를 그대로 증폭해서 다른 모든 포트로 내보냅니다. 허브는 신호 안에 무슨 데이터가 들어있는지, 어디로 가야 하는지 전혀 모릅니다. 그냥 신호를 복사해서 뿌리기만 합니다. 그래서 허브를 물리 계층 장비라고 하는 겁니다.

요즘은 허브를 거의 사용하지 않습니다. 스위치로 대체되었기 때문입니다. 하지만 물리 계층이 무엇인지 이해하는 데는 허브가 좋은 예시입니다.

**물리 계층의 예시**

여러분이 노트북에 랜선을 꽂습니다. 랜선의 한쪽 끝은 노트북의 랜 카드에 꽂히고, 다른 한쪽 끝은 벽에 있는 랜 포트에 꽂힙니다. 노트북에서 데이터를 보내면 랜 카드가 이 데이터(0과 1)를 전기 신호로 바꿔서 랜선에 실어 보냅니다. 이 전기 신호가 랜선을 타고 벽 너머의 스위치까지 도달합니다. 이 모든 과정이 물리 계층에서 일어나는 일입니다.

만약 랜선이 빠져있거나, 랜선이 단선되었거나, 랜 카드가 고장 나서 신호를 보낼 수 없다면? 이것은 물리 계층의 문제입니다. 네트워크가 안 될 때 가장 먼저 확인해야 하는 것이 바로 이 물리 계층입니다.

## 제2계층: 데이터링크 계층 (Data Link Layer)

물리 계층이 비트를 신호로 바꾸고 전송한다면, 데이터링크 계층은 그보다 한 단계 더 똑똑합니다.

**데이터링크 계층이 하는 일**

데이터링크 계층의 주요 역할은 **물리적으로 연결된 두 장비 사이에서 신뢰성 있게 데이터를 주고받는 것**입니다. 여기서 중요한 단어가 두 개 있습니다. "물리적으로 연결된"과 "신뢰성 있게"입니다.

"물리적으로 연결된"이라는 말은 케이블로 직접 연결되어 있거나, 같은 스위치에 연결되어 있거나, 같은 Wi-Fi에 연결되어 있는 것처럼 "같은 네트워크 안에 있다"는 뜻입니다. 데이터링크 계층은 멀리 떨어진 다른 네트워크와 통신하지 않습니다. 그것은 상위 계층인 네트워크 계층(3계층)의 일입니다.

"신뢰성 있게"라는 말은 에러를 검출하고, 순서를 맞추고, 흐름을 제어한다는 뜻입니다. 물리 계층에서는 그냥 신호만 보내지만, 데이터링크 계층에서는 이 데이터가 제대로 갔는지 확인합니다.

**프레임(Frame)이라는 단위**

데이터링크 계층에서 데이터의 단위를 **프레임(Frame)** 이라고 부릅니다. 물리 계층에서는 비트였는데, 데이터링크 계층에서는 이 비트들을 모아서 프레임이라는 단위로 만듭니다.

프레임에는 실제 데이터뿐만 아니라 여러 가지 제어 정보가 함께 들어갑니다. 예를 들어:
- **출발지 MAC 주소**: 이 프레임을 보낸 장비의 MAC 주소
- **목적지 MAC 주소**: 이 프레임을 받을 장비의 MAC 주소
- **에러 검출 코드**: 데이터가 전송 중에 손상되었는지 확인하는 코드

**MAC 주소란?**

데이터링크 계층에서 장비를 구분하는 주소를 **MAC(Media Access Control) 주소**라고 합니다. 모든 네트워크 카드는 제조될 때부터 고유한 MAC 주소를 갖고 태어납니다. MAC 주소는 48비트(6바이트)로 되어 있고, 보통 16진수로 표현합니다. 예를 들어 `00:1A:2B:3C:4D:5E` 이런 식입니다.

MAC 주소는 전 세계에서 유일합니다. 같은 MAC 주소를 가진 네트워크 카드는 존재하지 않습니다(이론상으로는). 마치 사람의 지문처럼 고유한 식별자인 셈이죠.

**스위치(Switch)는 데이터링크 계층 장비입니다**

스위치는 데이터링크 계층에서 동작하는 가장 중요한 네트워크 장비입니다. 스위치는 허브와 달리 **MAC 주소를 이해**할 수 있습니다.

스위치는 자신의 각 포트에 어떤 MAC 주소를 가진 장비가 연결되어 있는지 학습합니다. 그래서 프레임이 들어오면 목적지 MAC 주소를 보고, 해당 MAC 주소를 가진 장비가 연결된 포트로만 프레임을 전송합니다. 허브처럼 모든 포트로 뿌리지 않습니다.

예를 들어 스위치에 컴퓨터 A, B, C, D가 연결되어 있다고 해봅시다. 컴퓨터 A가 컴퓨터 B에게 데이터를 보내면, 스위치는 B의 MAC 주소를 확인하고 B가 연결된 포트로만 프레임을 전달합니다. C와 D는 이 프레임을 받지 않습니다. 이것이 허브와 스위치의 결정적인 차이입니다.

**데이터링크 계층의 예시**

여러분이 같은 사무실 네트워크 안에 있는 동료 컴퓨터로 파일을 보낸다고 생각해 봅시다. 둘 다 같은 스위치에 연결되어 있습니다.

1. 여러분의 컴퓨터는 프레임을 만듭니다. 이 프레임에는 여러분 컴퓨터의 MAC 주소(출발지)와 동료 컴퓨터의 MAC 주소(목적지)가 들어있습니다.
2. 이 프레임이 스위치로 전송됩니다.
3. 스위치는 프레임의 목적지 MAC 주소를 확인하고, 해당 MAC 주소를 가진 컴퓨터가 연결된 포트로 프레임을 전달합니다.
4. 동료 컴퓨터는 프레임을 받고, 자신의 MAC 주소와 목적지 MAC 주소를 비교합니다. 일치하므로 프레임을 받아들입니다.

이 모든 과정이 데이터링크 계층에서 일어납니다. 중요한 점은 같은 네트워크 안에서만 이렇게 동작한다는 것입니다. 만약 인터넷 너머에 있는 서버로 데이터를 보낸다면? 그때는 3계층인 네트워크 계층이 필요합니다.

## 제3계층: 네트워크 계층 (Network Layer)

2계층까지는 같은 네트워크 안에서만 통신할 수 있었습니다. 하지만 3계층인 네트워크 계층부터는 **서로 다른 네트워크 간에 통신**할 수 있게 됩니다.

**네트워크 계층이 하는 일**

네트워크 계층의 가장 중요한 역할은 **라우팅(Routing)** 입니다. 라우팅이란 데이터가 출발지에서 목적지까지 가는 최적의 경로를 찾아주는 것을 말합니다.

인터넷은 수많은 네트워크들이 라우터로 연결되어 있는 거대한 네트워크입니다. 여러분이 집에서 미국에 있는 구글 서버에 접속한다고 생각해 봅시다. 여러분의 데이터는 집에서 나와서 ISP(통신사)의 라우터로 가고, 거기서 또 다른 라우터로 가고, 또 다른 라우터로 가고... 이렇게 수십 개의 라우터를 거쳐서 최종적으로 구글 서버에 도착합니다.

각 라우터는 "이 데이터를 다음에 어디로 보낼까?"를 결정해야 합니다. 이것이 바로 라우팅이고, 네트워크 계층이 하는 일입니다.

**패킷(Packet)이라는 단위**

네트워크 계층에서 데이터의 단위를 **패킷(Packet)** 이라고 부릅니다. 패킷에는 출발지 IP 주소와 목적지 IP 주소가 들어있습니다.

**IP 주소란?**

네트워크 계층에서 장비를 구분하는 주소를 **IP(Internet Protocol) 주소**라고 합니다. MAC 주소와는 다릅니다.

MAC 주소는 네트워크 카드에 제조 시 새겨진 물리적 주소로 절대 바뀌지 않습니다. 하지만 IP 주소는 논리적 주소로 언제든지 바꿀 수 있습니다. 여러분이 집에서 회사로 노트북을 가져가면 IP 주소가 바뀌지만, MAC 주소는 그대로입니다.

IP 주소는 **네트워크 부분**과 **호스트 부분**으로 나뉩니다. 예를 들어 `192.168.1.10`이라는 IP 주소가 있다면, `192.168.1`은 네트워크를 나타내고 `10`은 그 네트워크 안의 특정 컴퓨터를 나타냅니다. 이렇게 네트워크를 구분할 수 있기 때문에 라우팅이 가능한 겁니다.

현재 주로 사용되는 IP 주소는 IPv4로, 32비트(4바이트)로 되어 있습니다. 보통 `192.168.1.1` 이런 식으로 표현합니다. 최근에는 IPv6도 사용되기 시작했는데, 이것은 128비트로 훨씬 더 많은 주소를 만들 수 있습니다.

**라우터(Router)는 네트워크 계층 장비입니다**

라우터는 네트워크 계층에서 동작하는 핵심 장비입니다. 라우터는 **IP 주소를 이해**하고 **라우팅**을 수행합니다.

라우터는 자신에게 연결된 여러 네트워크 사이에서 패킷을 전달하는 역할을 합니다. 라우터는 라우팅 테이블(Routing Table)이라는 것을 가지고 있는데, 여기에는 "어느 네트워크로 가려면 어느 방향으로 보내야 한다"는 정보가 들어있습니다.

예를 들어 여러분 집의 인터넷 공유기(이것도 라우터입니다)는 대략 이런 식으로 생각합니다:
- "192.168.1.0 네트워크는 내 안쪽(LAN)에 있어. 직접 전달하면 돼."
- "그 외의 모든 주소는 내가 모르니까 ISP 라우터로 보내야겠어."

이렇게 각 라우터가 조금씩 조금씩 패킷을 다음 라우터로 전달하다 보면 최종적으로 목적지에 도착하게 됩니다.

**네트워크 계층의 핵심 프로토콜: IP**

네트워크 계층에서 가장 중요한 프로토콜은 바로 **IP(Internet Protocol)** 입니다. 인터넷이라는 이름도 여기서 나왔습니다(Internet = Inter + Network, 네트워크들을 연결한다는 뜻).

IP 프로토콜은 패킷에 출발지와 목적지 IP 주소를 붙이고, 패킷을 목적지까지 전달하는 역할을 합니다. 다만 IP는 신뢰성을 보장하지 않습니다. 패킷이 목적지에 도착했는지 안 했는지 확인하지 않습니다. 그냥 "최선을 다해서(Best Effort)" 보낼 뿐입니다. 신뢰성은 상위 계층인 전송 계층(4계층)에서 담당합니다.

IP 외에도 네트워크 계층에는 여러 프로토콜이 있습니다:
- **ICMP**: Ping 명령어가 사용하는 프로토콜로, 네트워크 상태를 확인할 때 사용합니다.
- **ARP**: IP 주소를 MAC 주소로 변환해주는 프로토콜입니다. 같은 네트워크 안에서 통신할 때 필요합니다.
- **라우팅 프로토콜(RIP, OSPF, BGP 등)**: 라우터들이 서로 라우팅 정보를 교환하는 데 사용하는 프로토콜들입니다.

**네트워크 계층의 예시**

여러분이 집에서 네이버(naver.com)에 접속한다고 해봅시다.

1. 여러분의 컴퓨터는 먼저 DNS 서버에 물어봅니다. "naver.com의 IP 주소가 뭐야?"
2. DNS 서버가 답합니다. "223.130.200.107이야."
3. 이제 여러분의 컴퓨터는 목적지 IP 주소가 223.130.200.107인 패킷을 만듭니다.
4. 이 패킷을 집의 공유기(라우터)로 보냅니다.
5. 공유기는 "이 주소는 내 네트워크에 없네. ISP 라우터로 보내야겠다"라고 판단하고 ISP 라우터로 패킷을 전달합니다.
6. ISP 라우터는 자신의 라우팅 테이블을 확인하고 다음 라우터로 패킷을 전달합니다.
7. 이런 식으로 여러 라우터를 거쳐서 최종적으로 네이버 서버에 패킷이 도착합니다.

이 과정에서 패킷이 몇 개의 라우터를 거쳤는지 확인하려면 `tracert naver.com` (Windows) 또는 `traceroute naver.com` (Linux/Mac) 명령어를 사용하면 됩니다. 한번 해보세요. 여러분의 패킷이 얼마나 많은 라우터를 거쳐서 목적지에 도달하는지 볼 수 있습니다.

## 제4계층: 전송 계층 (Transport Layer)

자, 이제 절반을 넘어왔습니다. 4계층인 전송 계층은 하위 계층과 상위 계층을 연결하는 중요한 계층입니다.

**전송 계층이 하는 일**

전송 계층의 역할은 **종단 간(End-to-End) 통신을 관리**하는 것입니다. "종단 간"이라는 말은 "처음 보낸 컴퓨터부터 최종 목적지 컴퓨터까지"라는 뜻입니다.

3계층(네트워크 계층)까지는 패킷을 목적지 컴퓨터까지 전달하는 것에 집중했습니다. 하지만 그것만으로는 부족합니다. 목적지 컴퓨터에는 여러 프로그램이 동시에 실행되고 있을 수 있습니다. 웹 브라우저도 켜져 있고, 메신저도 켜져 있고, 게임도 켜져 있을 수 있죠. 그럼 이 데이터가 어느 프로그램으로 가야 하는지 구분해야 합니다. 이것을 하는 것이 전송 계층입니다.

또한 전송 계층은 데이터가 **신뢰성 있게** 전달되도록 합니다. 3계층의 IP는 신뢰성을 보장하지 않는다고 했죠? 패킷이 중간에 유실될 수도 있고, 순서가 바뀔 수도 있습니다. 전송 계층(정확히는 TCP)은 이런 문제를 해결합니다.

**세그먼트(Segment)라는 단위**

전송 계층에서 데이터의 단위를 **세그먼트(Segment)** 라고 부릅니다.

**포트 번호(Port Number)로 프로그램 구분**

전송 계층에서는 **포트 번호(Port Number)** 를 사용해서 프로그램을 구분합니다.

IP 주소가 "어느 집"을 나타낸다면, 포트 번호는 "그 집의 몇 호"를 나타낸다고 생각하면 됩니다. 192.168.1.10이라는 IP 주소를 가진 컴퓨터가 있다면, 이 컴퓨터의 80번 포트는 웹 서버가 사용하고, 22번 포트는 SSH 서버가 사용하고, 25번 포트는 이메일 서버가 사용할 수 있습니다.

포트 번호는 0번부터 65535번까지 있습니다. 이 중에서:
- 0~1023번: 잘 알려진 포트(Well-Known Ports). HTTP는 80번, HTTPS는 443번, SSH는 22번 등 정해진 서비스가 사용합니다.
- 1024~49151번: 등록된 포트(Registered Ports). 특정 응용 프로그램이 사용할 수 있습니다.
- 49152~65535번: 동적 포트(Dynamic Ports). 클라이언트가 임시로 사용합니다.

**TCP와 UDP: 두 가지 전송 방식**

전송 계층에는 두 가지 주요 프로토콜이 있습니다. **TCP**와 **UDP**입니다.

**TCP (Transmission Control Protocol): 신뢰성을 중시하는 프로토콜**

TCP는 "데이터가 확실하게 도착하는 것"을 가장 중요하게 생각합니다. TCP는 다음과 같은 특징이 있습니다:

1. **연결 지향(Connection-Oriented)**: 데이터를 보내기 전에 먼저 상대방과 연결을 수립합니다. 마치 전화를 걸어서 "여보세요?"라고 확인하는 것과 같습니다. 이것을 "3-Way Handshake"라고 합니다.

2. **신뢰성 보장**: 데이터가 제대로 도착했는지 확인합니다. 만약 패킷이 유실되면 자동으로 재전송합니다.

3. **순서 보장**: 패킷에 순서 번호를 붙여서, 순서가 바뀌어 도착해도 원래 순서대로 재조립합니다.

4. **흐름 제어**: 받는 쪽이 처리할 수 있는 속도로 데이터를 보냅니다. 너무 빨리 보내서 받는 쪽이 버퍼 오버플로우가 나는 것을 방지합니다.

5. **혼잡 제어**: 네트워크가 혼잡하면 전송 속도를 줄입니다.

이런 장점 때문에 신뢰성이 중요한 응용 프로그램들은 TCP를 사용합니다:
- 웹 브라우징 (HTTP/HTTPS)
- 이메일 (SMTP, POP3, IMAP)
- 파일 전송 (FTP)
- 원격 접속 (SSH, Telnet)

**UDP (User Datagram Protocol): 속도를 중시하는 프로토콜**

UDP는 "빠르게 보내는 것"을 가장 중요하게 생각합니다. UDP의 특징은:

1. **비연결 지향(Connectionless)**: 연결 수립 과정 없이 그냥 바로 데이터를 보냅니다.

2. **신뢰성 보장 안 함**: 데이터가 도착했는지 확인하지 않습니다. 유실되면 그냥 유실된 채로 끝입니다.

3. **순서 보장 안 함**: 순서가 바뀌어 도착할 수 있습니다.

4. **오버헤드가 적음**: TCP처럼 복잡한 기능이 없어서 헤더가 작고 처리가 빠릅니다.

이런 특징 때문에 속도가 중요하거나 약간의 손실은 괜찮은 응용 프로그램들이 UDP를 사용합니다:
- 실시간 스트리밍 (유튜브, 넷플릭스)
- 온라인 게임
- VoIP (인터넷 전화)
- DNS (도메인 이름 조회)
- DHCP (IP 주소 자동 할당)

예를 들어 유튜브로 동영상을 볼 때 가끔 화질이 깨지는 경우가 있죠? 이것은 UDP를 사용해서 일부 패킷이 유실되었기 때문입니다. 하지만 계속 재생은 됩니다. 만약 TCP를 사용했다면 패킷이 유실될 때마다 재전송을 기다려야 해서 영상이 자꾸 멈췄을 겁니다.

**전송 계층의 예시**

여러분이 웹 브라우저로 네이버에 접속한다고 해봅시다.

1. 웹 브라우저는 TCP를 사용해서 네이버 서버(223.130.200.107)의 443번 포트(HTTPS)에 연결을 시도합니다.
2. 3-Way Handshake를 통해 연결이 수립됩니다.
3. 이제 HTTP 요청 데이터를 보냅니다. 이 데이터는 세그먼트로 나뉘고, 각 세그먼트에는 순서 번호가 붙습니다.
4. 네이버 서버는 세그먼트를 받을 때마다 확인 응답(ACK)을 보냅니다.
5. 만약 어떤 세그먼트가 유실되면, 웹 브라우저는 일정 시간 후 자동으로 재전송합니다.
6. 모든 데이터가 도착하면, 네이버 서버는 웹 페이지 데이터를 다시 TCP로 보냅니다.
7. 데이터 전송이 끝나면 연결을 종료합니다.

이 모든 과정에서 TCP가 신뢰성을 보장합니다. 덕분에 우리는 웹 페이지가 깨지거나 일부가 빠진 채로 표시되는 것을 볼 일이 없습니다.

## 제5계층: 세션 계층 (Session Layer)

자, 이제부터는 상위 계층입니다. 상위 3개 계층(5, 6, 7계층)은 실무에서 명확히 구분되지 않는 경우가 많습니다. 대부분 운영체제나 응용 프로그램에 통합되어 있기 때문입니다. 하지만 개념적으로는 각각 역할이 다릅니다.

**세션 계층이 하는 일**

세션 계층의 역할은 **응용 프로그램 간의 세션을 설정하고, 유지하고, 종료**하는 것입니다.

"세션(Session)"이라는 것은 두 응용 프로그램 사이의 논리적인 연결을 말합니다. 예를 들어 여러분이 은행 앱에 로그인하면 세션이 생성됩니다. 이 세션이 유지되는 동안 여러분은 계좌 조회도 하고, 송금도 하고, 여러 작업을 할 수 있습니다. 그리고 로그아웃하면 세션이 종료됩니다.

세션 계층은 이런 세션을 관리합니다. 또한 대화의 동기화(Synchronization)도 담당합니다. 긴 데이터 전송 중에 체크포인트를 두어서, 문제가 생기면 처음부터 다시 보내는 게 아니라 마지막 체크포인트부터 다시 보낼 수 있게 합니다.

**세션 계층의 기능들**

- **세션 설정**: 두 응용 프로그램 간의 세션을 시작합니다.
- **세션 유지**: 세션이 활성 상태로 유지되도록 관리합니다.
- **세션 종료**: 통신이 끝나면 세션을 정리하고 종료합니다.
- **대화 제어**: 반이중(Half-Duplex) 또는 전이중(Full-Duplex) 통신을 관리합니다.
- **동기화**: 데이터 스트림에 체크포인트를 삽입하여 복구 지점을 만듭니다.

**세션 계층 관련 프로토콜/기술**

- **NetBIOS**: 옛날 Windows 네트워크에서 사용하던 세션 관리 프로토콜
- **RPC (Remote Procedure Call)**: 원격 컴퓨터의 함수를 호출하는 기술
- **SQL**: 데이터베이스와의 세션 관리
- **SSH, TLS의 세션 관리 부분**

**세션 계층의 예시**

실무에서 세션 계층을 명확히 보기는 어렵지만, 웹 애플리케이션의 세션을 예로 들 수 있습니다.

여러분이 쇼핑몰에 로그인했다고 해봅시다:
1. 로그인할 때 서버는 세션 ID를 생성하고 여러분에게 보냅니다(보통 쿠키로).
2. 이후 여러분이 상품을 보거나 장바구니에 담을 때마다 이 세션 ID를 함께 보냅니다.
3. 서버는 세션 ID로 "아, 이 사람이 아까 로그인한 그 사람이구나"를 알 수 있습니다.
4. 일정 시간 동안 활동이 없으면 세션이 만료되어 자동으로 로그아웃됩니다.
5. 또는 여러분이 직접 로그아웃하면 세션이 종료됩니다.

이런 세션 관리가 세션 계층의 개념을 보여주는 좋은 예시입니다.

## 제6계층: 표현 계층 (Presentation Layer)

표현 계층은 이름 그대로 데이터를 "어떻게 표현할 것인가"를 담당합니다.

**표현 계층이 하는 일**

표현 계층의 역할은 **데이터의 형식을 변환**하는 것입니다. 마치 번역가나 통역사 같은 역할이라고 생각하면 됩니다.

서로 다른 시스템은 데이터를 다르게 표현할 수 있습니다. 어떤 시스템은 문자를 ASCII로 표현하고, 어떤 시스템은 EBCDIC로 표현할 수 있습니다. 어떤 시스템은 정수를 Big-Endian으로 저장하고, 어떤 시스템은 Little-Endian으로 저장합니다. 표현 계층은 이런 차이를 흡수해서 서로 다른 시스템끼리도 데이터를 주고받을 수 있게 해줍니다.

**표현 계층의 주요 기능**

**1. 데이터 변환 (Translation)**

송신 측의 데이터 형식을 수신 측이 이해할 수 있는 형식으로 바꿔줍니다. 예를 들어:
- 문자 인코딩 변환: ASCII ↔ Unicode ↔ UTF-8
- 바이트 순서 변환: Big-Endian ↔ Little-Endian
- 데이터 직렬화: 객체를 바이트 스트림으로, 또는 그 반대로

**2. 암호화/복호화 (Encryption/Decryption)**

데이터를 안전하게 전송하기 위해 암호화하고, 받는 쪽에서 복호화합니다. 여러분이 HTTPS 웹사이트에 접속할 때 데이터가 암호화되는 것이 여기에 해당합니다.

**3. 압축/압축 해제 (Compression/Decompression)**

데이터의 크기를 줄여서 전송 효율을 높입니다. 큰 파일을 보낼 때 압축해서 보내고, 받는 쪽에서 압축을 풀어서 원본 데이터를 복원합니다.

**표현 계층 관련 기술들**

- **암호화**: SSL/TLS, SSH의 암호화 부분
- **문자 인코딩**: ASCII, Unicode, UTF-8, UTF-16, EUC-KR 등
- **이미지 포맷**: JPEG, GIF, PNG, BMP 등
- **비디오 포맷**: MPEG, H.264, VP9 등
- **오디오 포맷**: MP3, AAC, FLAC 등
- **데이터 직렬화**: JSON, XML, Protocol Buffers 등

**표현 계층의 예시**

**예시 1: HTTPS 웹사이트 접속**

여러분이 은행 웹사이트(https://...)에 접속한다고 해봅시다.

1. 여러분이 비밀번호를 입력하고 로그인 버튼을 누릅니다.
2. 표현 계층(정확히는 TLS/SSL)에서 이 데이터를 암호화합니다. "mypassword123"이 암호화되어 알아볼 수 없는 데이터가 됩니다.
3. 암호화된 데이터가 전송됩니다.
4. 은행 서버의 표현 계층에서 이 데이터를 복호화하여 원래의 "mypassword123"으로 되돌립니다.

중간에 누가 데이터를 가로채더라도 암호화되어 있어서 내용을 알 수 없습니다. 이것이 표현 계층이 보안에 기여하는 부분입니다.

**예시 2: 한글 이메일 보내기**

여러분이 한글로 이메일을 쓴다고 해봅시다.

1. "안녕하세요"라는 한글 텍스트를 UTF-8로 인코딩합니다.
2. 이 데이터가 전송됩니다.
3. 받는 사람의 이메일 프로그램이 UTF-8로 디코딩하여 다시 "안녕하세요"로 표시합니다.

만약 인코딩/디코딩이 제대로 안 되면 한글이 깨져서 "¾È³çÇÏ¼¼¿ä" 이런 식으로 보이게 됩니다. 이것이 표현 계층의 문제입니다.

## 제7계층: 응용 계층 (Application Layer)

드디어 마지막 계층입니다! 응용 계층은 우리가 직접 사용하는 응용 프로그램과 가장 가까운 계층입니다.

**응용 계층이 하는 일**

응용 계층의 역할은 **사용자에게 네트워크 서비스를 제공**하는 것입니다. 사용자가 직접 상호작용하는 계층이라고 생각하면 됩니다.

하위 6개 계층은 모두 데이터를 전송하는 것과 관련된 일을 합니다. 하지만 응용 계층은 "그래서 이 데이터로 뭘 할 건데?"에 대한 답을 제공합니다. 웹 페이지를 보여줄 수도 있고, 이메일을 주고받을 수도 있고, 파일을 전송할 수도 있습니다.

**응용 계층의 주요 프로토콜들**

응용 계층에는 정말 많은 프로토콜들이 있습니다. 우리가 일상적으로 사용하는 거의 모든 인터넷 서비스가 응용 계층의 프로토콜을 사용합니다.

**HTTP/HTTPS (HyperText Transfer Protocol)**

웹 브라우징에 사용하는 프로토콜입니다. 여러분이 주소창에 URL을 입력하고 엔터를 누르면 HTTP 또는 HTTPS 프로토콜을 통해 웹 서버와 통신합니다.

- HTTP: 평문으로 통신 (80번 포트)
- HTTPS: 암호화된 통신 (443번 포트)

**FTP (File Transfer Protocol)**

파일을 전송하는 프로토콜입니다. 옛날에는 많이 사용했지만, 요즘은 보안 문제로 SFTP나 FTPS를 더 많이 사용합니다.

**SMTP, POP3, IMAP (이메일 프로토콜)**

- **SMTP (Simple Mail Transfer Protocol)**: 이메일을 보낼 때 사용합니다.
- **POP3 (Post Office Protocol v3)**: 이메일을 받을 때 사용합니다. 서버에서 이메일을 다운로드하면 서버에서는 삭제됩니다.
- **IMAP (Internet Message Access Protocol)**: 이메일을 받을 때 사용합니다. 서버에 이메일을 남겨두고 여러 기기에서 동기화할 수 있습니다.

**DNS (Domain Name System)**

도메인 이름을 IP 주소로 변환해주는 프로토콜입니다. 여러분이 "naver.com"을 입력하면 DNS가 이것을 "223.130.200.107"로 바꿔줍니다. 인터넷 전화번호부 같은 역할이죠.

**DHCP (Dynamic Host Configuration Protocol)**

IP 주소를 자동으로 할당해주는 프로토콜입니다. 여러분이 카페에서 Wi-Fi에 연결하면 자동으로 IP 주소를 받는데, 이것이 DHCP 덕분입니다.

**SSH (Secure Shell)**

원격으로 다른 컴퓨터에 접속해서 명령어를 실행할 수 있게 해주는 프로토콜입니다. 서버 관리자들이 많이 사용합니다.

**Telnet**

SSH와 비슷하지만 암호화가 안 되는 옛날 프로토콜입니다. 보안 문제로 요즘은 거의 사용하지 않습니다.

**SNMP (Simple Network Management Protocol)**

네트워크 장비(라우터, 스위치 등)를 원격으로 모니터링하고 관리하는 프로토콜입니다.

**응용 계층의 예시**

**예시 1: 웹 브라우징**

여러분이 크롬 브라우저로 구글(google.com)에 접속한다고 해봅시다.

1. **DNS 조회**: 브라우저가 먼저 DNS 서버에 "google.com의 IP 주소가 뭐야?"라고 물어봅니다. DNS 서버가 "142.250.196.78이야"라고 답합니다.
2. **TCP 연결**: 4계층에서 TCP 연결을 수립합니다.
3. **HTTP 요청**: 7계층에서 HTTP GET 요청을 보냅니다. "/ 페이지를 주세요"
4. **HTTP 응답**: 구글 서버가 HTML 파일을 HTTP로 보냅니다.
5. **페이지 렌더링**: 브라우저가 HTML을 해석해서 화면에 표시합니다.

이 모든 과정에서 응용 계층의 프로토콜(DNS, HTTP)이 사용됩니다.

**예시 2: 이메일 보내기**

여러분이 Gmail로 이메일을 보낸다고 해봅시다.

1. 이메일 작성 후 "보내기" 버튼을 누릅니다.
2. Gmail 앱이 SMTP 프로토콜을 사용해서 Gmail 서버로 이메일을 보냅니다.
3. Gmail 서버가 받는 사람의 메일 서버로 SMTP를 통해 이메일을 전달합니다.
4. 받는 사람이 이메일을 확인하려고 메일 앱을 열면, 앱이 IMAP 프로토콜을 사용해서 서버에서 이메일을 가져옵니다.

SMTP와 IMAP 모두 응용 계층의 프로토콜입니다.

# 4. 실무에서 OSI 7계층 활용하기

자, 이론은 충분히 배웠습니다. 그런데 이것을 실무에서 어떻게 활용할까요?

## 문제 해결에 OSI 7계층 모델 적용하기

네트워크 문제가 발생했을 때 OSI 7계층 모델을 알면 체계적으로 접근할 수 있습니다.

**상황: "웹사이트가 안 열려요!"**

고객이 전화를 걸어서 "웹사이트가 안 열린다"고 합니다. 어디서부터 확인해야 할까요? OSI 7계층 모델을 따라 아래부터 확인해 봅시다.

**1단계: 물리 계층 확인**
- 랜선이 제대로 꽂혀 있나요?
- 랜 카드의 LED가 켜져 있나요?
- Wi-Fi를 사용한다면 Wi-Fi에 연결되어 있나요?

만약 랜선이 빠져있었다면 여기서 문제 해결 끝입니다. 더 이상 올라갈 필요가 없습니다.

**2단계: 데이터링크 계층 확인**
- 스위치 포트가 활성화되어 있나요?
- MAC 주소 테이블에 이 컴퓨터가 보이나요?
- VLAN 설정이 맞나요?

**3단계: 네트워크 계층 확인**
- IP 주소가 할당되었나요? `ipconfig` (Windows) 또는 `ifconfig` (Linux) 명령어로 확인합니다.
- 169.254.x.x 주소가 나온다면 DHCP에서 IP를 못 받은 겁니다. (APIPA 주소)
- 게이트웨이(라우터)까지 ping이 되나요? `ping 192.168.1.1`
- 외부 인터넷까지 ping이 되나요? `ping 8.8.8.8` (구글 DNS)
- DNS는 동작하나요? `nslookup naver.com`

대부분의 네트워크 문제는 여기까지 확인하면 찾을 수 있습니다.

**4단계: 전송 계층 확인**
- 방화벽에서 해당 포트가 열려있나요?
- 웹 서버의 443번(HTTPS) 또는 80번(HTTP) 포트가 Listening 상태인가요?
- `telnet naver.com 80` 명령어로 포트 연결을 테스트할 수 있습니다.

**5~7단계: 상위 계층 확인**
- 웹 서버 프로세스가 실행 중인가요?
- 웹 서버 설정 파일이 올바른가요?
- SSL 인증서가 유효한가요?
- 애플리케이션 로그에 에러가 있나요?

이렇게 아래부터 차근차근 확인하면 어느 계층에서 문제가 발생했는지 찾을 수 있고, 그 계층에 집중해서 문제를 해결할 수 있습니다.

## OSI 7계층과 TCP/IP 모델

실무에서는 OSI 7계층보다 **TCP/IP 모델**을 더 많이 사용합니다. 왜냐하면 실제 인터넷은 TCP/IP 프로토콜 기반으로 만들어졌기 때문입니다.

TCP/IP 모델은 4개 계층으로 되어 있습니다:

**OSI 7계층과 TCP/IP 4계층 비교:**

```
OSI 7계층                    TCP/IP 4계층
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
7. 응용 계층
6. 표현 계층                  응용 계층
5. 세션 계층                  (Application)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
4. 전송 계층                  전송 계층
                            (Transport)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
3. 네트워크 계층               인터넷 계층
                            (Internet)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
2. 데이터링크 계층             네트워크 인터페이스 계층
1. 물리 계층                  (Network Interface)
```

**차이점:**
- **OSI 모델**: 이론적인 참조 모델. 네트워크를 이해하고 설명하는 데 유용합니다.
- **TCP/IP 모델**: 실제 구현 모델. 인터넷이 이것을 기반으로 동작합니다.

**왜 OSI를 배우는가?**

TCP/IP가 실제로 사용되는데 왜 OSI 7계층을 배울까요? OSI 모델이 더 세밀하게 나뉘어 있어서 네트워크의 각 기능을 이해하기 쉽기 때문입니다. 또한 네트워크 장비를 분류할 때(L2 스위치, L3 스위치, L4 로드밸런서, L7 방화벽 등) OSI 계층을 사용합니다.

실무에서는 두 모델을 함께 사용합니다. 개념을 설명할 때는 OSI를, 실제 구현할 때는 TCP/IP를 사용하는 식입니다.

## 네트워크 장비와 OSI 계층

네트워크 장비들은 특정 계층에서 동작합니다. 이것을 알면 어떤 장비를 어디에 사용해야 하는지 알 수 있습니다.

- **L1 장비**: 허브, 리피터 - 물리적 신호만 다룸
- **L2 장비**: 스위치, 브리지 - MAC 주소를 보고 프레임 전달
- **L3 장비**: 라우터, L3 스위치 - IP 주소를 보고 패킷 라우팅
- **L4 장비**: L4 스위치, 로드밸런서 - 포트 번호를 보고 로드밸런싱
- **L7 장비**: L7 스위치, 웹 방화벽 - HTTP 내용을 보고 필터링

예를 들어 L7 방화벽은 HTTP 요청의 URL이나 쿠키까지 볼 수 있어서 "이 URL은 차단해!"라고 할 수 있습니다. 하지만 L3 라우터는 IP 주소만 볼 수 있어서 "192.168.1.0 네트워크는 차단해"까지만 할 수 있습니다.

# 5. 계층별 핵심 정리

여기까지 정말 긴 여정이었습니다. 핵심만 간단히 정리해 볼까요?

**계층별 한 줄 요약:**

- **L1 (물리)**: 0과 1을 전기/빛 신호로 바꿔서 전송
- **L2 (데이터링크)**: MAC 주소로 같은 네트워크 안에서 프레임 전달
- **L3 (네트워크)**: IP 주소로 다른 네트워크까지 패킷 라우팅
- **L4 (전송)**: 포트 번호로 프로그램 구분, TCP로 신뢰성 보장
- **L5 (세션)**: 응용 프로그램 간 세션 관리
- **L6 (표현)**: 암호화, 압축, 인코딩
- **L7 (응용)**: HTTP, FTP, DNS 등 실제 서비스 제공

**데이터 단위:**

- L1: 비트 (Bit)
- L2: 프레임 (Frame)
- L3: 패킷 (Packet)
- L4: 세그먼트 (Segment)
- L5~7: 데이터 (Data)

**주소 체계:**

- L2: MAC 주소 (예: 00:1A:2B:3C:4D:5E) - 물리적 주소, 변경 불가
- L3: IP 주소 (예: 192.168.1.10) - 논리적 주소, 변경 가능
- L4: 포트 번호 (예: 80, 443) - 응용 프로그램 구분

**주요 장비:**

- L1: 허브, 리피터
- L2: 스위치, 브리지
- L3: 라우터, L3 스위치
- L4~7: 로드밸런서, 방화벽

**계층 구조 외우는 법:**

**위에서 아래로 (7→1):** **A**ll **P**eople **S**eem **T**o **N**eed **D**ata **P**rocessing
- Application, Presentation, Session, Transport, Network, Data Link, Physical

**아래에서 위로 (1→7):** **P**lease **D**o **N**ot **T**hrow **S**ausage **P**izza **A**way
- Physical, Data Link, Network, Transport, Session, Presentation, Application

# 7. 자주 묻는 질문들

OSI 7계층을 공부하면서 자주 나오는 질문들을 정리해 봤습니다.

> 문제 1 | 스위치는 몇 계층 장비인가요?

정답은 → **L2 (데이터링크 계층) 장비**입니다. 스위치는 MAC 주소를 보고 프레임을 전달하기 때문입니다. 단, L3 스위치는 라우팅 기능도 있어서 L3 장비이기도 합니다.

> 문제 2 | IP 주소는 몇 계층에서 사용되나요?

정답은 → **L3 (네트워크 계층)** 입니다. IP 주소는 네트워크 계층의 주소 체계입니다.

> 문제 3 | TCP와 UDP는 몇 계층 프로토콜인가요?

정답은 → **L4 (전송 계층)** 입니다. 둘 다 전송 계층의 프로토콜이며, TCP는 신뢰성을 중시하고 UDP는 속도를 중시합니다.

> 문제 4 | HTTP는 몇 계층 프로토콜인가요?

정답은 → **L7 (응용 계층)** 입니다. 웹 브라우징 서비스를 제공하는 응용 계층 프로토콜입니다.

> 문제 5 | 캡슐화는 어느 방향으로 진행되나요?

정답은 → **위에서 아래로 (7계층 → 1계층)** 입니다. 데이터를 보낼 때 각 계층을 내려가면서 헤더가 추가됩니다.

> 문제 6 | 디캡슐화는 어느 방향으로 진행되나요?

정답은 → **아래에서 위로 (1계층 → 7계층)** 입니다. 데이터를 받을 때 각 계층을 올라가면서 헤더가 제거됩니다.

> 문제 7 | MAC 주소와 IP 주소의 차이는 무엇인가요?

정답은 → **MAC 주소는 L2의 물리적 주소로 변경할 수 없고, IP 주소는 L3의 논리적 주소로 변경할 수 있습니다.** MAC 주소는 네트워크 카드에 제조 시 새겨지며, IP 주소는 네트워크 관리자가 할당하거나 DHCP로 자동 할당됩니다.

> 문제 8 | OSI 모델과 TCP/IP 모델 중 어느 것이 실제로 사용되나요?

정답은 → **TCP/IP 모델이 실제로 사용됩니다.** 인터넷은 TCP/IP 프로토콜을 기반으로 만들어졌습니다. 하지만 OSI 모델은 네트워크를 이해하고 설명하는 데 매우 유용해서 교육과 문서화에 널리 사용됩니다.

> 문제 9 | L3 스위치와 라우터의 차이는 무엇인가요?

정답은 → **L3 스위치는 스위칭이 주 기능이고 라우팅은 부가 기능이지만, 라우터는 라우팅이 주 기능입니다.** L3 스위치는 주로 내부 네트워크(LAN)에서 VLAN 간 라우팅에 사용되고, 라우터는 WAN 연결이나 인터넷 접속에 사용됩니다. 또한 라우터는 더 다양한 라우팅 프로토콜을 지원하고 WAN 인터페이스를 가지고 있습니다.

> 문제 10 | 왜 7개 계층으로 나눴나요? 3개나 5개가 아니라?

답변 → **표준을 만들 당시 네트워크 기능을 논리적으로 분류한 결과가 7개였습니다.** 너무 적게 나누면 각 계층이 너무 많은 일을 하게 되고, 너무 많이 나누면 오히려 복잡해집니다. 7개가 적절한 균형점이었던 것이죠. 실제로 TCP/IP 모델은 이것을 4개로 단순화했습니다.

# 8. 마치며

정말 긴 여정이었습니다. 하지만 이제 여러분은 OSI 7계층이 무엇인지, 왜 필요한지, 각 계층이 무엇을 하는지 확실히 이해하셨을 겁니다.

OSI 7계층은 네트워크의 ABC입니다. 이것을 확실히 이해하지 못하면 네트워크의 다른 부분들도 이해하기 어렵습니다. 하지만 반대로 OSI 7계층을 제대로 이해하면 앞으로 배울 모든 네트워크 개념들이 훨씬 쉬워질 것입니다.

**실무에서 OSI 7계층을 어떻게 활용하나요?**

1. **문제 해결**: 네트워크 문제가 생기면 1계층부터 차근차근 확인합니다.
2. **장비 선택**: 어떤 계층의 기능이 필요한지 파악하여 적절한 장비를 선택합니다.
3. **보안 설계**: 각 계층마다 적절한 보안을 적용합니다.
4. **성능 최적화**: 병목이 발생하는 계층을 찾아서 최적화합니다.
5. **의사소통**: 다른 엔지니어들과 대화할 때 "L3에서 문제가 있어요", "L7 필터링이 필요합니다" 같은 식으로 명확하게 소통할 수 있습니다.

네트워크 엔지니어로서 첫걸음을 내디뎠습니다. OSI 7계층은 여러분의 네트워크 여정에서 가장 든든한 나침반이 될 것입니다. 처음에는 복잡해 보이지만, 실무에서 몇 번 적용해 보면 자연스럽게 몸에 익게 됩니다.

네트워크의 세계는 넓고 깊습니다. 하지만 OSI 7계층이라는 확고한 기초 위에 서 있다면, 어떤 복잡한 네트워크도 이해하고 설계하고 문제를 해결할 수 있을 것입니다. 화이팅!

# 다음 장 예고

**다음 장에서는 캡슐화와 디캡슐화에 대해 배우겠습니다.**

OSI 7계층의 개념을 이해했다면, 이제 **데이터가 각 계층을 거치면서 실제로 어떻게 처리되는지**를 배워야 합니다.

**다음 장 주요 내용**:
- **캡슐화 (Encapsulation)**: 데이터를 보낼 때 각 계층에서 헤더를 추가하는 과정
  - L7~L5: Data 생성
  - L4: TCP/UDP 헤더 추가 → Segment
  - L3: IP 헤더 추가 → Packet
  - L2: MAC 헤더 추가 → Frame
  - L1: 전기 신호로 변환 → Bit
- **디캡슐화 (Decapsulation)**: 데이터를 받을 때 각 계층에서 헤더를 제거하는 과정
- **실전 예제**: 웹 브라우저로 웹사이트에 접속할 때 실제로 일어나는 일
- **프로토콜 데이터 단위 (PDU)**: 각 계층에서 다루는 데이터 형식

캡슐화와 디캡슐화를 이해하면 네트워크 문제를 해결할 때 어느 계층에서 문제가 발생했는지 정확히 파악할 수 있습니다.
