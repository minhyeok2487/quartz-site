# 1. 네트워크 장비의 설정 저장이란?

네트워크 장비를 처음 설정하다 보면 꼭 한 번쯤은 겪게 되는 실수가 있습니다. 바로 열심히 설정을 완료하고 나서 "이제 끝났다!"라고 생각하며 장비를 재부팅했는데, 다시 켜보니 모든 설정이 사라져버린 경우입니다. 이런 당황스러운 상황을 겪어보셨나요?

이것은 스위치와 라우터의 설정 저장 방식을 이해하지 못해서 발생하는 문제입니다. 시스코 장비는 두 가지 설정 저장소를 사용하는데, 이것을 제대로 이해하지 못하면 실무에서 큰 문제를 겪을 수 있습니다.

이번 장에서는 네트워크 장비의 설정이 어떻게 저장되는지, 그리고 올바르게 설정을 저장하는 방법에 대해 알아보겠습니다.

# 2. Running-config vs Startup-config

시스코 스위치와 라우터는 두 가지 설정 저장소를 가지고 있습니다. 이것을 이해하는 것이 네트워크 장비 관리의 첫걸음입니다.

## Running-config (실행 중인 설정)

Running-config는 현재 장비가 실행 중인 설정입니다. 이 설정은 **RAM(Random Access Memory)** 에 저장됩니다. RAM은 휘발성 메모리라는 특징이 있는데, 이것은 전원이 꺼지면 모든 내용이 사라진다는 의미입니다.

여러분이 스위치나 라우터에 접속해서 인터페이스 IP 주소를 변경하거나, VLAN을 생성하거나, 라우팅 프로토콜을 설정하면 이 모든 변경 사항은 즉시 Running-config에 반영됩니다. 그래서 설정을 변경하자마자 바로 동작하는 것입니다.

하지만 여기에 함정이 있습니다. Running-config는 RAM에 저장되어 있기 때문에 장비를 재부팅하거나 전원이 꺼지면 모든 설정이 사라집니다. 마치 컴퓨터에서 문서 작업을 하고 저장하지 않은 채로 프로그램을 종료하는 것과 같은 상황이죠.

## Startup-config (시작 설정)

Startup-config는 장비가 부팅될 때 불러오는 설정입니다. 이 설정은 **NVRAM(Non-Volatile RAM)** 에 저장됩니다. NVRAM은 비휘발성 메모리로, 전원이 꺼져도 내용이 유지됩니다.

장비가 재부팅되면 NVRAM에 저장된 Startup-config를 읽어와서 RAM에 로드하고, 이것이 Running-config가 됩니다. 따라서 여러분이 설정한 내용을 영구적으로 보존하려면 반드시 Running-config를 Startup-config로 저장해야 합니다.

정리하면:
- **Running-config**: 현재 실행 중인 설정 (RAM, 휘발성)
- **Startup-config**: 부팅 시 로드되는 설정 (NVRAM, 비휘발성)

> 문제 | 네트워크 장비에서 설정을 변경하면 어느 저장소에 먼저 반영되나요?

정답은 → Running-config입니다. 모든 설정 변경은 즉시 Running-config에 반영되어 바로 동작하지만, Startup-config에는 자동으로 저장되지 않습니다.

> 문제 | 설정을 저장하지 않고 장비를 재부팅하면 어떻게 되나요?

정답은 → 모든 변경 사항이 사라지고 이전 Startup-config 상태로 돌아갑니다.

# 3. 설정 저장 방법

이제 가장 중요한 부분입니다. Running-config를 Startup-config로 저장하는 방법을 알아보겠습니다. 시스코 장비에서는 여러 가지 방법을 제공하는데, 모두 같은 결과를 가져옵니다.

## 방법 1: copy 명령어 사용

가장 직관적이고 명확한 방법입니다. 이 명령은 **"Running-config를 Startup-config로 복사하라"** 는 의미를 명확하게 전달합니다.

```bash
Switch#copy running-config startup-config
Destination filename [startup-config]? (Enter 키 입력)
Building configuration...
[OK]
```

명령을 실행하면 목적지 파일 이름을 확인하는 메시지가 나타납니다. 대부분의 경우 기본값인 `startup-config`를 그대로 사용하므로 그냥 Enter 키를 누르면 됩니다.

## 방법 2: write 명령어 사용

예전부터 사용되어 온 전통적인 방법입니다. 더 짧고 빠르게 입력할 수 있다는 장점이 있습니다.

```bash
Switch#write
Building configuration...
[OK]
```

또는

```bash
Switch#write memory
Building configuration...
[OK]
```

`write`와 `write memory`는 동일한 명령입니다. 더 짧게 줄여서 다음과 같이 사용할 수도 있습니다:

```bash
Switch#wr
```

시스코 IOS는 명령어 자동 완성 기능을 제공하므로 `wr`만 입력해도 `write` 명령으로 인식합니다.

## 방법 3: 축약형 명령어

시스코 IOS의 자동 완성 기능을 활용하면 더욱 빠르게 입력할 수 있습니다.

```bash
Switch#copy run start
Destination filename [startup-config]? (Enter 키 입력)
Building configuration...
[OK]
```

`running-config`는 `run`으로, `startup-config`는 `start`로 축약할 수 있습니다. 이 방법은 타이핑을 줄이고 싶을 때 매우 유용합니다.

## 어떤 방법을 사용해야 할까?

세 가지 방법 모두 동일한 결과를 만들어내므로, 자신에게 가장 편한 방법을 선택하면 됩니다.

- **copy running-config startup-config**: 명확하고 직관적, 초보자에게 추천
- **write 또는 wr**: 빠르고 간단, 숙련자에게 추천
- **copy run start**: 타이핑을 줄이고 싶을 때 추천

저는 개인적으로 `copy run start`를 자주 사용합니다. 충분히 이해하기 쉬우면서도 타이핑이 짧기 때문입니다.

# 4. 설정 확인 방법

설정을 저장했다면 제대로 저장되었는지 확인하는 것이 중요합니다. 또한 현재 동작 중인 설정과 저장된 설정을 비교해볼 필요도 있습니다.

## 현재 실행 중인 설정 보기

```bash
Switch#show running-config
```

또는 축약형으로:

```bash
Switch#show run
```

이 명령을 실행하면 현재 RAM에 있는 모든 설정이 화면에 표시됩니다. 인터페이스 설정, VLAN 설정, 라우팅 프로토콜 설정 등 모든 내용을 볼 수 있습니다.

예를 들어 다음과 같은 출력을 볼 수 있습니다:

```bash
Switch#show run
Building configuration...

Current configuration : 1234 bytes
!

service timestamps debug datetime msec
service timestamps log datetime msec
no service password-encryption
!

!

 switchport access vlan 10
 switchport mode access
!
interface FastEthernet0/2
 switchport access vlan 20
 switchport mode access
!
vlan 10

!
vlan 20

!
line con 0
line vty 0 4

!
end
```

## 저장된 설정 보기

```bash
Switch#show startup-config
```

또는 축약형으로:

```bash
Switch#show start
```

이 명령은 NVRAM에 저장된 설정을 보여줍니다. 장비를 재부팅하면 바로 이 설정이 로드됩니다.

만약 Running-config를 수정한 후 아직 저장하지 않았다면, `show running-config`와 `show startup-config`의 출력이 다를 것입니다. 이것은 정상적인 현상이며, 변경 사항을 영구적으로 보존하려면 반드시 저장해야 한다는 것을 의미합니다.

## 두 설정 비교하기

일부 IOS 버전에서는 두 설정을 직접 비교할 수 있는 명령을 제공합니다.

```bash
Switch#show archive config differences
```

이 명령은 Running-config와 Startup-config의 차이점을 보여줍니다. 어떤 부분이 변경되었는지 한눈에 확인할 수 있어서 매우 유용합니다.

# 5. 실무에서의 활용

실제 네트워크 관리 업무에서는 다음과 같은 작업 흐름을 따르는 것이 좋습니다:

**1단계: 설정 변경 전 백업**

```bash
Switch#show running-config
(현재 설정을 복사해서 텍스트 파일로 저장)
```

중요한 변경을 하기 전에는 항상 현재 설정을 백업해두는 것이 좋습니다. 문제가 발생했을 때 빠르게 복구할 수 있습니다.

**2단계: 설정 변경**

```bash
Switch#configure terminal
Switch(config)#interface fastEthernet 0/1
Switch(config-if)#switchport access vlan 10
Switch(config-if)#exit
Switch(config)#exit
```

필요한 설정을 변경합니다.

**3단계: 동작 확인**

```bash
Switch#show running-config
Switch#show interfaces fastEthernet 0/1 switchport
```

변경한 설정이 올바르게 동작하는지 확인합니다.

**4단계: 설정 저장**

```bash
Switch#copy run start
Destination filename [startup-config]? (Enter)
Building configuration...
[OK]
```

모든 것이 정상적으로 동작한다면 설정을 저장합니다.

**5단계: 저장 확인**

```bash
Switch#show startup-config
```

저장된 설정을 확인하여 올바르게 저장되었는지 검증합니다.

## 주의사항
1. **저장하지 않은 채로 재부팅하지 마세요**: 많은 초보자들이 이 실수를 합니다. 설정을 변경한 후에는 반드시 저장하는 습관을 들이세요.

2. **테스트 환경에서 먼저 시도하세요**: 운영 중인 장비에서 직접 설정을 변경하기 전에 테스트 환경에서 먼저 검증하는 것이 좋습니다.

3. **원격 접속 시 주의하세요**: 원격으로 장비에 접속해서 설정을 변경할 때는 특히 조심해야 합니다. 잘못된 설정으로 인해 네트워크 연결이 끊어지면 장비에 접근할 수 없게 됩니다.

4. **정기적으로 백업하세요**: 중요한 장비의 설정은 정기적으로 백업해서 별도로 보관하는 것이 좋습니다.

# 6. 설정 초기화 (추가 팁)

만약 잘못된 설정으로 인해 장비가 제대로 동작하지 않는다면 설정을 초기화할 수 있습니다.

## Startup-config 삭제

```bash
Switch#erase startup-config
Erasing the nvram filesystem will remove all configuration files! Continue? [confirm] (Enter)
[OK]
Erase of nvram: complete
```

이 명령은 NVRAM에 저장된 Startup-config를 삭제합니다. 하지만 Running-config는 그대로 남아있으므로 장비는 계속 동작합니다.

## 장비 재부팅

```bash
Switch#reload
Proceed with reload? [confirm] (Enter)
```

장비를 재부팅하면 Startup-config가 없으므로 공장 초기화 상태로 시작됩니다.

이렇게 해서 네트워크 장비의 설정 저장 방법에 대해 알아보았습니다. 이것은 네트워크 엔지니어가 반드시 알아야 하는 기본 중의 기본입니다. Running-config와 Startup-config의 차이를 명확히 이해하고, 설정을 변경한 후에는 반드시 저장하는 습관을 들이기 바랍니다. 이 작은 습관이 실무에서 큰 문제를 예방할 수 있습니다.
