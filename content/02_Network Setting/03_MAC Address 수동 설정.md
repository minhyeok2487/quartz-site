# 1. MAC Address 수동 설정이란?

네트워크 장비를 운영하다 보면 가끔 특별한 상황에 맞닥뜨리게 됩니다. 예를 들어, 오래된 라우터가 고장 나서 새 라우터로 교체해야 하는데, ISP(인터넷 서비스 공급자)가 기존 라우터의 MAC 주소로 연결을 인증하고 있다면 어떻게 될까요? 새 라우터를 연결했는데 MAC 주소가 달라서 인터넷이 되지 않는 상황이 발생할 수 있습니다.

이럴 때 필요한 것이 바로 **MAC Address 수동 설정**입니다. 이것은 네트워크 인터페이스의 MAC 주소를 직접 지정하는 기능으로, **MAC Address Cloning(MAC 주소 복제)** 라고도 불립니다.

이번 장에서는 시스코 라우터에서 MAC 주소를 수동으로 설정하는 방법과, 이 기능이 실무에서 어떻게 활용되는지 알아보겠습니다.

# 2. 왜 MAC 주소를 변경해야 할까?

MAC 주소는 일반적으로 제조사가 하드웨어에 영구적으로 할당한 고유 식별자입니다. 그런데 왜 이것을 변경해야 할까요?

## 주요 사용 사례

**1. 장비 교체 시 서비스 연속성 유지**

많은 ISP들은 보안과 관리를 위해 특정 MAC 주소로만 인터넷 연결을 허용합니다. 기존 라우터가 고장 나서 새 라우터로 교체할 때, ISP에 연락해서 새로운 MAC 주소를 등록하는 대신, 새 라우터의 MAC 주소를 기존 것과 동일하게 설정하면 즉시 서비스를 복구할 수 있습니다.

**2. MAC 주소 기반 인증 우회**

일부 네트워크에서는 MAC 주소를 기반으로 접근 제어를 합니다. 정당한 사유로 특정 MAC 주소가 필요한 경우, 이 기능을 사용할 수 있습니다.

**3. 네트워크 테스트 및 문제 해결**

네트워크 문제를 진단할 때, 특정 MAC 주소로 동작을 테스트해야 하는 경우가 있습니다.

> 문제 | MAC 주소는 하드웨어에 고정되어 있는데 어떻게 변경이 가능한가요?

정답은 → 하드웨어의 물리적 MAC 주소(Burned-In Address, BIA)는 변경되지 않습니다. 대신 라우터가 실제로 사용하는 MAC 주소를 소프트웨어적으로 재정의하는 것입니다. 하드웨어 MAC 주소는 그대로 남아있지만, 네트워크 통신에는 새로 설정한 MAC 주소가 사용됩니다.

# 3. MAC 주소 수동 설정 방법

이제 실제로 시스코 라우터에서 MAC 주소를 수동으로 설정하는 방법을 알아보겠습니다.

## 기본 설정 명령어

MAC 주소를 변경하려면 먼저 해당 인터페이스의 설정 모드로 들어가야 합니다.

```bash
R1#configure terminal
R1(config)#interface ethernet 0
R1(config-if)#mac-address ?
  H.H.H  MAC address
```

여기서 `mac-address` 명령어 뒤에 물음표(`?`)를 입력하면 MAC 주소 형식을 확인할 수 있습니다. 시스코 장비에서는 **H.H.H** 형식을 사용하는데, 이것은 16진수를 4자리씩 점(.)으로 구분하는 방식입니다.

## MAC 주소 설정하기

이제 실제로 MAC 주소를 설정해보겠습니다.

```bash
R1(config-if)#mac-address 003e.1111.1111
R1(config-if)#end
R1#
```

이렇게 하면 Ethernet 0 인터페이스의 MAC 주소가 `003e.1111.1111`로 변경됩니다.

## MAC 주소 형식 이해하기

MAC 주소는 48비트(6바이트)로 구성되어 있으며, 시스코 형식에서는:
- **003e.1111.1111**처럼 표기합니다
- 12개의 16진수 문자를 4개씩 점으로 구분합니다
- 다른 시스템에서는 **00:3E:11:11:11:11** 또는 **00-3E-11-11-11-11** 형식을 사용하기도 합니다

> 문제 | MAC 주소 003e.1111.1111을 콜론(:) 형식으로 표현하면?

정답은 → 00:3E:11:11:11:11 입니다. 형식만 다를 뿐 동일한 MAC 주소를 나타냅니다.

# 4. 설정 확인 방법

MAC 주소를 변경한 후에는 제대로 적용되었는지 확인해야 합니다.

## 인터페이스 정보 확인

```bash
R1#show interfaces ethernet 0
Ethernet0 is up, line protocol is up
  Hardware is AmdP2, address is 003e.1111.1111 (bia 0050.0f0a.0001)
  Internet address is 192.168.1.1/24
  MTU 1500 bytes, BW 10000 Kbit/sec, DLY 1000 usec,
     reliability 255/255, txload 1/255, rxload 1/255
```

출력에서 주목해야 할 부분:
- **address is 003e.1111.1111**: 현재 사용 중인 MAC 주소 (우리가 설정한 값)
- **bia 0050.0f0a.0001**: Burned-In Address, 즉 하드웨어에 원래 할당된 MAC 주소

이것을 보면 하드웨어의 원래 MAC 주소는 그대로 유지되지만, 실제 통신에는 우리가 설정한 MAC 주소가 사용되는 것을 확인할 수 있습니다.

## MAC 주소 테이블 확인

스위치에 연결된 경우, 스위치의 MAC 주소 테이블을 확인하면 변경된 MAC 주소가 학습된 것을 볼 수 있습니다.

```bash
Switch#show mac address-table
          Mac Address Table
-------------------------------------------
Vlan    Mac Address       Type        Ports
----    -----------       --------    -----
   1    003e.1111.1111    DYNAMIC     Fa0/1
```

# 5. 실무에서의 활용 시나리오

실제 네트워크 관리 현장에서 MAC 주소 수동 설정이 어떻게 활용되는지 살펴보겠습니다.

## 시나리오: ISP 라우터 교체

**상황**: 회사의 인터넷 게이트웨이 라우터가 고장났습니다. ISP는 기존 라우터의 MAC 주소 `0012.3456.789a`로 연결을 인증하고 있습니다.

**해결 과정**:

1. 기존 라우터의 MAC 주소를 확인합니다 (문서에서 또는 백업 설정에서)
2. 새 라우터를 설치하고 기본 설정을 진행합니다
3. WAN 인터페이스에 기존 MAC 주소를 설정합니다:

```bash
Router(config)#interface gigabitEthernet 0/0
Router(config-if)#mac-address 0012.3456.789a
Router(config-if)#ip address dhcp  # 또는 고정 IP 설정
Router(config-if)#no shutdown
Router(config-if)#end
Router#copy run start
```

4. ISP 측에서는 변경 사항을 인식하지 못하고 즉시 서비스가 복구됩니다

이 방법을 사용하면 ISP에 연락해서 새 MAC 주소를 등록하는 시간을 절약할 수 있으며, 서비스 중단 시간을 최소화할 수 있습니다.

## 주의사항

**1. 네트워크에 중복 MAC 주소가 없도록 주의하세요**

동일한 네트워크에 같은 MAC 주소를 가진 장비가 두 개 이상 있으면 심각한 통신 문제가 발생합니다. 기존 라우터를 교체할 때는 반드시 기존 장비를 네트워크에서 완전히 제거한 후 새 장비를 연결해야 합니다.

**2. 설정은 반드시 저장하세요**

MAC 주소 변경도 Running-config에만 적용되므로, 설정 후 반드시 `copy run start`로 저장해야 합니다.

**3. 정당한 목적으로만 사용하세요**

MAC 주소 변경은 강력한 기능이지만, 부적절하게 사용하면 보안 정책을 우회하거나 다른 장비로 위장하는 데 악용될 수 있습니다. 항상 정당한 관리 목적으로만 사용해야 합니다.

**4. 문서화하세요**

MAC 주소를 변경한 경우, 반드시 네트워크 문서에 기록해두어야 합니다. 나중에 문제가 발생했을 때 원인을 파악하기 어려울 수 있습니다.

# 6. MAC 주소 원래대로 되돌리기

설정한 MAC 주소를 제거하고 하드웨어 기본값으로 돌아가고 싶다면 다음과 같이 합니다.

```bash
R1(config)#interface ethernet 0
R1(config-if)#no mac-address
R1(config-if)#end
```

`no mac-address` 명령을 사용하면 수동으로 설정한 MAC 주소가 제거되고, 하드웨어의 BIA(Burned-In Address)가 다시 사용됩니다.

## 변경 확인

```bash
R1#show interfaces ethernet 0
Ethernet0 is up, line protocol is up
  Hardware is AmdP2, address is 0050.0f0a.0001 (bia 0050.0f0a.0001)
```

이제 address와 bia가 동일한 것을 확인할 수 있습니다. 이것은 하드웨어의 원래 MAC 주소를 사용하고 있다는 의미입니다.

# 7. 마치며

MAC 주소 수동 설정은 네트워크 관리자가 알아두면 유용한 기술입니다. 특히 장비 교체 상황에서 서비스 중단 시간을 최소화할 수 있는 강력한 도구가 됩니다.

하지만 이 기능은 신중하게 사용해야 합니다. 잘못 사용하면 네트워크에 중복 MAC 주소 문제를 일으켜 심각한 통신 장애를 유발할 수 있습니다. 항상 변경 전에 계획을 세우고, 변경 후에는 확인 절차를 거치며, 모든 내용을 문서화하는 습관을 들이시기 바랍니다.
