# 1. MAC Address Aging이란?

스위치를 운영하다 보면 한 가지 의문이 생길 수 있습니다. 스위치는 네트워크에 연결된 모든 장비의 MAC 주소를 학습해서 테이블에 저장한다고 배웠는데, 그렇다면 한 번 학습한 MAC 주소는 영원히 저장되는 걸까요? 만약 그렇다면 스위치의 메모리는 언젠가 가득 차지 않을까요?

바로 이런 문제를 해결하기 위해 **MAC Address Aging(MAC 주소 에이징)** 이라는 개념이 있습니다. 이것은 스위치가 일정 시간 동안 사용되지 않는 MAC 주소를 테이블에서 자동으로 제거하는 메커니즘입니다.

스위치가 학습한 MAC 주소들은 RAM(메모리)에 저장됩니다. 메모리는 한정된 자원이기 때문에 무한정 정보를 저장할 수 없습니다. 따라서 더 이상 사용되지 않는 정보는 제거하여 메모리를 효율적으로 관리해야 합니다.

이번 장에서는 MAC Address Aging이 무엇인지, 왜 필요한지, 그리고 어떻게 설정하는지 알아보겠습니다.

# 2. 왜 Aging Time이 필요한가?

MAC Address Table을 효율적으로 관리하지 않으면 여러 가지 문제가 발생할 수 있습니다. 이것을 이해하기 위해 실제 상황을 생각해보겠습니다.

## 메모리 낭비 문제

대형 네트워크 환경을 생각해보세요. 하루에 수백, 수천 개의 장비가 네트워크에 연결되고 연결이 끊어집니다. 노트북을 들고 회사에 출근한 직원, 회의실에서 사용한 태블릿, 방문객의 스마트폰 등 모든 장비의 MAC 주소가 스위치에 학습됩니다.

만약 스위치가 한 번 학습한 MAC 주소를 영원히 보관한다면:
- **메모리 공간이 낭비됩니다**: 더 이상 네트워크에 없는 장비의 정보까지 계속 저장하게 됩니다
- **성능이 저하됩니다**: MAC Address Table의 크기가 커지면 스위치가 목적지를 찾는 데 더 많은 시간이 걸립니다
- **메모리 고갈**: 결국 메모리가 가득 차서 새로운 MAC 주소를 학습할 수 없게 됩니다

## Aging 메커니즘의 작동 방식

이러한 문제를 해결하기 위해 스위치는 **일정 시간 동안 참조되지 않는 MAC 주소들을 MAC Address Table에서 자동으로 제거**합니다. 이것을 Aging(에이징, 노화)이라고 부릅니다.

작동 방식은 간단합니다:
1. 스위치가 MAC 주소를 학습하면 타이머를 시작합니다
2. 해당 MAC 주소와 관련된 트래픽이 발생할 때마다 타이머가 리셋됩니다
3. 설정된 시간(Aging Time) 동안 해당 MAC 주소와 관련된 트래픽이 없으면 테이블에서 제거됩니다
4. 나중에 해당 장비가 다시 통신하면 스위치가 다시 학습합니다

> 문제 | 노트북을 들고 출근한 직원이 점심시간에 노트북을 닫고 외출했습니다. 한 시간 후 돌아와서 노트북을 다시 켰을 때 스위치는 어떻게 동작할까요?

정답은 → Aging Time이 기본값(300초, 5분)이라면 노트북이 닫혀있는 동안 MAC 주소가 테이블에서 제거되었을 것입니다. 노트북이 다시 켜지고 네트워크 트래픽이 발생하면 스위치는 다시 MAC 주소를 학습합니다. 이것은 자연스러운 과정이며 사용자는 아무것도 느끼지 못합니다.

# 3. Aging Time 설정의 딜레마

Aging Time을 설정할 때는 신중해야 합니다. 너무 짧게 설정해도 문제고, 너무 길게 설정해도 문제가 있기 때문입니다.

## Aging Time이 너무 짧은 경우

Aging Time을 너무 짧게 설정하면(예: 10초) 다음과 같은 문제가 발생합니다:

**Unknown Unicast Flooding 빈번 발생**

짧은 Aging Time은 정상적으로 통신 중인 장비의 MAC 주소까지 테이블에서 제거할 수 있습니다. 예를 들어, 두 컴퓨터가 통신하고 있는데 잠깐 통신이 멈춘 사이에 MAC 주소가 제거되면, 다음 패킷이 도착했을 때 스위치는 목적지를 모르게 됩니다. 그러면 스위치는 해당 프레임을 모든 포트로 flooding해야 합니다.

**네트워크 효율 저하**

스위치가 자주 MAC 주소를 재학습해야 하므로 불필요한 flooding이 증가하고, 이것은 네트워크 대역폭을 낭비하며 전체적인 성능을 저하시킵니다.

## Aging Time이 너무 긴 경우

반대로 Aging Time을 너무 길게 설정하면(예: 3600초, 1시간):

**메모리 낭비**

이미 네트워크를 떠난 장비들의 MAC 주소가 오래도록 테이블에 남아있어 메모리를 낭비합니다.

**MAC Address Table 크기 증가**

테이블의 크기가 불필요하게 커져서 검색 시간이 증가하고 스위치 성능에 영향을 줄 수 있습니다.

## 적절한 균형 찾기

시스코 스위치의 **기본 Aging Time은 300초(5분)** 입니다. 이것은 대부분의 환경에서 적절한 값으로 검증되었습니다. 하지만 특수한 환경에서는 조정이 필요할 수 있습니다:

- **매우 동적인 환경** (많은 장비가 자주 연결/해제): 조금 짧게 설정 (예: 180초, 3분)
- **안정적인 환경** (고정된 장비들이 대부분): 조금 길게 설정 (예: 600초, 10분)

> 문제 | Aging Time을 0초로 설정하면 어떻게 될까요?

정답은 → Aging 기능이 완전히 비활성화됩니다. MAC Address Table에서 항목이 자동으로 제거되지 않으며, 수동으로 clear 명령을 실행하지 않는 한 영구적으로 유지됩니다. 이것은 특별한 상황(예: 매우 안정적이고 장비 변동이 거의 없는 폐쇄 네트워크)에서만 사용해야 합니다.

# 4. MAC Address Aging Time 설정 방법

이제 실제로 Aging Time을 설정하는 방법을 알아보겠습니다.

## 전역 Aging Time 설정

모든 VLAN에 동일한 Aging Time을 적용하려면:

```bash
Switch#configure terminal
Switch(config)#mac address-table aging-time 240
Switch(config)#end
```

이 명령은 전역적으로 Aging Time을 240초(4분)로 설정합니다.

## 특정 VLAN의 Aging Time 설정

특정 VLAN에만 다른 Aging Time을 적용할 수 있습니다. 예를 들어, VLAN 5의 Aging Time을 500초로 설정해보겠습니다.

```bash
IOU1#configure terminal
IOU1(config)#mac address-table aging-time 500 vlan 5
IOU1(config)#end
```

이렇게 하면 VLAN 5는 500초의 Aging Time을 가지고, 다른 VLAN들은 전역 설정값을 사용합니다.

## 설정 확인

설정한 Aging Time을 확인하는 방법은 여러 가지가 있습니다.

**전체 Aging Time 확인**

```bash
IOU1#show mac address-table aging-time
Global Aging Time:  300
Vlan    Aging Time
----    ----------
```

**특정 VLAN의 Aging Time 확인**

```bash
IOU1#show mac address-table aging-time vlan 5
Global Aging Time:  300
Vlan    Aging Time
----    ----------
   5     500
```

이 출력을 보면:
- **Global Aging Time: 300**: 전역 기본값은 300초
- **Vlan 5: 500**: VLAN 5는 개별적으로 500초로 설정됨

> 문제 | VLAN 10에 별도로 Aging Time을 설정하지 않았다면 어떤 값이 사용될까요?

정답은 → Global Aging Time인 300초가 사용됩니다. 개별 VLAN에 특정 값을 설정하지 않으면 전역 설정값이 적용됩니다.

## Aging 기능 비활성화

특별한 경우에 Aging 기능을 완전히 비활성화할 수 있습니다:

```bash
Switch(config)#mac address-table aging-time 0
```

이렇게 설정하면 MAC 주소가 자동으로 제거되지 않습니다.

# 5. Unknown Unicast Flooding 이해하기

Aging Time을 설정할 때 가장 중요한 개념 중 하나가 **Unknown Unicast Flooding**입니다. 이것은 Aging Time과 직접적인 관계가 있으므로 제대로 이해해야 합니다.

## Unknown Unicast Flooding이란?

**Unknown Unicast Flooding**은 스위치가 목적지 MAC 주소를 MAC Address Table에서 찾지 못했을 때, 해당 프레임을 수신 포트를 제외한 모든 포트로 flooding(전송)하는 현상입니다.

## 왜 발생하는가?

다음과 같은 상황에서 발생합니다:

**1. MAC 주소가 아직 학습되지 않은 경우**

새로운 장비가 네트워크에 연결되었지만 아직 아무런 트래픽을 보내지 않았을 때, 다른 장비가 이 새로운 장비에게 패킷을 보내려고 하면 스위치는 목적지를 모르므로 flooding합니다.

**2. MAC 주소가 Aging되어 제거된 경우**

Aging Time이 지나서 MAC 주소가 테이블에서 제거되었을 때, 해당 장비로 가는 패킷이 도착하면 스위치는 다시 flooding해야 합니다.

## Aging Time과의 관계

이제 왜 Aging Time 설정이 중요한지 명확해집니다:

**Aging Time이 너무 짧으면:**
- 정상적으로 통신 중인 장비의 MAC 주소까지 자주 제거됨
- Unknown Unicast Flooding이 빈번하게 발생
- 불필요한 트래픽 증가로 네트워크 성능 저하

**Aging Time이 적절하면:**
- 실제로 떠난 장비의 MAC 주소만 제거됨
- Unknown Unicast Flooding이 최소화됨
- 메모리도 효율적으로 관리됨

## 예시 시나리오

컴퓨터 A(MAC: aaaa.aaaa.aaaa)와 컴퓨터 B(MAC: bbbb.bbbb.bbbb)가 파일 전송을 하고 있다고 가정해봅시다.

**Aging Time이 30초로 설정된 경우:**
1. A와 B가 통신하면서 MAC 주소가 학습됨
2. 파일 전송 중 40초간 A에서 B로 가는 트래픽이 없었음 (B에서 A로는 계속 ACK 전송)
3. 30초가 지나면서 스위치는 B의 MAC 주소를 제거함 (B에서 트래픽이 없었으므로)
4. A가 다시 B에게 데이터를 보내려 하면 스위치는 B의 위치를 모르므로 모든 포트로 flooding
5. B가 응답하면 스위치가 다시 B의 MAC 주소를 학습
6. 이 과정이 계속 반복됨 → 비효율적!

**Aging Time이 300초(5분)로 설정된 경우:**
1. A와 B가 통신하면서 MAC 주소가 학습됨
2. 파일 전송 중 40초간 A에서 B로 가는 트래픽이 없었음
3. Aging Time이 300초이므로 MAC 주소는 유지됨
4. A가 다시 B에게 데이터를 보낼 때 스위치는 정확히 B의 포트로 전송
5. 효율적인 통신!

# 6. 실무에서의 활용

실제 네트워크 환경에서 Aging Time을 어떻게 설정해야 하는지 몇 가지 시나리오를 살펴보겠습니다.

## 시나리오 1: 사무실 네트워크

**환경**: 직원들이 노트북을 사용하며 하루에 여러 번 연결/해제

**권장 설정**: 기본값 300초 유지

대부분의 직원들은 출근해서 노트북을 연결하고 퇴근할 때 연결을 해제합니다. 300초는 점심시간이나 짧은 회의 중에도 MAC 주소가 유지되기에 충분합니다.

## 시나리오 2: 데이터센터

**환경**: 서버들이 고정적으로 연결되어 있으며 거의 변동이 없음

**권장 설정**: 600초(10분) 또는 그 이상

데이터센터의 서버들은 24시간 켜져있고 지속적으로 통신합니다. 긴 Aging Time을 설정해도 메모리 문제가 발생하지 않으며, MAC 주소 재학습 빈도를 줄일 수 있습니다.

```bash
DataCenter-SW(config)#mac address-table aging-time 600
```

## 시나리오 3: 게스트 네트워크

**환경**: 방문객들이 자주 연결하고 해제하는 VLAN

**권장 설정**: VLAN별로 180초(3분)

게스트 네트워크는 장비 변동이 많으므로 더 짧은 Aging Time이 적절합니다. 떠난 방문객의 MAC 주소를 빨리 제거하여 메모리를 효율적으로 사용할 수 있습니다.

```bash
Office-SW(config)#mac address-table aging-time 180 vlan 100
```

여기서 VLAN 100이 게스트 네트워크라고 가정합니다.

## 시나리오 4: 무선 네트워크

**환경**: WiFi 접속 포인트가 연결된 스위치

**권장 설정**: 기본값 300초 유지 또는 약간 짧게(240초)

무선 장비들은 자주 연결이 끊어졌다 다시 연결되는 특성이 있습니다. 너무 긴 Aging Time은 이미 연결이 끊어진 장비들의 MAC 주소를 오래 보관하게 됩니다.

## 주의사항

**1. 환경에 맞게 조정하세요**

모든 네트워크가 다르므로, 자신의 환경을 관찰하고 그에 맞게 조정해야 합니다. 기본값으로 시작해서 문제가 있을 때만 변경하는 것이 좋습니다.

**2. 변경 사항을 모니터링하세요**

Aging Time을 변경한 후에는 다음을 모니터링해야 합니다:
- MAC Address Table의 크기 변화
- Unknown Unicast 트래픽 발생 빈도
- 전반적인 네트워크 성능

**3. 설정을 저장하세요**

Aging Time 설정도 Running-config에만 적용되므로 반드시 저장해야 합니다:

```bash
Switch#copy run start
```

**4. 문서화하세요**

기본값에서 변경한 경우, 왜 변경했는지 이유를 문서에 기록해두어야 합니다. 나중에 다른 관리자가 보거나 문제 해결할 때 도움이 됩니다.

# 7. MAC Address Table 관리 명령어

Aging과 관련하여 유용한 추가 명령어들을 알아보겠습니다.

## MAC Address Table 보기

```bash
Switch#show mac address-table
          Mac Address Table
-------------------------------------------
Vlan    Mac Address       Type        Ports
----    -----------       --------    -----
   1    0050.7966.6800    DYNAMIC     Fa0/1
   1    0050.7966.6801    DYNAMIC     Fa0/2
   5    0050.7966.6802    DYNAMIC     Fa0/5
```

## 특정 VLAN의 MAC Address 보기

```bash
Switch#show mac address-table vlan 5
```

## MAC Address Table 수동 삭제

특정 상황에서 MAC Address Table을 수동으로 지워야 할 때가 있습니다:

**모든 동적 MAC 주소 삭제**

```bash
Switch#clear mac address-table dynamic
```

**특정 VLAN의 MAC 주소만 삭제**

```bash
Switch#clear mac address-table dynamic vlan 5
```

**특정 인터페이스의 MAC 주소 삭제**

```bash
Switch#clear mac address-table dynamic interface fastEthernet 0/1
```

이 명령들은 문제 해결 시 유용하게 사용됩니다.

# 8. 마치며

MAC Address Aging은 스위치가 한정된 메모리 자원을 효율적으로 관리하기 위한 중요한 메커니즘입니다. 적절한 Aging Time 설정은 네트워크 성능과 직결되는 문제입니다.

핵심을 정리하면:
- **Aging Time은 스위치 메모리 효율과 네트워크 성능의 균형점**입니다
- **너무 짧으면** Unknown Unicast Flooding이 빈번해지고 성능이 저하됩니다
- **너무 길면** 메모리가 낭비되고 MAC Address Table 크기가 불필요하게 커집니다
- **기본값 300초(5분)** 는 대부분의 환경에서 적절합니다
- **환경에 따라** VLAN별로 다른 Aging Time을 설정할 수 있습니다

네트워크를 처음 설정할 때는 기본값을 사용하고, 실제 운영하면서 모니터링 결과를 바탕으로 필요한 경우에만 조정하는 것이 좋습니다. 그리고 변경할 때는 반드시 그 이유를 문서화하고, 변경 후 충분한 시간 동안 모니터링하여 예상치 못한 문제가 없는지 확인해야 합니다.

이렇게 해서 MAC Address Aging에 대해 알아보았습니다. 이것은 눈에 보이지 않지만 스위치가 효율적으로 동작하도록 만드는 중요한 기능입니다. 이해하고 나면 네트워크를 더욱 효과적으로 관리할 수 있을 것입니다.
