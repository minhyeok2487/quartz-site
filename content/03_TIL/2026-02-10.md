# CCNP Enterprise Lab - Step 1: L2 통신 확인

**관련 문서:** [[06_VTP(VLAN Trunking Protocol)|VTP(VLAN Trunking Protocol)]] · [[05_STP(Spanning Tree Protocol)|STP(Spanning Tree Protocol)]] · [[06_Router-on-a-Stick과 Inter-VLAN 라우팅|Inter-VLAN 라우팅]]

---

## 목표

같은 VLAN(10)에 있는 두 PC가 Trunk를 거쳐 서로 통신되는 것을 확인한다.

## 환경

- GNS3
- 스위치: Cisco IOU L2 15.2d × 2대
- PC: VPCS × 2대

## 토폴로지

```
[PC1] ── e0/1 ── [CORE-SW1] ── e0/0 ──── e0/0 ── [CORE-SW2] ── e0/1 ── [PC2]
10.1.10.101        Trunk(dot1q)          Trunk(dot1q)        10.1.10.102
                    VLAN 10                                    VLAN 10
```

## 포트 할당

|장비|포트|역할|모드|
|---|---|---|---|
|CORE-SW1|e0/0|스위치 간 연결|Trunk|
|CORE-SW1|e0/1|PC1 연결|Access (VLAN 10)|
|CORE-SW2|e0/0|스위치 간 연결|Trunk|
|CORE-SW2|e0/1|PC2 연결|Access (VLAN 10)|

## IP 할당

|장비|IP|Subnet|
|---|---|---|
|PC1|10.1.10.101|255.255.255.0|
|PC2|10.1.10.102|255.255.255.0|

---

## 설정

### CORE-SW1

```
enable
conf t
hostname CORE-SW1

vlan 10
 name Sales
exit

interface e0/0
 switchport trunk encapsulation dot1q
 switchport mode trunk
 no shutdown

interface e0/1
 switchport mode access
 switchport access vlan 10
 no shutdown
end
wr mem
```

### CORE-SW2

```
enable
conf t
hostname CORE-SW2

vlan 10
 name Sales
exit

interface e0/0
 switchport trunk encapsulation dot1q
 switchport mode trunk
 no shutdown

interface e0/1
 switchport mode access
 switchport access vlan 10
 no shutdown
end
wr mem
```

### PC1 (VPCS)

```
ip 10.1.10.101 255.255.255.0
```

### PC2 (VPCS)

```
ip 10.1.10.102 255.255.255.0
```

---

## 트러블슈팅

### 증상

PC1에서 `ping 10.1.10.102` 실패 — "host not reachable"

### 진단 과정

**1단계: CORE-SW1에서 VLAN 확인**

```
CORE-SW1# show vlan brief
```

- 결과: VLAN 10 생성됨, e0/1이 VLAN 10에 할당됨 → 정상

**2단계: CORE-SW1에서 Trunk 확인**

```
CORE-SW1# show interfaces trunk
```

- 발견: Trunk 모드가 `auto`로 되어 있었음 → `on`으로 명시적 설정 필요
- 발견: STP forwarding VLAN이 `none` → VLAN 10 트래픽이 차단되고 있었음

**3단계: Trunk 모드 재설정**

```
conf t
interface e0/0
 switchport trunk encapsulation dot1q
 switchport mode trunk
end
```

**4단계: CORE-SW2 확인**

```
CORE-SW2# show vlan brief
CORE-SW2# show interfaces trunk
```

- 결과: VLAN 10 존재, Trunk 정상 동작, STP forwarding VLAN 1,10 확인

**5단계: CORE-SW1 STP 상태 확인**

```
CORE-SW1# show spanning-tree vlan 10
```

- 결과: CORE-SW1이 Root Bridge, e0/0 Designated FWD 상태 → 정상

### 원인

**STP 수렴(convergence) 지연.** 설정 직후 STP가 아직 Forwarding 상태로 전환되지 않은 상태에서 ping을 시도했기 때문. RSTP라도 포트 상태 전환에 시간이 소요된다. 수렴 완료 후 ping 성공.

### 교훈

- Trunk 모드는 `auto`에 의존하지 말고 **명시적으로 `mode trunk` 설정**할 것
- 설정 직후 통신 안 될 때는 **STP 수렴 시간을 고려**할 것
- Access 포트에 **PortFast**를 적용하면 STP 대기 시간 제거 가능 (추후 적용 예정)
- `show vlan brief`, `show interfaces trunk`, `show spanning-tree vlan X`는 L2 트러블슈팅 기본 3종 세트

---

## 검증 결과

```
PC1> ping 10.1.10.102
84 bytes from 10.1.10.102 icmp_seq=1 ttl=64 time=0.001 ms
```

**✅ Step 1 완료 — 같은 VLAN L2 통신 성공**

# CCNP Enterprise Lab - Step 2: VLAN 격리 확인 & STP Dispute 트러블슈팅

## 목표

서로 다른 VLAN(10, 20)에 있는 PC끼리는 통신이 안 되는 것을 확인한다.

## 환경

- GNS3
- 스위치: Cisco IOU L2 15.2d × 2대
- PC: VPCS × 3대

## 토폴로지

```
[PC1] ── e0/1 ── [CORE-SW1] ══ e0/0 ══ [CORE-SW2] ── e0/1 ── [PC2]
VLAN 10              Trunk                              VLAN 10
10.1.10.101                                             10.1.10.102

                                         [CORE-SW2] ── e0/2 ── [PC3]
                                                        VLAN 20
                                                        10.1.20.101
```

## 추가 설정

### CORE-SW1, CORE-SW2 양쪽

```
conf t
vlan 20
 name Dev
exit
end
```

### CORE-SW2만

```
conf t
interface e0/2
 switchport mode access
 switchport access vlan 20
 no shutdown
end
```

### PC3 (VPCS)

```
ip 10.1.20.101 255.255.255.0
```

## VLAN 격리 검증

PC3에서 ping 테스트:

```
PC3> ping 10.1.10.101   ← 실패 (정상: 다른 VLAN)
PC3> ping 10.1.10.102   ← 실패 (정상: 다른 VLAN)
```

VLAN이 다르면 L3 라우팅 없이는 통신 불가 → **VLAN 격리 정상 동작 확인**

---

## 트러블슈팅: STP Dispute 문제

### 증상

Step 1에서 성공했던 PC1 → PC2 (같은 VLAN 10) ping이 **간헐적으로 실패**

### 진단 과정

**1단계: STP 상태 확인**

```
CORE-SW1# show spanning-tree vlan 10
```

```
Et0/0               Desg BLK 100       128.1    Shr Dispute
```

- CORE-SW1의 e0/0이 **Designated BLK** + **Dispute** 상태
- 포트 타입이 **Shr (Shared)** → half-duplex 동작

**2단계: 양쪽 Root Bridge 확인**

- CORE-SW1: "This bridge is the root" (Priority 32778)
- CORE-SW2: "This bridge is the root" (Priority 32778)
- **양쪽 다 자기가 Root라고 주장** → BPDU 교환 실패

### 시도한 해결 방법들

**시도 1: Root Bridge 명시적 지정**

```
! CORE-SW1
conf t
spanning-tree vlan 10 root primary
spanning-tree vlan 20 root primary
end

! CORE-SW2
conf t
spanning-tree vlan 10 root secondary
spanning-tree vlan 20 root secondary
end
```

- 결과: CORE-SW2는 정상 (Root FWD), CORE-SW1의 e0/0은 여전히 **Dispute BLK**

**시도 2: 포트 shutdown/no shutdown**

```
! CORE-SW1
conf t
interface e0/0
 shutdown
! 5초 대기
 no shutdown
end
```

- 결과: 일시적으로 복구 후 다시 Dispute 발생

**시도 3: duplex full 설정**

```
! 양쪽 스위치
conf t
interface e0/0
 duplex full
end
```

- 결과: 효과 없음

**시도 4: STP link-type 변경**

```
! 양쪽 스위치
conf t
interface e0/0
 spanning-tree link-type point-to-point
end
```

- 결과: 타입이 Shr → P2p로 변경되었으나 **Dispute 지속**

**시도 5: VLAN 10 STP 비활성화 (최종 해결)**

```
! 양쪽 스위치
conf t
no spanning-tree vlan 10
end
```

- 결과: **ping 성공** → L2 통신 자체는 정상이었음

### 원인 분석

**IOU L2 15.2d의 알려진 버그**

IOU의 Ethernet 포트는 내부적으로 shared media(hub)처럼 동작한다. 실제 스위치의 dedicated full-duplex 포트와 달리, IOU에서는 다음 현상이 발생:

1. CORE-SW1이 BPDU 전송
2. IOU의 shared media 특성으로 자기가 보낸 BPDU를 다시 수신
3. CORE-SW1이 "상대방도 Designated를 주장한다"고 판단
4. Dispute 선언 → 포트 BLK

실장비에서는 발생하지 않는 문제이며, GNS3 + IOU 조합에서 종종 보고되는 이슈.

### 대응 방안

|방법|적용 상황|
|---|---|
|STP 끄기 (현재 적용)|스위치 2대, 루프 위험 없음|
|IOSvL2로 교체|QEMU 기반이라 이 문제 없음 (리소스 더 필요)|
|bpdufilter 적용|장비 늘어날 때 특정 포트에 적용 가능|

### 교훈

- IOU 환경에서 STP Dispute가 발생하면 **IOU 버그를 먼저 의심**할 것
- 실장비에서 Dispute 발생 시에는 duplex mismatch, 케이블 불량, 중간에 hub 존재 등을 확인
- **Root Bridge는 반드시 명시적으로 지정** (기본 Priority에 의존하지 말 것)
- `show spanning-tree vlan X`는 STP 문제 진단의 핵심 명령어
- 포트 타입이 Shr인지 P2p인지 확인하는 것이 Dispute 진단의 첫 단서

## 현재 설정 상태

### CORE-SW1

```
hostname CORE-SW1

vtp mode transparent

vlan 10
 name Sales
vlan 20
 name Dev

spanning-tree mode rapid-pvst
spanning-tree vlan 10,20 priority 24576
no spanning-tree vlan 10

interface e0/0
 switchport trunk encapsulation dot1q
 switchport mode trunk
 duplex full
 spanning-tree link-type point-to-point

interface e0/1
 switchport mode access
 switchport access vlan 10
```

### CORE-SW2

```
hostname CORE-SW2

vlan 10
 name Sales
vlan 20
 name Dev

 switchport trunk encapsulation dot1q

 duplex full

interface e0/1
 switchport mode access
```
