# 1. Threat Prevention 개요 - 위협을 막아라

지금까지 우리는 **Access Control** 과 **Advanced Networking** 을 배웠습니다. Access Control이 "누가 어디로 갈 수 있는가"를 제어한다면, 이번에 배울 **Threat Prevention** 은 "그 트래픽 안에 위협이 있는가"를 검사합니다.

비유하자면 이렇습니다. Access Control은 공항의 **출입국 심사** 입니다. 여권을 확인하고, 입국 목적을 묻고, 허가된 사람만 들여보내죠. 하지만 출입국 심사를 통과한 사람의 가방에 폭탄이 들어있을 수도 있잖아요? 그래서 **보안 검색대** 가 필요합니다. 가방을 X-ray로 스캔하고, 의심스러운 물건이 있으면 검사합니다.

Threat Prevention이 바로 그 보안 검색대입니다.

## Threat Prevention의 구성 요소

체크포인트의 Threat Prevention은 여러 **블레이드** 로 구성됩니다:

| 블레이드 | 역할 |
|----------|------|
| **IPS** | 알려진 공격 패턴 탐지 및 차단 |
| **Anti-Bot & Advanced DNS** | 봇넷 통신 및 악성 DNS 쿼리 차단 |
| **Anti-Virus** | 악성코드 탐지 |
| **Threat Emulation** | 알려지지 않은 위협 탐지 (샌드박스) |
| **Threat Extraction** | 위험 요소 제거 후 안전한 파일 전달 |
| **Zero Phishing** | 피싱 사이트 실시간 차단 |

각각의 블레이드가 다른 유형의 위협을 담당합니다. 마치 공항 보안에도 X-ray 검사, 금속 탐지기, 폭발물 탐지 등 여러 장비가 있는 것처럼요.

## 위협의 발전 - 왜 이렇게 많이 필요할까?

"방화벽 하나면 충분한 거 아니야?"라고 생각할 수 있습니다. 예전에는 그랬을지도 모릅니다. 하지만 해커들도 진화했습니다.

**1세대 공격 (1990년대)**: 단순한 포트 스캔, 알려진 취약점 공격
→ 방화벽 포트 차단으로 방어 가능

**2세대 공격 (2000년대)**: 애플리케이션 레벨 공격, 웜
→ IPS 필요

**3세대 공격 (2010년대)**: APT(지능형 지속 위협), 제로데이 공격
→ 샌드박스, 행동 분석 필요

**4세대 공격 (현재)**: 공급망 공격, AI 기반 공격, 랜섬웨어 서비스(RaaS)
→ 다층 방어, 위협 인텔리전스 필요

해커들이 점점 똑똑해지니까 우리도 여러 겹의 방어막이 필요해진 겁니다.

# 2. IPS - 침입 방지 시스템

**IPS(Intrusion Prevention System)** 는 네트워크 보안의 핵심 구성 요소입니다. 이름 그대로 **침입을 방지** 하는 시스템이죠.

## IDS와 IPS의 차이

IPS를 이해하려면 먼저 **IDS(Intrusion Detection System)** 를 알아야 합니다.

**IDS (침입 탐지 시스템)**:
- 수상한 트래픽을 **탐지** 해서 관리자에게 알림
- 트래픽을 직접 차단하지는 않음
- "도둑이 들어왔어요!"라고 알려주는 경보 시스템

**IPS (침입 방지 시스템)**:
- 수상한 트래픽을 탐지하고 **즉시 차단**
- 트래픽 경로에 인라인으로 배치됨
- "도둑이 들어오려고 해서 막았습니다"라고 행동하는 경비원

```
[IDS 배치]
인터넷 ──→ 방화벽 ──→ 내부 네트워크
              │
              └──→ IDS (미러링) ──→ 알림

[IPS 배치]
인터넷 ──→ IPS ──→ 방화벽 ──→ 내부 네트워크
           │
         직접 차단
```

요즘은 IDS보다 IPS를 더 많이 씁니다. 탐지만 하고 막지 않으면 피해가 발생한 후에야 알게 되니까요.

## 시그니처 기반 탐지

IPS는 주로 **시그니처(Signature)** 기반으로 동작합니다. 시그니처란 알려진 공격의 **패턴** 입니다.

예를 들어 SQL 인젝션 공격을 보겠습니다:

```
정상 요청:
GET /search?q=network HTTP/1.1

SQL 인젝션 시도:
GET /search?q='; DROP TABLE users;-- HTTP/1.1
```

IPS는 `'; DROP TABLE`같은 패턴을 보면 "이거 SQL 인젝션이네!"라고 인식하고 차단합니다.

**시그니처의 종류:**
- **취약점 시그니처**: 특정 소프트웨어 취약점을 노린 공격 탐지
- **익스플로잇 시그니처**: 실제 공격 코드 패턴 탐지
- **프로토콜 이상 탐지**: 비정상적인 프로토콜 사용 탐지

체크포인트는 **ThreatCloud** 를 통해 전 세계에서 수집한 위협 정보를 기반으로 시그니처를 업데이트합니다. 새로운 공격이 발견되면 빠르게 시그니처가 배포되죠.(기본 2시간 간격 업데이트)

## IPS 프로파일 설정

체크포인트에서 IPS를 설정할 때는 **프로파일(Profile)** 을 사용합니다.

**미리 정의된 프로파일:**
- **Optimized**: 균형 잡힌 설정 (권장)
- **Strict**: 최대 보안, 성능 영향 있음
- **Basic**: 최소 보안, 성능 우선

**Optimized 프로파일이 좋은 이유:**

시그니처마다 **심각도(Severity)** 와 **신뢰도(Confidence)** 가 있습니다.

- **심각도**: Critical, High, Medium, Low, Informational
- **신뢰도**: High, Medium, Low

Optimized 프로파일은 "심각도 High 이상 + 신뢰도 Medium 이상"인 시그니처만 활성화합니다. 오탐(False Positive)을 줄이면서 중요한 공격은 막는 거죠.

```
시그니처 예시:
- CVE-2021-44228 (Log4j): 심각도 Critical, 신뢰도 High → 차단
- 의심스러운 User-Agent: 심각도 Low, 신뢰도 Low → 무시
```

## IPS 예외 처리

가끔 정상적인 트래픽이 IPS에 걸리는 경우가 있습니다. 이걸 **오탐(False Positive)** 이라고 합니다.

예를 들어 개발팀이 SQL 쿼리를 테스트하는데 IPS가 계속 막으면 곤란하겠죠? 이럴 때는 **예외(Exception)** 를 설정합니다.

**예외 설정 방법:**
1. SmartConsole → Threat Prevention Policy
2. 해당 시그니처 찾기
3. 예외 조건 추가 (특정 출발지 IP, 목적지 등)

> 주의 | 예외를 너무 많이 만들면 보안에 구멍이 생깁니다. "왜 이 예외가 필요한지" 문서화하고, 주기적으로 검토하세요.

# 3. Anti-Bot - 봇넷 통신 차단

**봇넷(Botnet)** 이라는 말을 들어보셨나요? **Bot + Network** 의 합성어로, 악성코드에 감염된 컴퓨터들의 네트워크입니다.

## 봇넷은 어떻게 동작하는가?

1. **감염**: 사용자가 악성 이메일 첨부파일을 열거나, 감염된 웹사이트를 방문
2. **잠복**: 악성코드가 PC에 설치되지만 겉으로는 티가 안 남
3. **C&C 통신**: 감염된 PC가 해커의 **C&C(Command & Control) 서버** 에 접속해서 명령을 받음
4. **공격 수행**: 해커의 명령에 따라 DDoS 공격, 스팸 발송, 정보 유출 등 수행

```
[해커] ──→ [C&C 서버]
              ↓
        ┌─────┼─────┐
        ↓     ↓     ↓
      [봇1] [봇2] [봇3]  ← 감염된 PC들
        │     │     │
        └─────┴─────┘
              ↓
         [피해 대상]
```

무서운 건 **감염된 사용자는 모른다** 는 겁니다. 컴퓨터가 조금 느려진 것 같기도 하고... 그냥 쓰는 거죠. 근데 알고 보면 자기 컴퓨터가 해커의 좀비로 활동하고 있는 겁니다.

## Anti-Bot이 하는 일

**Anti-Bot** 블레이드는 내부 PC가 외부의 C&C 서버와 통신하는 것을 탐지하고 차단합니다.

**탐지 방식:**

1. **도메인/IP 블랙리스트**: 알려진 C&C 서버 주소 차단
2. **통신 패턴 분석**: 봇넷 특유의 통신 패턴 탐지
3. **DNS 분석**: 수상한 DNS 쿼리 탐지 (DGA 등)

**DGA(Domain Generation Algorithm)란?**

똑똑한 봇넷은 C&C 서버 주소를 고정하지 않습니다. 알고리즘으로 매일 새로운 도메인을 생성하죠.

```
1월 1일: abc123xyz.com
1월 2일: def456uvw.com
1월 3일: ghi789rst.com
```

해커도 같은 알고리즘을 갖고 있어서 그날의 도메인을 알 수 있습니다. 보안팀이 하나를 막으면 다음 날 새 도메인으로 바뀌는 거죠.

Anti-Bot은 이런 DGA 패턴도 탐지할 수 있습니다. "이 도메인 이름이 너무 랜덤한데? 수상해!"

## Anti-Bot 활성화와 동작

SmartConsole에서 Threat Prevention Policy를 열면 **Anti-Bot** 열이 있습니다. 규칙별로 켜거나 끌 수 있죠.

**동작 모드:**
- **Prevent**: 봇넷 통신 차단 (권장)
- **Detect**: 탐지만 하고 로그 남김

> 실무 팁 | 처음 배포할 때는 Detect 모드로 일주일 정도 돌려보세요. 오탐이 없는지 확인한 후 Prevent로 전환합니다.

## 감염된 PC 찾기

Anti-Bot이 봇넷 통신을 차단했다면, 해당 PC가 감염된 겁니다. 로그를 보면 어떤 내부 IP가 C&C 서버에 접속하려 했는지 알 수 있습니다.

```
출발지: 192.168.1.100 (내부 PC)
목적지: malware-cnc.evil.com (C&C 서버)
동작: Prevent (차단됨)
```

이 정보로 감염된 PC를 찾아서 치료하면 됩니다. Anti-Bot은 네트워크 레벨에서 통신을 막을 뿐, PC의 악성코드를 제거하지는 않습니다. 그건 **엔드포인트 보안 솔루션** 의 몫이죠.

## Advanced DNS - DNS 기반 위협 차단

**Advanced DNS** 는 Anti-Bot과 함께 동작하는 기능입니다. DNS 쿼리를 분석해서 악성 도메인 접속을 차단합니다.

**왜 DNS 레벨에서 차단할까요?**

악성코드가 C&C 서버에 접속하려면 먼저 **DNS 쿼리** 를 보냅니다. "malware-cnc.evil.com의 IP 주소가 뭐야?"라고 물어보는 거죠. Advanced DNS는 이 단계에서 차단합니다.

```
[감염된 PC] ─DNS 쿼리─→ [방화벽] ─→ X 차단!
                           │
                    "이 도메인 악성이야"
```

**장점:**
- **연결 전에 차단**: IP 연결이 시작되기도 전에 막음
- **암호화 우회**: HTTPS로 암호화해도 DNS는 평문인 경우가 많음
- **성능 영향 최소**: DNS 쿼리만 검사하므로 가벼움

**Advanced DNS가 탐지하는 것들:**
- 알려진 악성 도메인
- DGA(Domain Generation Algorithm) 패턴
- DNS 터널링 시도
- 피싱 도메인

> 참고 | DNS over HTTPS(DoH) 나 DNS over TLS(DoT) 를 사용하면 DNS 쿼리도 암호화됩니다. 이 경우 Advanced DNS 탐지가 어려울 수 있어서, HTTPS Inspection과 함께 사용하는 것이 좋습니다.

# 4. Anti-Virus - 악성코드 탐지

**Anti-Virus** 블레이드는 네트워크를 통과하는 파일에서 악성코드를 탐지합니다.

## PC 백신과의 차이

"PC에 백신 깔려 있는데 방화벽에도 Anti-Virus가 필요해요?"

좋은 질문입니다. 둘은 **다른 레벨** 에서 동작합니다.

**PC 백신 (엔드포인트)**:
- PC에서 실행되는 파일 검사
- USB, 다운로드 파일 등 실시간 검사
- PC 리소스 사용

**방화벽 Anti-Virus (네트워크)**:
- 네트워크를 통과하는 파일 검사
- 이메일 첨부파일, 웹 다운로드 등
- PC에 도달하기 전에 차단

```
[인터넷] ──악성파일──→ [방화벽 Anti-Virus] ──→ X (차단)
                              ↓ (통과 시)
                       [PC 백신] ──→ 최종 검사
```

**심층 방어(Defense in Depth)** 관점에서 둘 다 있는 게 좋습니다. 네트워크에서 1차로 막고, PC에서 2차로 막는 거죠.

## 검사 대상 프로토콜

방화벽 Anti-Virus가 검사할 수 있는 프로토콜:
- **HTTP/HTTPS**: 웹 다운로드
- **FTP**: 파일 전송
- **SMTP/POP3/IMAP**: 이메일 첨부파일
- **SMB**: 파일 공유

HTTPS 검사를 하려면 앞서 배운 **HTTPS Inspection** 이 필요합니다. 암호화를 풀어야 내용을 볼 수 있으니까요.

## 시그니처와 휴리스틱

Anti-Virus도 IPS처럼 **시그니처** 를 사용합니다. 알려진 악성코드의 해시값이나 코드 패턴을 데이터베이스에 저장해 두고 비교하죠.

**시그니처 탐지의 한계:**

```
알려진 악성코드 A → 시그니처 있음 → 탐지 O
새로운 악성코드 B → 시그니처 없음 → 탐지 X
```

그래서 **휴리스틱(Heuristic)** 탐지도 사용합니다. 코드의 **행동 패턴** 을 분석해서 "이거 악성코드 같은데?"라고 추측하는 거죠.

```
휴리스틱 예시:
- 파일이 자기 자신을 복사하려 함 → 의심
- 레지스트리 시작 프로그램에 등록하려 함 → 의심
- 시스템 파일을 수정하려 함 → 의심
```

하지만 휴리스틱은 **오탐** 가능성이 있습니다. 정상 프로그램도 비슷한 행동을 할 수 있으니까요. 그래서 더 정교한 분석이 필요한데, 그게 바로 다음에 배울 **Threat Emulation** 입니다.

# 5. SandBlast Threat Emulation - 제로데이 방어

**제로데이(Zero-day)** 공격이란 아직 알려지지 않은 취약점을 이용한 공격입니다. 시그니처가 없으니까 기존 Anti-Virus로는 막을 수 없죠.

"알려지지 않은 공격을 어떻게 막아요?"

정답은 **직접 실행해 보는 것** 입니다.

## 샌드박스란?

**샌드박스(Sandbox)** 는 격리된 가상 환경입니다. 의심스러운 파일을 이 안에서 실행해 보고, 무슨 행동을 하는지 관찰합니다.

```
의심스러운 파일 도착
        ↓
[샌드박스 - 격리된 가상 환경]
        │
   실행해 봄
        │
        ├── 정상 행동 → 통과
        │
        └── 악성 행동 감지 → 차단
            - 파일 암호화 시도 (랜섬웨어)
            - C&C 서버 접속 시도
            - 시스템 파일 변조
```

마치 폭발물 의심 물체를 폭발 방호 챔버 안에서 터뜨려 보는 것과 같습니다. 실제 환경은 안전하게 보호하면서 위험성을 확인하는 거죠.

## Threat Emulation의 동작

체크포인트의 **SandBlast Threat Emulation** 은 이 샌드박스 기술을 구현한 것입니다.

**동작 과정:**

1. 파일이 방화벽을 통과하려 함
2. Anti-Virus가 1차 검사 (알려진 악성코드 체크)
3. 알려지지 않은 파일 → Threat Emulation으로 전송
4. 샌드박스에서 파일 실행
5. 행동 분석 (파일, 레지스트리, 네트워크 활동 등)
6. 악성으로 판단되면 → 차단
7. 정상으로 판단되면 → 통과

**에뮬레이션 환경:**

Threat Emulation은 여러 운영체제 환경을 시뮬레이션합니다:
- Windows 7, 10, 11
- Office 2016, 2019, 365
- Adobe Reader 다양한 버전

공격자들은 특정 환경에서만 동작하는 악성코드를 만들기도 합니다. "Windows 10 + Office 2019에서만 실행돼라" 같은 식으로요. 그래서 여러 환경에서 테스트해 봐야 합니다.

## 클라우드 vs 로컬 에뮬레이션

Threat Emulation은 두 가지 방식으로 운영할 수 있습니다:

**클라우드 에뮬레이션 (ThreatCloud)**:
- 파일을 체크포인트 클라우드로 전송
- 클라우드의 샌드박스에서 분석
- 장점: 빠른 분석, 최신 환경
- 단점: 파일이 외부로 나감 (규정 이슈)

**로컬 에뮬레이션 (SandBlast Appliance)**:
- 전용 하드웨어를 사내에 설치
- 파일이 회사 밖으로 나가지 않음
- 장점: 데이터 주권 유지
- 단점: 추가 장비 비용

금융권이나 정부 기관처럼 데이터가 외부로 나가면 안 되는 곳은 로컬 에뮬레이션을 선택합니다.

## 에뮬레이션 우회 기술과 대응

똑똑한 악성코드는 자신이 샌드박스 안에 있는지 감지하려 합니다.

**샌드박스 탐지 기법:**
- 가상머신 아티팩트 확인 (VMware Tools 등)
- 분석 도구 프로세스 확인 (Wireshark, Procmon 등)
- 사용자 행동 확인 (마우스 움직임, 키보드 입력)
- 시간 가속 탐지 (샌드박스가 시간을 빨리 돌리는 경우)

"샌드박스 같으면 숨어있고, 실제 PC 같으면 공격해라"

체크포인트는 이런 우회 기술에도 대응합니다:
- **CPU 레벨 검사**: 코드가 실제로 어떻게 실행되는지 CPU 명령어 수준에서 분석
- **반 우회 기술**: 샌드박스처럼 보이지 않도록 환경 조작
- **시간 지연 분석**: 일정 시간 후에만 동작하는 악성코드 대응

# 6. Threat Extraction - 안전한 파일 전달

사용자가 이메일로 Word 문서를 받았습니다. 이 문서에 악성 매크로가 숨어있을 수도 있습니다. Threat Emulation으로 검사하면 안전한지 알 수 있죠.

근데 문제가 있습니다. **검사하는 동안 기다려야 합니다.**

파일 크기와 복잡도에 따라 몇 초에서 몇 분까지 걸릴 수 있습니다. 급한 업무 중에 "파일 검사 중입니다. 잠시 기다려 주세요"라고 하면 사용자가 짜증나겠죠?

**Threat Extraction** 은 이 문제를 해결합니다.

## 동작 원리

```
원본 파일 도착 (위험 요소 포함 가능)
        ↓
[Threat Extraction]
        │
        ├──→ 위험 요소 제거
        │    - 매크로 삭제
        │    - 임베디드 객체 삭제
        │    - 하이퍼링크 삭제
        │    - JavaScript 삭제
        │
        └──→ 안전한 버전 즉시 전달
                ↓
        [동시에 Threat Emulation 분석]
                ↓
        분석 완료 후 원본 제공 (선택)
```

**두 마리 토끼를 잡는 방식입니다:**

1. **즉각적인 파일 전달**: 위험 요소를 제거한 "깨끗한" 버전을 바로 전달
2. **백그라운드 분석**: 원본 파일은 Threat Emulation으로 분석
3. **원본 접근 옵션**: 분석이 끝나면 원본 파일 다운로드 링크 제공

## 지원 파일 형식

Threat Extraction이 처리할 수 있는 파일:
- **Office 문서**: Word, Excel, PowerPoint
- **PDF 파일**
- **이미지 파일**: (이미지에 숨겨진 악성코드 제거)

**변환 형식:**
- 원본 형식 유지 (매크로만 제거)
- PDF로 변환 (가장 안전)
- 이미지로 변환 (완전히 정적인 형태)

## 실제 사용 시나리오

영업팀 김 대리가 거래처에서 견적서 Excel 파일을 받았습니다.

**Threat Extraction 없이:**
1. 파일 도착
2. Threat Emulation 분석 시작 (2분 소요)
3. 2분 후 "안전함" 판정
4. 김 대리 파일 수신
5. 김 대리: "왜 이렇게 늦어?!"

**Threat Extraction 사용:**
1. 파일 도착
2. 즉시 매크로 제거된 Excel 전달 (3초)
3. 김 대리: 바로 견적서 내용 확인
4. 백그라운드에서 원본 분석 중
5. 매크로가 필요하면 분석 완료 후 원본 다운로드

업무 효율성과 보안을 동시에 챙기는 거죠.

## 주의사항

Threat Extraction이 제거하는 것들:
- **매크로**: Excel VBA 등
- **임베디드 객체**: OLE 객체
- **하이퍼링크**: 외부 링크
- **DDE**: Dynamic Data Exchange

이 기능들이 업무에 **반드시 필요한 경우** 도 있습니다. 예를 들어 재무팀이 매크로가 들어간 복잡한 Excel 양식을 사용한다면, 매크로가 제거되면 업무가 안 되겠죠?

이런 경우에는:
1. 특정 발신자는 Threat Extraction 예외 처리
2. 분석 완료 후 원본 다운로드 허용
3. 해당 부서는 별도 정책 적용

# 7. Zero Phishing - 피싱 사이트 실시간 차단

**피싱(Phishing)** 은 가장 흔하고 효과적인 공격 방법 중 하나입니다. 아무리 좋은 방화벽이 있어도 사용자가 가짜 로그인 페이지에 비밀번호를 입력하면 끝이니까요.

## 피싱 공격의 위험성

"저는 피싱에 안 속아요"라고 생각하시나요?

요즘 피싱 사이트는 정말 정교합니다. 실제 은행 사이트와 **픽셀 단위로 똑같이** 만들어요. URL도 비슷하게 위장합니다:

```
정상: https://www.mybank.com/login
피싱: https://www.mybank-secure.com/login
피싱: https://www.mybaank.com/login  (a가 하나 더!)
피싱: https://www.мybank.com/login   (키릴 문자 м 사용)
```

2023년 보안 보고서에 따르면, 기업 데이터 유출 사고의 **36%** 가 피싱으로 시작되었습니다. 랜섬웨어 감염의 초기 침투 경로로도 피싱이 가장 많이 사용됩니다.

## Zero Phishing이 하는 일

**Zero Phishing** 블레이드는 사용자가 피싱 사이트에 접속하는 것을 **실시간으로 차단** 합니다.

**탐지 방식:**

1. **URL 평판 검사**: ThreatCloud 데이터베이스에서 알려진 피싱 URL 확인
2. **실시간 페이지 분석**: 페이지 내용을 분석해서 피싱 특성 탐지
3. **브랜드 위장 탐지**: 유명 브랜드(은행, 포털 등)를 사칭하는 페이지 탐지
4. **새로 생성된 도메인 주의**: 최근 등록된 도메인은 위험도 높음

**동작 흐름:**

```
사용자가 링크 클릭
        ↓
[Zero Phishing 검사]
        │
        ├── 정상 사이트 → 접속 허용
        │
        └── 피싱 의심 → 경고 페이지 표시
                        "이 사이트는 피싱으로 의심됩니다"
```

## URL Filtering과의 차이

앞서 배운 **URL Filtering** 과 비슷해 보이지만 다릅니다:

| 기능 | URL Filtering | Zero Phishing |
|------|---------------|---------------|
| 목적 | 카테고리별 접근 제어 | 피싱 사이트 차단 |
| 분류 방식 | 카테고리 (게임, SNS 등) | 피싱 여부 |
| 탐지 방법 | URL 카테고리 DB | 실시간 페이지 분석 |
| 위치 | Access Control | Threat Prevention |

URL Filtering이 "도박 사이트 차단"이라면, Zero Phishing은 "가짜 은행 사이트 차단"입니다. 둘 다 켜두는 게 좋습니다.

## 사용자 인식 강화

Zero Phishing이 경고 페이지를 보여줄 때, 사용자에게 **왜 차단되었는지** 설명합니다:

```
⚠️ 경고: 피싱 사이트 의심

이 웹사이트는 피싱으로 의심됩니다.
개인정보나 로그인 정보를 입력하지 마세요.

[이전 페이지로 돌아가기]  [위험을 감수하고 계속]
```

"위험을 감수하고 계속" 옵션을 줄 수도 있고, 완전히 차단할 수도 있습니다. 보안 정책에 따라 설정하면 됩니다.

> 실무 팁 | Zero Phishing은 사용자 교육 효과도 있습니다. 경고 페이지를 본 사용자는 "아, 이런 게 피싱이구나"라고 인식하게 되니까요.

# 8. Threat Prevention Policy 구성

지금까지 배운 블레이드들을 실제로 어떻게 설정하는지 알아보겠습니다.

## Autonomous vs Custom 모드

SmartConsole에서 Gateway 속성을 열면 Threat Prevention 탭에서 두 가지 모드를 선택할 수 있습니다:

**Autonomous Threat Prevention (자동 모드)**:
- 체크포인트가 권장하는 **최적의 설정을 자동 적용**
- 별도 정책 설정 없이 바로 보호 시작
- 초보자나 빠른 배포가 필요한 환경에 적합
- ThreatCloud 의 실시간 업데이트 자동 반영

**Custom Threat Prevention (수동 모드)**:
- 관리자가 **직접 정책을 세밀하게 설정**
- 어떤 블레이드를 켜고 끌지 선택 가능
- 프로파일, 예외, 동작 모드 등 커스터마이징
- 기업 환경에 맞는 정밀한 제어가 필요할 때 사용

```
┌─────────────────────────────────────────────┐
│  ○ Autonomous Threat Prevention            │
│  ● Custom Threat Prevention     ← 선택됨   │
├─────────────────────────────────────────────┤
│  SandBlast:                                 │
│    ☑ Threat Emulation                      │
│    ☐ Threat Extraction                     │
│    ☐ Zero Phishing                         │
│                                             │
│  Threat Prevention:                         │
│    ☑ IPS                                   │
│    ☑ Anti-Bot & Advanced DNS               │
│    ☑ Anti-Virus                            │
└─────────────────────────────────────────────┘
```

> 실무 팁 | 처음에는 Autonomous 모드로 시작해서 보호를 활성화하고, 환경을 파악한 후 Custom 모드로 전환해서 세밀하게 조정하는 것이 좋습니다.

## 정책 구조

SmartConsole → Security Policies → **Threat Prevention** 탭

```
┌─────────────────────────────────────────────────────────────────┐
│  #  │ Name    │ IPS  │ Anti-Bot │ Anti-Virus │ TE  │ TX  │ ...│
├─────────────────────────────────────────────────────────────────┤
│  1  │ 서버    │  ●   │    ●     │     ●      │  ●  │     │    │
│  2  │ 사용자  │  ●   │    ●     │     ●      │  ●  │  ●  │    │
│  3  │ 게스트  │  ●   │    ●     │            │     │     │    │
└─────────────────────────────────────────────────────────────────┘
* TE: Threat Emulation, TX: Threat Extraction
```

규칙별로 어떤 블레이드를 적용할지 선택합니다.

## 프로파일 선택

각 블레이드에는 **프로파일** 을 지정합니다.

**사전 정의된 프로파일:**
- **Optimized**: 균형 잡힌 설정 (대부분의 환경에 권장)
- **Strict**: 최대 보안 (고보안 환경)
- **Basic**: 최소 보안 (성능 우선)

**커스텀 프로파일:**
필요하면 직접 프로파일을 만들 수 있습니다. 특정 시그니처만 켜거나 끄거나, 동작을 변경하거나.

> 실무 팁 | 처음에는 Optimized 프로파일로 시작하세요. 로그를 모니터링하면서 필요에 따라 조정합니다.

## 동작 모드

**Prevent (차단)**: 위협 탐지 시 차단
**Detect (탐지)**: 탐지만 하고 로그 남김, 차단 안 함

**단계적 배포 전략:**

1. **1주차**: 모든 블레이드 Detect 모드로 배포
2. **2주차**: 로그 분석, 오탐 확인 및 예외 처리
3. **3주차**: 오탐 없는 블레이드부터 Prevent로 전환
4. **4주차 이후**: 전체 Prevent 모드, 지속적 모니터링

급하게 Prevent로 바꿨다가 업무가 마비되면 곤란하니까요.

## 로그 분석

Threat Prevention 로그는 **SmartConsole의 Logs & Monitor** 또는 **SmartLog** 에서 확인합니다.

**주요 로그 필드:**
- **Protection Name**: 탐지한 위협 이름
- **Severity**: 심각도
- **Confidence**: 탐지 신뢰도
- **Action**: 수행한 동작 (Prevent, Detect)
- **Source/Destination**: 출발지/목적지 정보

**로그 예시:**
```
Protection: CVE-2021-44228 (Log4j RCE)
Severity: Critical
Confidence: High
Action: Prevent
Source: 203.0.113.50 (외부)
Destination: 192.168.1.10:8080 (내부 웹 서버)
```

이런 로그가 보이면? 외부에서 내부 웹 서버로 Log4j 공격이 들어왔고, IPS가 막은 겁니다.

# 9. 정리하며

이번 장에서는 Threat Prevention의 핵심 블레이드들을 배웠습니다.

정리하면:

- **IPS**: 알려진 공격 패턴(시그니처) 을 기반으로 침입 방지
- **Anti-Bot & Advanced DNS**: 봇넷 통신 및 악성 DNS 쿼리 차단
- **Anti-Virus**: 네트워크를 통과하는 파일에서 악성코드 탐지
- **Threat Emulation**: 샌드박스에서 파일을 실행하여 제로데이 공격 탐지
- **Threat Extraction**: 위험 요소를 제거한 안전한 파일 즉시 전달
- **Zero Phishing**: 피싱 사이트 실시간 탐지 및 차단

그리고 **Autonomous vs Custom** 모드로 이 블레이드들을 자동 또는 수동으로 관리할 수 있습니다.

이 블레이드들이 **함께 동작** 할 때 강력한 보안이 됩니다:

```
파일 도착
    ↓
[Anti-Virus] ─ 알려진 악성코드? → 차단
    ↓ (미탐지)
[Threat Emulation] ─ 행동 분석 → 악성? → 차단
    ↓ (정상)
[Threat Extraction] ─ 위험 요소 제거 → 안전한 버전 전달
```

Access Control이 "문 앞에서 신분증 검사"라면, Threat Prevention은 "가방 속까지 샅샅이 검사"입니다. 둘 다 있어야 안전한 네트워크를 만들 수 있습니다.
