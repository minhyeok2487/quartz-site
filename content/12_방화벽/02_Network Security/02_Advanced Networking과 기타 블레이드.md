# 1. Advanced Networking - 네트워크 고급 기능

지난 장에서 Access Control 블레이드들을 배웠습니다. 이번 장에서는 Network Security의 나머지 블레이드들을 살펴보겠습니다. 보안보다는 **네트워크 성능과 관리**에 초점을 맞춘 기능들이에요.

Gateway 속성의 Network Security 탭을 보면 **Advanced Networking** 섹션이 있습니다:

- Dynamic Routing
- SecureXL
- QoS
- Monitoring

하나씩 알아볼까요?

## Dynamic Routing - 라우팅 프로토콜 연동

방화벽도 결국 네트워크 장비입니다. 트래픽이 방화벽을 통과하려면 **라우팅**이 필요하죠. 작은 네트워크에서는 정적 라우팅(Static Route)으로 충분하지만, 네트워크가 커지면 얘기가 달라집니다.

**Dynamic Routing** 블레이드를 활성화하면 체크포인트 방화벽이 라우팅 프로토콜에 참여할 수 있습니다:

- **OSPF**: 대규모 내부 네트워크용
- **BGP**: 인터넷/ISP 연동용
- **RIP**: 소규모 네트워크용 (요즘 잘 안 씀)

**언제 필요할까요?**

예를 들어 회사에 코어 라우터가 있고, 그 아래에 체크포인트 방화벽이 있다고 해봅시다. 네트워크 구성이 바뀔 때마다 방화벽에 정적 라우팅을 일일이 추가하기 귀찮겠죠? OSPF로 연동해 두면 라우팅 테이블이 자동으로 동기화됩니다.

```
[코어 라우터] ←── OSPF ──→ [체크포인트 방화벽]
     ↓
 라우팅 변경 시 자동 동기화
```

> 참고 | Dynamic Routing 설정은 Gaia OS의 CLI나 WebUI에서 합니다. SmartConsole에서는 블레이드 활성화만 하고, 실제 라우팅 설정은 Gaia에서 해야 합니다.

## SecureXL - 방화벽 가속화

방화벽은 모든 패킷을 검사합니다. 트래픽이 많아지면 CPU가 힘들어하겠죠? **SecureXL**은 이 문제를 해결하는 **가속화 기술**입니다.

**원리가 뭘까요?**

첫 번째 패킷은 방화벽이 꼼꼼히 검사합니다. "출발지가 어디고, 목적지가 어디고, 어떤 규칙에 매칭되고..." 이 정보를 **연결 테이블**에 저장합니다.

같은 연결의 두 번째 패킷부터는? 이미 검사한 연결이니까 **빠른 경로(Accelerated Path)** 로 처리합니다. CPU를 거의 안 쓰고 하드웨어 수준에서 처리하는 거죠.

```
첫 번째 패킷: 꼼꼼히 검사 (Firewall Path) → 느림
두 번째 패킷~: 빠른 경로 (Accelerated Path) → 빠름
```

**SecureXL이 꺼져 있으면?**

모든 패킷을 CPU가 처리합니다. 트래픽이 많으면 방화벽이 병목이 됩니다. 그래서 **기본적으로 켜져 있고, 끄면 안 됩니다**.

**SecureXL 상태 확인:**

```bash
[Expert@FW:0]# fwaccel stat
```

> 주의 | 일부 고급 기능(특정 IPS 시그니처, HTTPS Inspection 등)은 SecureXL 가속이 안 되고 느린 경로로 처리됩니다. 그래서 보안 기능을 많이 켜면 성능이 떨어질 수 있습니다.

## QoS - 트래픽 우선순위

인터넷 회선은 한정되어 있습니다. 누군가 대용량 파일을 다운로드하면 다른 사람의 화상회의가 끊길 수 있죠. **QoS(Quality of Service)** 는 이런 문제를 해결합니다.

**QoS가 하는 일:**
- 중요한 트래픽에 **높은 우선순위** 부여
- 덜 중요한 트래픽의 **대역폭 제한**
- 트래픽 종류별 **대역폭 보장**

**예를 들면:**

| 트래픽 종류 | 우선순위 | 대역폭 |
|------------|----------|--------|
| VoIP/화상회의 | 최상 | 보장 20% |
| 업무 시스템 | 높음 | 보장 30% |
| 일반 웹 | 보통 | 나머지 |
| YouTube/Netflix | 낮음 | 최대 10% 제한 |

이렇게 설정하면 누가 YouTube를 보든 화상회의는 끊기지 않습니다.

**QoS 설정 위치:**

SmartConsole → Security Policies → **QoS** 탭에서 QoS Policy를 만들 수 있습니다. Access Control Policy와 비슷하게 규칙 기반으로 설정합니다.

## Monitoring - 장비 모니터링

**Monitoring** 블레이드는 방화벽 장비 자체를 모니터링하는 기능입니다. SNMP를 활성화해서 외부 NMS(Network Management System)에서 모니터링할 수 있게 해줍니다.

**모니터링 항목:**
- CPU, 메모리 사용률
- 인터페이스 트래픽
- 연결 수
- 방화벽 상태

대부분의 회사에서는 Zabbix, PRTG, SolarWinds 같은 NMS로 네트워크 장비들을 통합 모니터링합니다. 체크포인트 방화벽도 SNMP로 연동하면 같이 모니터링할 수 있습니다.

# 2. Other - 기타 보안 기능

Network Security 탭의 **Other** 섹션에는 특수한 보안 기능들이 있습니다.

## Data Loss Prevention (DLP) - 정보 유출 방지

앞에서 배운 **Content Awareness**가 파일 유형을 보는 거라면, **DLP**는 **데이터 내용**까지 깊이 봅니다.

**Content Awareness vs DLP:**

| 기능 | Content Awareness | DLP |
|------|-------------------|-----|
| 검사 대상 | 파일 유형 (exe, pdf 등) | 데이터 내용 (주민번호, 카드번호 등) |
| 정책 복잡도 | 단순 | 복잡 |
| 성능 영향 | 적음 | 큼 |
| 라이선스 | Access Control에 포함 | 별도 |

**DLP가 하는 일:**

이메일이나 웹으로 파일을 보낼 때, 그 안에 민감한 정보가 있는지 검사합니다:

- 주민등록번호 패턴 감지
- 신용카드 번호 패턴 감지
- 특정 키워드 ("기밀", "대외비" 등)
- 소스코드 패턴

민감한 정보가 발견되면:
- 차단
- 경고 후 전송
- 로그만 남기고 허용

**규정 준수에 필수:**

개인정보보호법, GDPR, PCI-DSS 같은 규정을 준수하려면 DLP가 거의 필수입니다. 고객 정보가 외부로 유출되면 큰일이니까요.

## Anti-Spam & Email Security - 이메일 보안

이메일은 가장 흔한 공격 경로입니다. 피싱, 악성 첨부파일, 스팸... **Anti-Spam & Email Security** 블레이드는 이런 이메일 위협을 차단합니다.

**주요 기능:**
- **스팸 필터링**: 광고성 이메일 차단
- **피싱 탐지**: 가짜 로그인 페이지 링크 차단
- **악성 첨부파일 검사**: 바이러스, 랜섬웨어 탐지
- **발신자 검증**: SPF, DKIM, DMARC 확인

**배치 방식:**

체크포인트 방화벽이 메일 서버 앞에서 이메일 트래픽을 검사합니다. 또는 MTA(Mail Transfer Agent) 모드로 직접 이메일을 받아서 처리할 수도 있습니다.

```
[인터넷] → [체크포인트 방화벽] → [메일 서버]
              ↓
         이메일 검사
```

> 참고 | 요즘은 Microsoft 365, Google Workspace 같은 클라우드 이메일 서비스를 많이 씁니다. 이런 경우에는 방화벽의 이메일 보안보다 **클라우드 이메일 보안 솔루션**을 쓰는 게 더 적합합니다.

# 3. Infinity Services - 클라우드 시대의 새로운 기능

**Infinity Services**는 체크포인트의 최신 클라우드 기반 서비스들입니다. 전통적인 방화벽 기능을 넘어서 새로운 환경에 대응합니다.

## IoT Protect - IoT 장치 보호

요즘 네트워크에는 PC와 서버만 있는 게 아닙니다. IP 카메라, 프린터, 스마트 TV, 공조 시스템, 출입 통제 장치... 온갖 **IoT 장치**들이 연결되어 있죠.

**IoT의 문제점:**
- 보안 업데이트가 안 됨 (제조사가 신경 안 씀)
- 기본 비밀번호 그대로 사용
- 취약점이 많음
- 감염되면 봇넷에 이용됨

2016년 **Mirai 봇넷**을 기억하시나요? 수십만 대의 IoT 장치가 감염되어 대규모 DDoS 공격을 일으켰습니다. IP 카메라, 공유기 같은 장치들이었죠.

**IoT Protect가 하는 일:**

1. **IoT 장치 식별**: 네트워크에 어떤 IoT 장치가 있는지 자동 발견
2. **위험 평가**: 각 장치의 취약점과 위험도 분석
3. **자동 정책 적용**: IoT 장치에 맞는 보안 정책 자동 생성
4. **이상 행동 탐지**: IoT 장치가 평소와 다르게 행동하면 알림

예를 들어 IP 카메라가 갑자기 외부 서버와 대량의 트래픽을 주고받으면? "이거 감염된 거 아니야?"라고 경고해 줍니다.

## SD-WAN - 소프트웨어 정의 WAN

**SD-WAN(Software-Defined WAN)** 은 지사 연결을 더 똑똑하게 만드는 기술입니다.

**전통적인 WAN의 문제:**

회사에 본사와 지사가 여러 개 있습니다. 예전에는 이렇게 연결했죠:
- **MPLS 전용 회선**: 비싸지만 안정적
- **인터넷 VPN**: 저렴하지만 품질 불안정

MPLS는 너무 비싸고, 인터넷 VPN은 품질이 들쭉날쭉... 뭔가 아쉽습니다.

**SD-WAN의 해결책:**

여러 회선(MPLS, 인터넷, LTE 등)을 동시에 사용하면서 **트래픽을 똑똑하게 분배**합니다:

- 화상회의 → MPLS (품질 중요)
- 일반 웹 → 인터넷 (비용 절감)
- MPLS 장애 시 → 자동으로 인터넷으로 전환

```
[지사] ──── MPLS ────┐
         │          ├──→ [본사]
         └─ 인터넷 ──┘

SD-WAN이 자동으로 최적 경로 선택
```

**체크포인트 SD-WAN:**

체크포인트 방화벽에 SD-WAN 블레이드를 활성화하면 **보안 + SD-WAN**을 하나의 장비로 해결할 수 있습니다. 지사마다 방화벽과 SD-WAN 장비를 따로 둘 필요가 없죠.

# 4. 정리하며

이번 장에서는 Network Security의 나머지 블레이드들을 살펴봤습니다.

**Advanced Networking:**
- **Dynamic Routing**: 라우팅 프로토콜 연동으로 라우팅 자동화
- **SecureXL**: 방화벽 성능 가속화 (기본 켜져 있음, 끄지 마세요!)
- **QoS**: 트래픽 우선순위로 중요한 서비스 보장
- **Monitoring**: SNMP로 NMS 연동

**Other:**
- **DLP**: 민감 정보 유출 방지, 규정 준수에 필수
- **Anti-Spam & Email Security**: 이메일 위협 차단

**Infinity Services:**
- **IoT Protect**: IoT 장치 자동 식별 및 보호
- **SD-WAN**: 여러 회선을 똑똑하게 활용

이 블레이드들은 Access Control만큼 자주 쓰이지는 않지만, 특정 환경에서는 꼭 필요한 기능들입니다. "아, 이런 기능도 있구나" 정도로 알아두면 나중에 필요할 때 떠올릴 수 있겠죠?
